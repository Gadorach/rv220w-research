# RV220W v1.3.2 build and RAM boot

Version 1.3.2 has two test paths. The supplied DTB-repacked ELF is the fastest regression test because all non-DTB kernel/initramfs sections remain byte-identical to the board-proven v1.3.1 image. A clean OpenWrt build remains the final source-integration test.

## Path A: boot the supplied candidate

From the installed toolkit:

```fish
cd ~/src/rv220w-research/rv220w-research/promotion-toolkit
sudo -v
./rv220w.fish tftp-boot \
  ~/Downloads/rv220w-openwrt-build-environment-v1.3.2/artifacts/rv220w-openwrt-rv220w-initramfs-v1.3.2-dtb-repacked.elf
```

Use the actual extraction path when it differs. The source buffer ends at `0x063fb2a8`, below the conservative `0x07f00000` limit.

## Path B: upgrade and build from source

Run the upgrader only from a physical directory outside the installed toolkit. The script aborts before changing files when `pwd -P` is inside the destination.

```fish
cd /
cd ~/Downloads/rv220w-openwrt-build-environment-v1.3.2
./upgrade-existing-v1.3.fish
```

Open a fresh shell, then verify and build:

```fish
cd ~/src/rv220w-research/rv220w-research/promotion-toolkit
pwd -P
cat VERSION
./rv220w.fish doctor
./rv220w.fish platform verify
./rv220w.fish build rv220w-initramfs
```

`VERSION` must report `1.3.2`, and the physical path must not contain `.backup-`. Preserve the generated ELF, expanded config, readelf report, SHA-256, and build log as a distinct evidence set. Do not overwrite the proven v1.3.1 ELF or the supplied repacked candidate.

## First validation commands

Use the supplied snapshot script rather than pasting a multiline block through serial:

```sh
/root/rv220w-ethernet-snapshot.sh 2>/dev/null || true
cat /proc/mtd
ls -l /dev/mtd* /dev/mtd*ro 2>/dev/null
cat /sys/class/net/eth0/operstate 2>/dev/null
cat /sys/class/net/eth0/speed 2>/dev/null
cat /sys/class/net/eth0/duplex 2>/dev/null
dmesg | grep -Ei 'phys_mapped_flash|cfi|cmdlinepart|mtd|octeon.*ethernet|eth0'
```

Acceptance requires a working normal `ttyS0` console, seven read-only MTD partitions, the 32 MiB x16 Macronix detection through `phys_mapped_flash`, and retained eth0 traffic at 1000/full. No flash write is permitted.
