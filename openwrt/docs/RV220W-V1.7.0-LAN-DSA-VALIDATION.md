# RV220W v1.7.0 — RAM-only LAN DSA ownership validation

## Purpose

Exercise upstream B53/DSA ownership only on the proven LAN half of the BCM53115:
ports 1-4 are user ports and port 8 is the CPU port connected to Octeon `eth0`.
WAN port 0, switch conduit port 5, Octeon `eth1`, and unused `eth2` are deliberately
excluded.  This avoids claiming upstream multi-conduit support before a single
conduit has been proven.

## Important behavioral change

Unlike discovery profiles, B53/DSA setup is ownership-changing: the driver may
software-reset the switch and rewrite forwarding, tagging, VLAN, and port state.
The image remains RAM-only and contains no flash workflow; a power cycle returns
the board to U-Boot initialization.

## Variants

- `dsa-lan` / `rv220w-dsa-lan-rxid`: CPU port `phy-mode = "rgmii-rxid"`; chosen as the first test because the passive snapshot found port-8 RGMII control `0x00` and upstream B53 clears both DLL bits for this mode and then enables its timing-select behavior. It is the least invasive of the three supplied variants, but it is not register-preserving.
- `rv220w-dsa-lan-txid`: `rgmii-txid`, retained as the common alternative.
- `rv220w-dsa-lan-rgmii`: plain `rgmii`, causing B53 to request both internal delays.

The variant names describe software requests, not yet-proven PCB delay placement.
Test only the first variant initially.

## Initial campaign

```fish
./rv220w.fish build dsa-lan
./rv220w.fish tftp-boot --profile dsa-lan --interface enp0s31f6 --configure-interface
```

Keep the host connected to LAN1.  After boot, use UART regardless of network state:

```fish
./rv220w.fish collect-dsa run4-LAN1-before
ping -I enp0s31f6 -c 20 192.168.240.2
./rv220w.fish collect-dsa run4-LAN1-after
```

Preserve the build log, TFTP/serial boot log, both DSA reports and serial transcripts,
and host NIC counter/ping output.
