# RV220W v1.6.0 — passive B53 topology stage

## Purpose

Stage 4 established the complete external copper map:

| Physical jack | BCM53115 PHY | Octeon interface |
|---|---:|---|
| WAN | 0 | eth1 |
| LAN1 | 1 | eth0 |
| LAN2 | 2 | eth0 |
| LAN3 | 3 | eth0 |
| LAN4 | 4 | eth0 |

PHY 5 is present but is not an external copper jack. Pseudo-PHY address `0x1e`
responds and is the Broadcom switch-management endpoint. Board inspection also
strongly suggests that `eth2` belongs to an unpopulated optional Ethernet
footprint rather than to the populated BCM53115 topology.

v1.6.0 adds a passive switch-register snapshot to identify the two populated
CPU-facing switch ports and preserve the vendor bootloader's working VLAN and
port-mode configuration before any DSA binding experiment.

## Safety boundary

The target helper performs the same management indirection used by the upstream
B53 MDIO driver:

1. write page selector register `0x10` at pseudo-PHY `0x1e`;
2. write register/read-command selector `0x11` at pseudo-PHY `0x1e`;
3. poll selector `0x11` until the read command completes;
4. read data registers `0x18` through `0x1b`.

Only selector registers `0x10` and `0x11` may be written. The helper contains a
hard refusal for every other MDIO write target.

Allowed:

- selector-only writes to `0x1e:0x10` and `0x1e:0x11`;
- switch data-register reads through `0x1e:0x18..0x1b`;
- direct network-counter reads from sysfs;
- UART upload, execution, and retrieval.

Prohibited:

- writes to switch data registers;
- PHY BMCR or other PHY-register writes;
- VLAN or ARL table operations;
- MIB reset, freeze, or clear commands;
- switch reset or GPIO changes;
- B53/DSA binding;
- flash or U-Boot environment writes.

The original pseudo-PHY selector values are captured and restored after the
snapshot. A trap attempts restoration if the script is interrupted.

## Captured evidence

The snapshot reads only static/status registers needed for topology inference:

- BCM device ID and core revision;
- strap value;
- switch mode, forwarding controls, flood masks, and learning mask;
- global management and Broadcom-header controls;
- link, speed, and duplex summaries;
- VLAN control registers;
- port control, port-based VLAN membership, and default VLAN tag for ports 0-8;
- indirect MII identity/status registers for ports 0-8;
- GMII override and RGMII control registers;
- Octeon `eth0`, `eth1`, and `eth2` counters.

Link-change status and VLAN/ARL table command registers are intentionally not
read because they may be latch/command oriented and are not required here. MIB
counter pages are deferred until the CPU-port mapping is known.

## Required test sequence

No image rebuild is required. Exit any interactive serial-console program before
each command.

### 1. No-cable baseline

Disconnect every Ethernet cable and wait 10-15 seconds:

```fish
./rv220w.fish collect-b53 run3-NONE
```

### 2. WAN-only state

Connect only WAN and wait 10-15 seconds:

```fish
./rv220w.fish collect-b53 run3-WAN
```

### 3. LAN1-only state

Connect only LAN1 and wait 10-15 seconds:

```fish
./rv220w.fish collect-b53 run3-LAN1
```

Reports and raw UART transcripts are saved under:

```text
~/src/rv220w-openwrt/logs/discovery/b53/
```

The three reports should be uploaded together. No ping or SSH is required.

## Decision gate

The evidence is sufficient for the first separate DSA experiment only when it
identifies:

- the persistent internal link bits with no external cables;
- the port-based VLAN membership connecting PHY 0 to the WAN CPU path;
- the membership connecting PHY 1-4 to the LAN CPU path;
- whether ports 5 and/or 8 are enabled as IMP/CPU ports;
- existing Broadcom-header/tag state;
- RGMII/GMII mode and override state for the internal ports.

The first DSA image must remain a separate RAM-only profile. It must not replace
or modify the hardware-proven v1.3.2 reference profile or the read-only discovery
profile.
