# RV220W v1.5.0 — read-only MDIO identity stage

## Purpose

Identify devices visible on the Octeon MDIO bus and determine whether direct Clause 22 link status correlates with WAN and LAN1-LAN4. This stage does not bind DSA or perform Broadcom pseudo-PHY indirect access.

## Safety boundary

The scanner invokes only read forms:

```text
mdio BUS
mdio BUS phy PHYAD raw REG
```

It never supplies a register value. It does not select Broadcom pages, trigger pseudo-PHY operations, bind B53/DSA, reset hardware, or access flash.

Registers read at each address 0-31:

- 0: BMCR
- 1: BMSR, twice (latch-low then current state)
- 2: PHY ID 1
- 3: PHY ID 2

## Collection sequence

With the current discovery image running:

```fish
./rv220w.fish collect-mdio run2-NONE
./rv220w.fish collect-mdio run2-WAN
./rv220w.fish collect-mdio run2-LAN1
./rv220w.fish collect-mdio run2-LAN2
./rv220w.fish collect-mdio run2-LAN3
./rv220w.fish collect-mdio run2-LAN4
```

Disconnect every Ethernet cable for `NONE`. For each other label, connect only the named jack, wait 10-15 seconds, then collect.

Outputs are stored under:

```text
$RV220W_WORKSPACE/logs/discovery/mdio/
```

## Gate

Do not enable a B53 device-tree child until these scans identify the direct bus responders. If only the pseudo-PHY responds, the next stage must explicitly authorize narrowly scoped Broadcom indirect management transactions while continuing to prohibit forwarding/VLAN/reset writes.
