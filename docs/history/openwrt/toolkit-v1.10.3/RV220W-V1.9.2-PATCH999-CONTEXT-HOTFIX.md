# RV220W v1.9.2 patch-999 context hotfix

## Failure

The first v1.9.1 build reached the RV220W target patches and failed while applying `999-octeon-production-dt-flash-cleanups.patch` to `arch/mips/cavium-octeon/setup.c`. The BootBus `flash_setup.c` hunk applied, but the setup hunk did not.

The cause was patch context, not the cleanup design. OpenWrt applies `400-ubnt_dts_pruning.patch` earlier in the same target patch series, and it edits the board-selection/pruning region immediately above the stable fill-MAC/unflatten tail. v1.9.1 unnecessarily included that modified region in patch 999's context.

## Correction

v1.9.2 keeps the same two functional changes but narrows the hunks. The `setup.c` hunk anchors only on `octeon_fill_mac_addresses()` and `unflatten_and_copy_device_tree()`. The `flash_setup.c` hunk anchors only on `of_flash_match[]` and its existing `cfi-flash` entry.

No production DTS property, network policy, switch patch, package selection, NOR ownership, or raw-FDT behavior changed.

## Recovery

Install the v1.9.1-to-v1.9.2 updater and rerun the normal build:

```fish
./rv220w.fish build rj45-full
```

The OpenWrt prepare phase recreates the kernel build directory, so the rejected `.rej` file from the failed attempt does not need manual cleanup. All operations remain RAM-only and do not write router NOR.
