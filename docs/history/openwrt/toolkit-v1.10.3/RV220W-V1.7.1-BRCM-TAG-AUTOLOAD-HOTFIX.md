# RV220W v1.7.1 — Broadcom DSA tag-driver autoload hotfix

## Observed v1.7.0 behavior

The B53 MDIO driver read the device ID successfully and reported:

```text
found switch: BCM53115, rev 8
deferred probe pending: bcm53xx: failed to register switch
```

No `lan1`–`lan4` DSA interfaces appeared. The failure was therefore after chip
identification and before successful DSA switch registration.

## Root cause

The v1.7.0 initramfs contained:

```text
/lib/modules/6.12.94/tag_brcm.ko
/lib/modules/6.12.94/b53_common.ko
/lib/modules/6.12.94/b53_mdio.ko
```

but its generated module-autoload files loaded only:

```text
b53_common
b53_mdio
```

`tag_brcm.ko` advertises the `dsa_tag:brcm` / protocol-ID-1 aliases required by
the BCM53115 CPU port. On this minimal OpenWrt initramfs, the deferred DSA lookup
did not resolve that alias automatically before B53 registration.

## Correction

The DSA overlay now installs:

```text
/etc/modules.d/30-tag-brcm
```

containing:

```text
tag_brcm
```

This loads the tag driver before the package-generated `dsa-b53` and
`dsa-b53-mdio` autoload files. No DTS topology or switch timing setting changes.

## Test

Rebuild and RAM-boot the default `dsa-lan` candidate, then collect:

```fish
./rv220w.fish collect-dsa run4b-LAN1-before
ping -I enp0s31f6 -c 20 192.168.240.2
./rv220w.fish collect-dsa run4b-LAN1-after
```

Expected first gate:

```text
tag_brcm appears in lsmod
BCM53115 registration succeeds
lan1, lan2, lan3, and lan4 appear
```

The image remains RAM-only. B53/DSA may reset and reconfigure volatile switch
state, but no flash-writing workflow is included.
