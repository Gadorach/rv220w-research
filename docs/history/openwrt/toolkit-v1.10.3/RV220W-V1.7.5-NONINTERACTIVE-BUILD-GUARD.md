# RV220W v1.7.5 noninteractive build guard

During the v1.7.4 DSA build, a top-level OpenWrt `menuconfig` interface acquired the caller's terminal while the scripted build was inside `target/linux/compile`. The short build log stopped at that target because curses output was written directly to the controlling terminal rather than to the build log.

v1.7.5 treats every automated OpenWrt `make` operation as strictly noninteractive. It launches `make` in a new `setsid` session, closes stdin, and supplies noninteractive environment settings. Consequently an accidental Kconfig UI cannot open `/dev/tty`; it fails and is captured in the verbose build log instead of blocking the terminal.

The explicit `./rv220w.fish build menuconfig` action remains interactive and receives a TTY plus an authorization marker. DSA builds use `V=s` from their first attempt to preserve the command that caused any future configuration failure.

This change affects only the toolkit build transport. The Octeon kernel patch remains unchanged, and no B53 or OpenWrt-core source is modified.
