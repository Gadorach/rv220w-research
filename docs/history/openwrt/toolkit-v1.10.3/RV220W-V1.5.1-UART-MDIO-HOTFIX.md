# RV220W v1.5.1 — UART-first MDIO collection hotfix

## Why this hotfix exists

The v1.5.0 host collector used SSH for both target execution and report retrieval. That design was incompatible with the required `NONE` test and with any port that did not route to `192.168.240.2`, including WAN in the current validation configuration.

v1.5.1 makes UART the default transport. SSH remains available only through the explicit `--ssh` flag.

## Transport behavior

The host helper:

1. opens the OpenWrt console at 115200 baud by default;
2. synchronizes with the running BusyBox `ash` shell;
3. disables local terminal echo while commands are framed;
4. uses the installed `/usr/sbin/rv220w-mdio-scan` when present;
5. otherwise uploads the packaged scanner to `/tmp` as base64;
6. verifies the uploaded scanner with SHA-256 before execution;
7. runs the unchanged direct Clause 22 read-only scanner;
8. retrieves the report through sentinel-framed UART output; and
9. restores terminal echo before closing the serial port.

The UART transport performs no MDIO writes, switch-page selections, DSA binding, flash operations, resets, or persistent configuration changes.

## Required operational condition

Only one process can own the FTDI serial adapter. Exit `serial-console`, `screen`, `minicom`, or any other UART reader before running the host collector.

## Commands

No Ethernet cable is required:

```fish
./rv220w.fish collect-mdio run2-NONE
```

Connect only WAN, wait 10–15 seconds, then:

```fish
./rv220w.fish collect-mdio run2-WAN
```

An explicit serial port or non-default console baud can be supplied:

```fish
./rv220w.fish collect-mdio run2-WAN \
    --port /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_A50285BI-if00-port0 \
    --uart-baud 115200
```

SSH compatibility mode remains available only for a working LAN path:

```fish
./rv220w.fish collect-mdio run2-LAN1 --ssh
```

Outputs and UART transcripts are stored under:

```text
$RV220W_WORKSPACE/logs/discovery/mdio/
```

## Existing Stage 4 evidence

The successful v1.5.0 scans established:

- LAN1 changes BMSR at PHY address 1;
- LAN2 changes BMSR at PHY address 2;
- LAN3 changes BMSR at PHY address 3;
- LAN4 changes BMSR at PHY address 4;
- PHY addresses 0–4 share ID `0x0143bf88`;
- address 5 responds with ID `0x0143bff0`;
- pseudo-PHY address `0x1e` responds with zero IDs;
- only `NONE` and WAN remain required.
