# RV220W v1.9.1 production cleanup candidate

## Scope

v1.9.1 preserves the hardware-proven five-port DSA topology and v1.9.0 VLAN
fix, then removes validation-only behavior from the `rj45-full` image.
Everything remains RAM-only; the NOR partitions stay read-only.

The first v1.9.0 boot, TFTP transfer, runtime status and firewall ruleset are
preserved under `evidence/run10-rj45-v190-boot`.  That capture proves the image
booted with the intended DSA topology and LAN1 at 1000/full.  The operator then
reported a successful quick test of all five RJ45 jacks, including LAN DHCP and
WAN operation.  No complete packet/counter log accompanied that quick test, so
that portion remains informal hardware confirmation rather than a completed
acceptance record.

## Production DTS

The full-RJ45 build now uses
`openwrt/production/cn5010_cisco_rv220w-production.dts.in` rather than the
validation template.

- Octeon `ethernet@0` and `ethernet@1` have fixed 1000/full links to the switch.
  External link status remains on DSA user ports.
- CPU switch ports 5 and 8 retain `rgmii-rxid` and their proven fixed links.
- `ethernet@2`, USB, reset-key ownership, and unused BootBus children remain
  disabled.
- The NOR child is deliberately retained but uses
  `cavium,octeon-3860-bootbus-flash`, selecting the Octeon-specific mapping
  driver without first invoking generic physmap.

## Kernel cleanup patch 999

`999-octeon-production-dt-flash-cleanups.patch` performs two generic Octeon
repairs:

1. Refreshes OF's flat-tree verification/CRC after Octeon MAC-address fixups,
   allowing `/sys/firmware/fdt` to represent the actual appended tree.
2. Adds an explicit Octeon BootBus flash compatible to the architecture driver.
   That driver continues to read U-Boot's live CS register and derive the true
   32 MiB base and x16 width.  The generic `bank-width` workaround is not used.

The NOR node must not be removed: it is the platform-device trigger for the
BootBus-aware driver.

## Runtime cleanup

- `kmod-mdio-netlink`, `mdio-tools`, raw B53 helpers, and the DSA snapshot helper
  are excluded from `rj45-full`; diagnostic profiles retain them.
- The status tool detects firewall4 by the loaded `inet fw4` nftables table,
  prints the standard DSA/bridge/ethtool counters, reports `/proc/mtd`, raw-FDT
  availability, kernel taint, DHCP leases, and security state.
- Dropbear is bound to the LAN logical interface.
- Stock ESP and UDP/500 WAN-to-LAN exceptions are removed.  WAN ping remains
  explicitly allowed; users can add IPsec passthrough rules when required.

## Expected clean boot markers

```text
DSA: tree 0 setup
Bootbus flash: Setting flash for 32MB flash at 0x1dc00000
raw_fdt=available
kernel_tainted=0
firewall=loaded
```

The production boot should no longer emit:

```text
Using deprecated link status - please update your DT
physmap-flash ... Can't get bank width from device tree
OF: fdt: not creating '/sys/firmware/fdt': CRC check failed
mdio_netlink: loading out-of-tree module taints kernel
```

## Acceptance

Validate all five ports, LAN DHCP, WAN DHCP/DHCPv6, 1500-byte paths, NAT,
strict WAN-to-LAN isolation, `/proc/mtd`, and `/sys/firmware/fdt` after boot.
No MTD write, U-Boot `saveenv`, or persistent installation is part of this
stage.
