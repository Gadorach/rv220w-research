# RV220W v1.10.2 NOR transfer hotfix

## Hardware result

The v1.10.1 NOR-writer image built and RAM-booted successfully. Linux exposed exactly one writable 22 MiB `openwrt-slot` at `/dev/mtd1`; all protected regions remained read-only. Two complete backups were collected before any write attempt. Both are 23,068,672 bytes and byte-identical with SHA-256:

```text
47b546d826e9016d3fa0a8e08356e1ba614cba7290d11eba79a6bd80e0671c6d
```

## Failure

The host workflow used modern `scp`. OpenSSH 9 and later use SFTP by default, while the deliberately minimal OpenWrt/Dropbear maintenance image does not include `/usr/libexec/sftp-server`. Transfer therefore stopped with:

```text
ash: /usr/libexec/sftp-server: not found
scp: Connection closed
```

The failure occurred after the mandatory backup but before the target writer was invoked. NOR was not erased or programmed.

A separate usability defect was also observed: each initramfs boot creates a new Dropbear host key, but the writer used the user's persistent `known_hosts`. That produced a misleading host-identification failure after changing RAM images.

## Correction

`scripts/nor-stage.fish` no longer requires or invokes `scp`. It streams the exact image bytes through non-PTY SSH:

```text
local file -> cat -> ssh -> private /tmp partial -> atomic rename
```

The host checks both Fish pipeline statuses. On any transfer or target-writer failure it removes the partial and staged remote files. The target-side writer still independently verifies exact size, SHA-256 and ELF magic before calling `mtd`, then hashes the complete NOR slot after writing.

Expected RAM-boot host keys are isolated with `UserKnownHostsFile=/dev/null`, `GlobalKnownHostsFile=/dev/null`, and `StrictHostKeyChecking=no`. This mirrors the established RAM-image collector policy and prevents stale ephemeral keys from modifying or blocking the user's persistent SSH trust database.

## Reuse of the running writer

This is a host-only fix. The v1.10.1 target helper, partition map and writer image are unchanged and compatible. Install v1.10.2, leave the existing writer image running, and repeat:

```fish
./rv220w.fish nor-stage status
./rv220w.fish nor-stage write --confirm RV220W_WRITE_OPENWRT_SLOT
```

The write action will make another mandatory backup before streaming the image.
