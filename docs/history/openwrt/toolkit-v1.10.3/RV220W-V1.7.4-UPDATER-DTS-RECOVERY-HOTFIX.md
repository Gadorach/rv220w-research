# RV220W v1.7.4 updater and source-DTS recovery hotfix

The failed v1.7.2 DSA build could leave the generated LAN-only validation DTS in the OpenWrt target overlay because cleanup aborted after the kernel patch failure. The v1.7.3 updater correctly refused to accept that tree, but its error did not distinguish a known stale build substitution from an unknown local modification.

v1.7.4 adds a conservative recovery helper. It restores the hardware-proven v1.3.2 DTS only when the current source is an exact or structurally identified toolkit-generated DSA candidate. Canonical DTS files and platform-compatible local formatting are left unchanged. Unknown source trees are rejected without modification.

The updater backs up and restores the toolkit, Octeon target patch, and source DTS as one transaction. The kernel change remains confined to the legacy Octeon Ethernet driver; B53 and OpenWrt core are unchanged.
