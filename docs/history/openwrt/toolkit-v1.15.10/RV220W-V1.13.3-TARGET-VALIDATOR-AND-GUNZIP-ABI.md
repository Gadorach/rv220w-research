# RV220W v1.13.3 target validator and U-Boot ABI correction

## Hardware evidence

The v1.13.2 LuCI upload reached the RV220W platform validator but failed at
`platform.sh` line 65 because `od` was not installed. The generated expanded
configuration enables BusyBox `hexdump` and does not enable BusyBox `od` or
`coreutils-od`. This was a runtime dependency defect, not a board metadata or
archive identity failure.

The vendor U-Boot `gunzip` command was also hardware-qualified as a
four-argument command:

```text
gunzip <source-address> <source-length> <destination-address> <destination-capacity>
```

Both the exact gzip length and the complete fixed 6 MiB kernel partition length
were accepted. The fixed-length form decompressed the ELF, booted Linux, was
saved in `openwrt_boot`, and completed an unattended cold boot.

## Correction

The target validator now uses BusyBox `hexdump` for both operations formerly
performed by `od`:

- decimal byte extraction for SquashFS v4 `bytes_used`;
- all-zero validation of the sub-1024-byte tar alignment suffix.

The manifest boot plan now emits:

```text
cp.b 0xbdc80000 0x05500000 0x600000
gunzip 0x05500000 0x600000 0x06500000 0x1a00000
bootoctlinux 0x06500000 console=ttyS0,115200
```

No flash layout or sysupgrade write policy changes in this release.
