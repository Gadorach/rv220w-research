# RV220W v1.15.2 — DTS installer/template hotfix

## Hardware symptom

Immediately after upgrading to v1.15.1, `./rv220w.fish platform verify` failed with a missing `rv220w:green:power` DTS token. This was not an invalid LED mapping. The OpenWrt workspace still contained the pre-LED canonical DTS because the updater never runs platform installation and `platform verify` is intentionally read-only.

A second audit found that `build persistent-wifi` temporarily renders `openwrt/wifi/cn5010_cisco_rv220w-wifi-discovery.dts.in` over the canonical source. v1.15.1 had changed only the canonical reference DTS, so the generated persistent-WiFi DTB would still have omitted the new LEDs.

## Corrections

- The conservative source-DTS repair helper accepts only the exact pre-LED canonical SHA-256 `941cfbcf8e90eb51a7be9912273e0ab8655b2192695c253095dfc28f46599269` as a canonical predecessor and atomically replaces it with the current canonical DTS. Unknown local platform-compatible edits are still not overwritten.
- The production and Wi-Fi production templates now contain the complete surveyed LED block: GPIO2 POWER, GPIO3 DIAG, GPIO4 WLAN, GPIO6 DMZ, all active-low. GPIO5 is explicitly absent.
- The release test simulates predecessor promotion and checks the templates used by the actual build path.

## Required workflow

```fish
./rv220w.fish platform install
./rv220w.fish platform verify
./rv220w.fish build persistent-wifi
./rv220w.fish verify
```

Discard any persistent-WiFi artifact produced by v1.15.1. The v1.15.2 build invalidates predecessor artifacts at the beginning of the build.
