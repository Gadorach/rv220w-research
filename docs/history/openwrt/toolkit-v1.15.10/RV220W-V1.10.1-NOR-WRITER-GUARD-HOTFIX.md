# RV220W v1.10.1 NOR-writer guard hotfix

## Failure

The v1.10.0 `nor-writer` build completed `defconfig` and then stopped with:

```text
LuCI profile package was not retained by defconfig: CONFIG_PACKAGE_luci-light=y
```

This was a build-helper validation defect. The NOR-writer seed intentionally
excludes LuCI and uHTTPd, but `verify_nor_writer_config()` incorrectly called
`verify_luci_config()`.

The supplied expanded writer configuration proves that `defconfig` retained the
intended flash-stage target, `mtd`, firewall/DHCP/DSA base, and excluded LuCI.
No kernel compilation had begun when the helper rejected it.

## Correction

v1.10.1 validates the writer against `verify_rj45_full_config()` and then checks:

```text
required:
  CONFIG_PACKAGE_mtd=y
  CONFIG_TARGET_octeon_generic_DEVICE_cisco_rv220w_flash_stage=y

forbidden:
  CONFIG_TARGET_octeon_generic_DEVICE_cisco_rv220w=y
  luci-light / luci-base / admin / firewall LuCI packages
  uhttpd / uhttpd-mod-ubus
```

The writer banner now accurately identifies a LuCI-free maintenance image.

## Unchanged safety boundary

- The normal RV220W target keeps all seven MTD partitions read-only.
- The writer target exposes only the 22 MiB `openwrt-slot` as writable.
- `boot-chain`, `stock-data`, `legacy-env-gap`, `vendor-tail`, and `uboot-env`
  remain read-only.
- The writer performs no automatic reboot, `saveenv`, or boot-command change.
- Write and restore actions retain separate exact confirmation tokens, mandatory
  pre-write backup, local SHA-256 validation, and complete NOR read-back.

## Validation

The hotfix test consumes the actual v1.10.0 expanded writer configuration and
proves that it passes the corrected requirements while failing the old LuCI
requirement. Static tests also reject any regression to `verify_luci_config()`
in the NOR-writer verifier.

Build after updating:

```fish
./rv220w.fish build nor-writer
```
