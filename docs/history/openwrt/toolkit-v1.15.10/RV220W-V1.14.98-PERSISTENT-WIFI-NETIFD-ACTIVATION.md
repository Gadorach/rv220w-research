# RV220W v1.14.98 persistent Wi-Fi netifd/UCI activation

v1.14.97 hardware proved that the BCM4322 AP datapath is healthy on both bands. Direct temporary probes on channel 1 and channel 36 each created an nl80211 `__ap` interface, reached hostapd `AP-ENABLED`, and incremented b43 `Adding Interface type 3`.

The normal installed state instead showed `radio0` enabled but the only configured AP section `wifinet0` still carried `disabled='1'`. The radio therefore remained `up=false`, with no hostapd process and no wireless netdev. The recurring netifd `command failed: Not supported (-122)` is not used as a failure gate; OpenWrt has long emitted that message when a driver rejects the all-antenna-mask setup call while continuing radio configuration.

v1.14.98 remains no-build/no-flash. It adds `persistent-wifi-stage enable-ap`, which transactionally enables one existing AP section through ordinary UCI/netifd, forces a fixed CA non-DFS channel, and verifies that the normal path reaches an AP netdev, hostapd and a new b43 type-3 interface marker. Failure restores `/etc/config/wireless` byte-for-byte and calls `wifi up` on the restored configuration; success intentionally keeps the enabled administrator configuration.

The first hardware gate should use the existing `wifinet0` on channel 1:

```fish
./rv220w.fish persistent-wifi-stage enable-ap \
    --wifi-section wifinet0 \
    --channel 1 \
    --confirm RV220W_ENABLE_CONFIGURED_AP_V11498
```

If that passes, normal LuCI/UCI/netifd AP operation is qualified. A later test may move the same single BCM4322 PHY to channel 36; simultaneous 2.4 GHz and 5 GHz operation is not possible on this one dual-band radio.
