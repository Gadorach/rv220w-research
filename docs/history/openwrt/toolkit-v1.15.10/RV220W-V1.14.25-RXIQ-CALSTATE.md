# RV220W v1.14.25 — read-only RX-IQ calibration-state qualification

## Hardware result carried from v1.14.24

The corrected v1.14.24 image built successfully and its provenance sidecar was verified before RAM boot. The explicit 2.4 GHz N-PHY diagnostic then completed all 33 IQ measurements (three samples on each channel 1–11) with b43 `STARTED`, `radio_on=1`, forced PIO, both RX cores enabled, and the CCK+OFDM classifier enabled.

Both receive chains showed substantial IQ accumulator activity while earlier DMA and PIO monitor tests received zero decoded 802.11 frames from a nearby strong AP. Therefore the antennas/BCM2056 analog receive/ADC path is not simply dead. The unresolved boundary is now N-PHY calibration/baseband/decode.

## Upstream calibration gap

For N-PHY revision 4, Linux b43 routes RX-IQ calibration through `b43_nphy_rev3_cal_rx_iq()`. In Linux 6.12 that routine is a stub returning `-1`.

The normal calibration flow independently performs RSSI calibration, then TX-IQ/LO calibration, then RX-IQ calibration. `b43_nphy_save_cal()` — which snapshots the four live RX-IQ compensation coefficients and records `iqcal_chanspec_{2G,5G}` — is reached only after RX-IQ calibration returns success.

This makes the following read-only pattern especially useful:

- RF/ADC IQ activity is present;
- `rssical_chanspec_2G.center_freq` is non-zero;
- `iqcal_chanspec_2G.center_freq` remains zero;
- rev3+ RX-IQ implementation marker is zero;
- live/cached RX-IQ compensation coefficients are zero/default.

That pattern would strongly support the missing rev3+ RX-IQ implementation as the next active engineering target, but v1.14.25 does not run or implement calibration.

## Rev3+ gain-register correction

The v1.14.24 diagnostic mislabeled one register. The legacy `B43_NPHY_C2_INITGAIN` alias is register `0x036`; on rev3+ N-PHY that address is repurposed as `B43_NPHY_REV3_C1_CLIP_MEDGAIN_B`. Actual rev3+ core-2 initial gain lives at `B43_NPHY_REV3_C2_INITGAIN_A/B` (`0x2A7/0x2A8`).

v1.14.25 therefore reports the dedicated rev3+ core-1/core-2 initial-gain A/B registers and separately labels core-1 clip-medium-gain B. The previous `c2_initgain=0x0004` observation must not be used as evidence of core asymmetry.

## New read-only state

Each `nphy_rxdiag` sample now includes:

- live RX-IQ compensation A0/B0/A1/B1, raw and signed;
- cached 2.4 GHz and 5 GHz RX-IQ compensation A0/B0/A1/B1, raw and signed;
- IQ-cal and RSSI-cal chanspec center frequencies/channel types for 2.4 and 5 GHz;
- N-PHY `measure_hold`, `mute`, `perical`, current/hardware RX/TX chain policy;
- `rxcalparams`, hang-avoid, gain-boost, eLNA configuration, IPA state, TX-power-control state, TX/RX-chain state, deaf count, and TX-IQ-local coefficient-valid state;
- corrected rev3+ initial-gain registers.

The existing hardware IQ estimator still runs, but no new calibration or RF override is introduced.

## Safety boundary

v1.14.25 does not invoke RX-IQ calibration, TX tone/sample playback, RF-sequence forcing, RF-control override, scan, probe request, association, AP mode, injection, user traffic, or NVM writes. Normal boot remains WLAN-disabled. The explicit diagnostic retains the existing `--ack-rf` requirement because it starts the receiver and changes channels.

## Decision after hardware capture

If the current-band RSSI calibration chanspec is populated while the RX-IQ chanspec/cache remains unsaved/default, the next release may stage an **explicit opt-in** reconstruction of Broadcom's rev3–6 RX-IQ calibration path, with state save/restore, rollback and a separate `--ack-rf-cal` gate. That active calibration is intentionally not part of v1.14.25.

If RX-IQ chanspec/cache state is already populated, the rev3+ stub is not sufficient to explain the decode failure and the next investigation should stay read-only around baseband/decode/workaround state instead.
