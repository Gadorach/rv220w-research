# RV220W v1.14.75 — active-scan retained verification generation

## Hardware result that motivated this revision

v1.14.74 reached the intended continuous calibration-to-managed-vif lifecycle. The fresh active-side `integration:retain` transaction completed successfully and produced IQ tuple `4,1023,0,4`. The first `verify:retained` also passed. `rvwact0` was then created and brought UP while the calibration monitor stayed alive; a second `verify:retained` reported `rc=0`, `verified=1`, verified MAC suspend/resume, and the **same** IQ tuple `4,1023,0,4`.

The target nevertheless stopped because the shell observed `active_scan_managed_verify_write_rc=1`. This is not evidence that calibration was lost; the semantic debugfs state shows the verification ran and passed. The different shell status between the first and second otherwise identical verification means the callback convention mismatch is not assumed to be the sole cause of that status anomaly.

## Debugfs callback ABI correction

Upstream b43 models per-file debugfs write callbacks as `int (*write)(...)`. Successful callbacks return `0`; the generic `b43_debugfs_write()` wrapper translates that zero into the userspace byte count. The custom RX-IQ fault handler in the hardware-qualified 998 patch instead returned `count` on success. v1.14.75 leaves 998 byte-identical and adds a separate post-998 patch:

`openwrt/wifi/999-b43-rv220w-rxiq-verify-generation.patch`

It changes only the custom debugfs diagnostic ABI/state:

- `nphy_rxiq_fault_write_file()` returns `0` on successful `verify:retained` and normal successful diagnostic writes, matching b43's callback convention.
- a `verify_retained_generation` counter is exposed in the existing readback and increments whenever a permitted `verify:retained` operation actually enters the kernel verification path.

No RX-IQ/RCCAL math, radio sequencing, PCI routing, normal b43 TX/RX path, SPROM, NVM or NOR behavior changes.

## Freshness gate

The active target records the generation after the pre-managed verification. After `rvwact0` comes UP, it issues another `verify:retained` and requires:

1. the generation to be numeric and strictly greater than the pre-managed generation;
2. semantic verification `rc=0`;
3. `verify_retained_attempted=1` and `verify_retained_verified=1`;
4. verified MAC suspend and resume;
5. the exact same retained IQ tuple;
6. channel readback remains 2447 MHz.

The shell-level debugfs write status remains evidence, but the generation advance proves the second semantic state was produced by a **fresh** kernel verification rather than stale readback.

If the generation does not advance, the run stops before scanning as `active-scan-managed-verify-not-fresh`. Only after all of the above gates pass is the existing single cfg80211 wildcard channel-8 active scan allowed.

## Safety boundary

The active experiment remains CA/channel 8 only and explicitly requires RF, calibration and TX acknowledgement. It still forbids authentication, association, AP mode, arbitrary frame injection, user-data traffic, persistent writes, NVM writes and NOR writes. Persistent platform v1.7.5 is not modified by this WLAN discovery revision.
