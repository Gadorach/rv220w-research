# RV220W v1.8.1 pre-defconfig menuconfig race hotfix

## Symptom

An automated `dsa-dual` build could print missing `tmp/info/.files-targetinfo-*` errors and display the OpenWrt configuration UI even though the detached `world` build continued and produced a valid ELF. The orphaned `mconf` process could consume one CPU core indefinitely because its stdin was `/dev/null`.

## Root cause

The DSA helper substituted the candidate DTS and called `make target/linux/clean` before copying and expanding the profile seed. OpenWrt's top-level `.config` rule intentionally invokes `menuconfig` when `.config` is absent or lacks `CONFIG_HAVE_DOT_CONFIG`. The accidental `menuconfig` and the following `defconfig` could then run `prepare-tmpinfo` concurrently, racing the PID-suffixed target-info files.

## Correction

Toolkit v1.8.1:

1. installs the profile seed and completes `make defconfig`;
2. verifies `CONFIG_HAVE_DOT_CONFIG=y`;
3. only then performs clean, download, kernel, or world targets;
4. serializes builds with a workspace `flock`;
5. clears inherited `MAKEFLAGS` and `MFLAGS`;
6. rejects menuconfig/nconfig/xconfig targets in the automated helper.

The dual-conduit topology and all kernel patches are byte-for-byte unchanged from v1.8.0.

## Existing v1.8.0 artifact

A staged artifact is usable when its SHA-256 file verifies, `readelf` reports a complete ELF64 big-endian Octeon image, the appended DTB is a valid FDT, and the initramfs contains the v1.8.0 dual-conduit build marker. The configuration-UI process is independent of the completed image pipeline.
