# RV220W v1.13.4 stage2 dependency correction

The first write-producing self-upgrade passed target validation and switched to OpenWrt's RAM filesystem. The RV220W function then failed before `mtd erase rootfs` because `head` was not available in stage2. Neither rootfs nor kernel was modified. OpenWrt's generic `do_stage2` does not check the platform function return, so it printed “Upgrade completed” and rebooted the unchanged system.

Platform v1.7.4 removes both `head` uses and the latent `tr` dependency. It uses exact `grep`, `hexdump` plus `sed`, and a one-block `dd`, all from the standard stage2 copy set. The RV220W wrapper now exits nonzero on any board-specific failure, preventing the generic completion/reboot path.

No partition, image, bootloader, writer, or write-order change is included.
