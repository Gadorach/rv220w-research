# RV220W v1.11.7 compressed persistent-kernel correction

## Failure identified

The v1.11.6 explicit-output DTB helper completed all of its checks and moved the verified ELF back into place. OpenWrt then executed the device `KERNEL_SIZE := 6m` check. The raw Octeon ELF exceeded that limit, so `Build/check-size` deleted it. The following export `cp` produced the misleading `cannot stat` failure.

## Correct image form

The 6 MiB NOR kernel partition now contains a deterministic gzip stream of the complete non-initramfs ELF. The OpenWrt pipeline is:

```make
KERNEL := kernel-bin | strip-kernel | patch-cmdline | rv220w-append-dtb-elf | gzip
KERNEL_INSTALL := 1
KERNEL_SIZE := 6m
```

The size check therefore applies to the bytes that will actually be written to NOR.

## Boot candidate

The manifest emits:

```text
cp.b 0xbdc80000 0x05500000 0x600000
gunzip 0x05500000 0x06500000 0x1a00000
bootoctlinux 0x06500000 console=ttyS0,115200
```

Before any kernel NOR write, first TFTP-boot the decompressed `.elf`. Then TFTP-load the exact padded `kernel.part.bin` to `0x05500000`, run the manifest `gunzip` command, and boot the decompressed ELF. This validates the vendor U-Boot command and the `0xff`-padded gzip stream.
