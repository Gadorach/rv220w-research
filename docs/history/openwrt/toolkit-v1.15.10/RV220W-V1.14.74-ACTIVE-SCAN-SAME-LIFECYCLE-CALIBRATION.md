# RV220W v1.14.74 — active-scan same-lifecycle retained calibration

## Hardware finding from v1.14.73

The v1.14.73 run reconfirmed the complete receive path on CA channel 8: retained RX-IQ/RCCAL calibration passed, b43 remained on IRQ109/CIU36/PCI INT0, and 351 IRQ/DMA0/PIO/header/b43/mac80211 receive events completed with zero b43 drops or PIO/length/FCS errors.

The following active-scan command did **not** reach regulatory setup, managed-interface creation or TX. v1.14.73 transport diagnostics captured target rc=3 and the exact error: the new SSH command could not find a verified retained calibration transaction in `nphy_rxiq_fault`.

That was a lifecycle bug in the experiment, not a TX result. The pre-active command had already deleted its final monitor interface before returning. With no live interface, mac80211 is free to stop the hardware; b43's `b43_op_stop()` stops and exits the wireless core. The next command therefore cannot safely assume the previous debugfs transaction describes the still-live PHY.

## v1.14.74 experiment

The host collector still requires the independent, hardware-qualified `rxiq-calibration` + passive-RX analyzer PASS before it attempts the active target.

The active target then establishes its *own* live calibration chain:

1. Create `rvwactmon0` as a virtual monitor and bring it up.
2. Tune it to 2447 MHz / channel 8.
3. Run `integration:retain` and require successful primary/cleanup/MAC-suspend-resume plus a retained IQ tuple.
4. Run `verify:retained` and require the exact same tuple.
5. Keep `rvwactmon0` UP. This keeps the mac80211/b43 hardware lifecycle alive without consuming b43's single real `wl->operating` vif slot.
6. Add and bring up `rvwact0` as the single managed vif.
7. Run a second `verify:retained` and require the same tuple after managed-vif bring-up.
8. Require the held monitor still reports 2447 MHz.
9. Only then issue `iw dev rvwact0 scan flush freq 2447`.
10. Capture b43 txstat, host IRQ/CIU state, BSS results, link/station isolation and kernel diagnostics.

Cleanup deletes the managed vif first and the held monitor last. Therefore the final b43/mac80211 hardware stop cannot occur until after the scan evidence is complete.

## Safety boundary

No authentication, association, AP mode, arbitrary frame injection, SSID-targeted probe, user-data transmission, NVM/NOR write or persistent calibration is introduced. The only permitted user TX remains ordinary wildcard probe requests generated by cfg80211 for a single channel-8 scan after explicit `--ack-tx`.

If the managed-vif transition changes or invalidates the retained coefficients, v1.14.74 fails before scan with `active-scan-managed-vif-retained-state-lost`. If live calibration itself fails, it reports `active-scan-live-calibration-failed` or `active-scan-live-calibration-verify-failed`. A genuine `active-scan-no-b43-tx-status` result is only meaningful after same-lifecycle calibration/handoff and scan completion have both succeeded.
