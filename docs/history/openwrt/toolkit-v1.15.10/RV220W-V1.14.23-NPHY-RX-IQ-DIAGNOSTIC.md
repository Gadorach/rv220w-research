# RV220W v1.14.23 — N-PHY receive-state and IQ diagnostic

## Prior hardware result

v1.14.22 forced b43 PIO before first probe. The CA 2.4 GHz monitor sweep reported `pio=1`, exact requested/reported frequency agreement on channels 1–11, b43 `STARTED` and radio-on, but zero interface RX packets and zero non-empty tcpdump receive summaries. This follows v1.14.21 DMA zero-RX evidence, including a repeat with antennas attached and a strong dual-band WAP less than two metres away. The host DMA engine is no longer the leading fault.

## Purpose

This release does not alter RF calibration. It asks whether the initialized N-PHY receive path itself is active below mac80211 frame decode.

The new b43 `nphy_rxdiag` debugfs file snapshots N-PHY classifier/RF-sequence/RF-control/AFE/gain registers and selected BCM2056 synthesizer/RX-chain registers. If b43 is STARTED, reading the file also invokes the same N-PHY IQ-estimator register sequence already used by `b43_nphy_rx_iq_est()`: 4096 samples, wait-time 32, non-wait mode, start, poll, and read the two cores' I/Q power and cross-product accumulators.

No transmit tone/sample playback, RF override, RX-IQ calibration routine, scan, association, AP, injection or user traffic operation is exposed. The only diagnostic PHY writes are IQ-estimator sample-count/wait/mode/start controls.

## Interpretation

- Estimator timeout, `RFSEQCA` RX-enable mask other than 3, or CCK/OFDM classifier bits not both set: direct initialized PHY-state problem.
- Estimator completes and every I/Q power accumulator is exactly zero: prioritize BCM2056/FEM/AFE/RF power-up and analog receive state.
- Estimator completes with non-zero I/Q power while monitor frame RX remains zero: ADC/IQ activity exists; prioritize receive calibration, classifier/baseband and decode differences. Non-zero power alone is not treated as proof of a valid RF signal.

Linux 6.12's N-PHY rev3+ RX-IQ calibration entry point remains unimplemented (`return -1`) and its rev3–6 superswitch initialization retains an inactive FIXME block. Those are source gaps to compare against stock `wl.ko` only after this diagnostic determines which branch applies.
