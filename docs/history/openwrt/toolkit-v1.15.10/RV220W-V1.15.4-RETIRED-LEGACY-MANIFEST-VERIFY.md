# RV220W v1.15.4 — retired legacy persistent manifest verification

The v1.15.2 production build is valid. v1.15.3 corrected the historical v1.14.89 quarantine comparison, but the hardware workspace exposed one remaining assumption: the verifier still required the physical v1.14.89 quarantine directory to remain forever whenever the genuine legacy `rj45-luci-persistent` manifest remained.

Modern production builds legitimately clean old wrappers and quarantine directories. The old manifest may remain as harmless historical metadata. v1.15.4 therefore classifies legacy component state as follows:

- manifest present, both legacy wrappers absent, and `artifact_prefix=rv220w-openwrt-rv220w-rj45-luci-persistent`: retired metadata; warning only;
- manifest + both wrappers present: verify normally, except the exact proven v1.14.89 collision wrapper pair is classified as historical collision evidence;
- any one-sided/partial wrapper set: fail closed;
- manifest-only state with an unexpected artifact prefix: fail closed.

The current `rv220w-wifi-client-persistent` production namespace is independently mandatory and retains component-manifest verification, built-kernel front-panel LED marker verification, deep SquashFS policy verification, and sysupgrade metadata verification.

No OpenWrt source/image, kernel, DT, package, wireless configuration, NOR layout, or target runtime change is made. Do not rebuild. Upgrade the toolkit and rerun `./rv220w.fish verify` against the existing v1.15.2 production artifacts.
