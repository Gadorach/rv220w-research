# RV220W v1.14.59 — retained live calibration state

## Purpose

v1.14.58 hardware-qualified the complete reconstructed N-PHY4/BCM2056r3 RX-IQ + RCCAL transaction with natural return 0 and exact rollback. v1.14.59 changes only the cleanup policy for one explicit dual-ack stage, `retained-state`.

## Retained state

After natural completion, the test keeps in live RAM/hardware only:

- RX-IQ compensation A0/B0/A1/B1; and
- BCM2056 RX_LPC, RX_HPC and TX_LPC for both cores (six registers total).

The retained values must equal the independently captured coefficient candidates and derived RCCAL commit.

## Restored transient state

The test still restores/verifies the full 320-word N-table17 sample surface, IQEST registers, temporary per-core PHY/radio calibration setup, TX-power state/tables, RFSEQ gains, RX-gain overrides, BBConfig, hang-avoid, carrier/deaf nesting and sample playback state.

No flash/NVM write is permitted. Association, AP mode, frame injection and user-data TX remain blocked.

## Qualification semantics

A PASS requires natural `primary_rc=0`, `integration_complete=1`, `retained_state_verified=1`, cleanup rc/mask zero, MAC suspend/resume verification, post-cleanup A0/B0/A1/B1 equal to the candidates, and all six RCCAL readbacks equal to the derived values. `rollback_verified=0` is expected because the intended calibration state is deliberately retained.

Normal `--rxiq-calibration` remains blocked in this release.
