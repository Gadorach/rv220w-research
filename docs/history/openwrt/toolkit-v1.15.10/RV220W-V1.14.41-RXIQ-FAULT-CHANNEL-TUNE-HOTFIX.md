# RV220W v1.14.41 — pre-tone RX-IQ fault-gate channel-tune hotfix

## Hardware result from v1.14.40

v1.14.40 compiled successfully through `package/kernel/mac80211`, produced the RAM-only wifi-discovery ELF, and booted normally on the RV220W. b43 again identified the BCM4322 as N-PHY rev4 with BCM2056 radio rev3 and the wired DSA baseline remained operational.

The five requested pre-tone rollback tests did **not** execute the kernel transaction. Every target capture stopped after:

```text
rxiq_fault_frequency=2447
rxiq_fault_setfreq_rc=234
```

The host command printed:

```text
kernel reports: (extension) channel is disabled
command failed: Invalid argument (-22)
```

Shell status 234 is `256 - 22`, corresponding to the reported `EINVAL`. No `rxiq_fault_write_rc`, primary result, cleanup result, MAC suspend/resume, IQ tuple or capture-complete field was produced. Therefore v1.14.40 supplies **no rollback result**; it only identifies a failed channel-tune precondition.

## Root cause and change

The new v1.14.40 fault helper was the only fixed-channel RV220W diagnostic that requested an explicit HT chandef:

```sh
iw dev rvwfault0 set freq 2447 HT20
```

The previously hardware-qualified monitor and RX-IQ paths use the plain frequency form after bringing the monitor interface up:

```sh
iw dev <monitor> set freq 2447
```

v1.14.41 removes only the `HT20` argument and keeps the already-qualified ordering: create monitor interface -> interface UP -> wait -> set frequency -> verify `iw dev ... info` readback -> only then write the fault debugfs control.

The b43 kernel patch is byte-identical to v1.14.40 (`b3f3be53b9e61452bc8fbe64a24e3fc5ef55063b0a98f51d16a9eb25015516a0`). The five reachable fault stages and all pre-tone limits are unchanged.

## Analyzer improvement

The fault analyzer now reports a distinct `precondition-channel-tune-failed` finding when `rxiq_fault_setfreq_rc` is non-zero and no transaction fields exist. This prevents an unexecuted transaction from being described as if cleanup, MAC serialization and IQ rollback themselves failed.

## Hardware sequence

After build and RAM-boot qualification, run `carrier` first. Continue to `tpc-off`, `gain-table`, `core0-phy`, and `core0-radio` only after each preceding capture passes. Normal `--rxiq-calibration` remains blocked.
