# RV220W v1.14.31 — RX-IQ tune sequencing and selectable 2.4 GHz channel

## Hardware result that triggered this release

v1.14.30 completed the OpenWrt/mac80211 build and RAM boot. The active RX-IQ collector then failed before writing `run` to the debugfs calibration control: `iw dev rvwcal0 set freq 2412` returned `Resource busy (-16)` because the newly-created monitor interface had not yet been brought UP. Consequently the empty v1.14.30 analyzer report contains no calibration evidence.

## Change

The target helper now creates `rvwcal0`, brings it UP, waits for b43 to enter the started state, then tunes it. The tune return code and `iw dev ... info` frequency readback are emitted and must pass before calibration starts.

The explicit diagnostic channel is selectable from CA channels 1 through 11. Frequency is `2407 + channel*5` MHz. The kernel debugfs control independently rejects channels outside 1-11 and remains restricted to N-PHY rev4, BCM2056 rev3, 2.4 GHz, and forced PIO.

The active RX-IQ reconstruction itself is unchanged from v1.14.30: live coefficient save, verified MAC suspend, stock-derived internal-tone/gain sequence, cleanup, MAC resume, five-second monitor observation, second verified MAC suspend, exact coefficient rollback/readback, and final MAC resume. No calibration cache/chanspec or persistent storage is written.

## Current hardware test

Use channel 8 / 2447 MHz so the nearby strong AP can be the decoded-frame observation source without reconfiguring the production network.

```fish
./rv220w.fish collect-wifi \
  --rxiq-calibration \
  --country CA \
  --channel 8 \
  --ack-rf \
  --ack-calibration \
  rxiq-calibration-ch8
```
