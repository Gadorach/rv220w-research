# RV220W v1.14.96 — post-bootstrap installed-image identity

v1.14.95 hardware-qualified the complete persistent Wi-Fi kernel + rootfs NOR promotion and normal saved-`openwrt_boot` cold boot.

v1.14.96 changes no OpenWrt image bytes and performs no flash write. It corrects the host-side identity model after first boot.

## Why the old full-rootfs SHA is wrong after boot

The candidate staging image is a 25.375 MiB rootfs partition image containing:

1. the immutable SquashFS source image;
2. `0xff` erase-block padding to the squashfs-split boundary;
3. the remainder reserved for `rootfs_data`.

On first boot, fstools initializes `rootfs_data` as JFFS2. From that point onward, writes to `/overlay` legitimately change bytes in the same physical MTD `rootfs` partition. Therefore the complete padded partition SHA is no longer an installed-image invariant.

For the hardware-qualified candidate:

- SquashFS source size: `5558296` bytes
- SquashFS source SHA-256: `8ab994df5cf128585108cb49779237bbe9b01c762b30a334208fb75467db048c`
- pristine padded rootfs partition SHA-256: `f3e58496486c9845412b75d93da104f9321c503e79daeaad9e36dde652f7f59c`

The first two values remain invariant across normal JFFS2 use. The last one does not.

## New verification policy

`persistent-wifi-stage verify-rootfs` now validates only `components.rootfs.source_size` bytes from the physical rootfs MTD against `components.rootfs.source_sha256`.

`persistent-wifi-stage write-kernel` uses the same immutable-prefix proof before and after a kernel write. It no longer requires a pristine all-`0xff` JFFS2 tail and therefore never asks for a rootfs rewrite merely because the overlay has been used.

`persistent-wifi-stage installed-check` is read-only and is intended for the promoted normal NOR installation. It verifies:

- exact immutable 6 MiB kernel partition SHA;
- exact immutable SquashFS source prefix;
- candidate build profile;
- SquashFS `/rom`, JFFS2 `/overlay`, overlayfs `/`;
- b43/SSB, native `pio=0`, BCM4322 IRQ109;
- disabled-radio safety state and zero wireless netdevs;
- LAN control-plane availability.

No build, TFTP boot or flash write is required for v1.14.96.
