# RV220W v1.14.97 persistent wireless control-plane diagnosis

The hardware-qualified v1.14.95/v1.14.96 NOR image scans successfully on the BCM4322, but the first normal LuCI configuration did not produce a persistent station or AP interface. Runtime installation of `hostapd` and then full `wpad` did not change the observed lifecycle: b43 repeatedly logged `Adding Interface type 2` (station), switched between 5 GHz and 2.4 GHz during scan, then removed the station interface. No `Adding Interface type 3` (AP) was observed.

Upstream b43 explicitly advertises AP, mesh, station, and ad-hoc interface modes and accepts `NL80211_IFTYPE_AP` in `b43_op_add_interface`, so v1.14.97 first tests the local cfg80211/b43 AP path directly before changing the persistent image.

## No-build boundary

The complete `openwrt/` tree is unchanged from v1.14.96. Do not rebuild, TFTP boot, or write NOR for this release.

## Read-only diagnosis

```fish
./rv220w.fish persistent-wifi-stage wireless-diagnose
```

This prints UCI wireless state with keys redacted, `wifi status`, `network.wireless` ubus status, supported interface modes, regulatory state, active wireless interfaces, daemon/package state, and recent wireless logs.

## Direct AP probe

The user already installed full `wpad` into the JFFS2 overlay. The temporary probe therefore uses the current running image and bypasses UCI/netifd:

```fish
./rv220w.fish persistent-wifi-stage ap-probe \
    --channel 1 \
    --ssid RV220W-AP-PROBE \
    --confirm RV220W_TEMP_OPEN_AP_PROBE_V11497
```

The probe emits a short-lived **open** beacon. It never runs `uci set`, `uci delete`, or `uci commit`. It runs `wifi down`, creates `rvwap0` as `__ap`, launches hostapd, requires `AP-ENABLED` plus a new b43 `Adding Interface type 3` marker, cleans up the direct interface, and finishes with `wifi up` using the unchanged UCI configuration.

A PASS localizes the remaining fault to UCI/netifd policy/configuration. A failure before type-3 creation localizes it to cfg80211/mac80211/b43 AP capability. A type-3 success followed by hostapd failure localizes it to hostapd/channel/regulatory integration.
