# RV220W v1.14.91 — unprivileged persistent-WiFi verification

The v1.14.90 restage run proved the correctly named candidate components: kernel wrapper `d3df4710...97a9c`, rootfs wrapper `f3e58496...f59c`, and sysupgrade `5c4290d0...943de`. The failure was host-side verification.

`unsquashfs` full extraction tried to create the SquashFS `/dev/console` character device and failed because the host process was not root. v1.14.91 keeps the same deep policy checks but uses `unsquashfs -lc` to list entries and `unsquashfs -cat` to read `/etc/modules.conf`, the radio-disable guard, and optional wireless config without extracting special files.

The failed v1.14.90 run also stopped before quarantine, leaving v1.14.89's legacy-named wrappers in place. Those wrappers have the exact same SHA-256 as the correctly named candidate wrappers. Restage now performs this exact-duplicate quarantine before rootfs content inspection. `verify` independently recognizes the collision only if the candidate manifest validates first and both wrapper pairs compare byte-identically.

No OpenWrt rebuild is needed. Upgrade, rerun `./rv220w.fish restage persistent-wifi`, then `./rv220w.fish verify`. Do not run `persistent-stage` or write NOR.
