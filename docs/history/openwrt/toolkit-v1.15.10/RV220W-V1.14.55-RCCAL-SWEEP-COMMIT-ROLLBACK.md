# RV220W v1.14.55 — RCCAL sweep + derived commit rollback qualification

## Qualified predecessor

v1.14.54 hardware-qualified the mirrored per-core portion of the Broadcom rev3+ RX-IQ transaction through point 11. Core1 RX / opposite TX0 gain search completed with three iterations and a usable row-5 optimum, then the corrected dedicated 16,384-sample core1 estimator calculated A1/B1 with mask `0x02`. The transaction reached the architecture-resolved injected cancellation and restored all state exactly.

## Why RCCAL remains a separate gate

RCCAL is not another mirrored core calculation. In the vendor rev3+ flow it is entered on the core1/calibration-type path, uses DAC-test sample playback semantics, performs a separate gain-control pass and RC binary sweep, then feeds a post-loop radio-register commit. v1.14.55 therefore qualifies the complete RCCAL sweep and its derived non-IPA commit together while still cancelling before any normal calibration can escape the diagnostic transaction.

## Channel-8 / 20-MHz vendor behavior

The outer transaction clears `BBCFG.RSTRX` before calibration. That also makes the DAC-test spur selector deterministic (`0`) for this run. The target-scoped corrected waveform loader therefore uses the vendor DAC-test playback mode with 160 samples at 20 MHz. The existing 320-word N-table17 snapshot is sufficient for both the 20-MHz and 40-MHz geometries.

The RCCAL sweep retains the reconstructed Broadcom constants and semantics:

- RX core1 / opposite TX core0;
- RCCAL gain-control path uses DAC-test tone mode;
- reference tone: 3 MHz;
- target tone: 9.5 MHz;
- IQ estimator: 1024 samples;
- reference normalized power: `max((I+Q)>>11, 1)`;
- target normalized power may legitimately be zero;
- 20-MHz target power ratio: 28606;
- binary sweep starts at raw RCCAL 128 with step 16;
- accepted final raw value: 137..142, fallback 140;
- exported candidate: `best_raw - 128`, therefore normally 9..14.

## Derived non-IPA commit

The RV220W 2.4-GHz path is non-IPA. After the core1 sweep candidate is observed, v1.14.55 derives:

```text
RX_LPC = candidate | 0x80
RX_HPC = clamp((((candidate - 12) >> 1) + 10), 0, 31) | 0x80
TX_LPC = clamp(((candidate - 12) + 10), 0, 31) | 0x80
```

The same core1-derived values are written to both cores, matching the vendor outer flow. The diagnostic captures all six live register values and independently compares them with the derived expectations before point-13 cancellation.

## Rollback boundary

`rccal-commit` is the only new public fault stage. The intermediate RCCAL sweep point is intentionally not exposed separately. On a successful run, point 13 is reached immediately after live commit readback, then cleanup restores and verifies the pre-run RX_LPC/RX_HPC/TX_LPC values for both cores along with all existing PHY, radio, TX-power, IQEST, sample-table and IQ-coefficient rollback surfaces.

Normal `--rxiq-calibration` remains blocked in v1.14.55.
