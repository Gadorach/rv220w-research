# RV220W v1.14.40 — RX-IQ pre-tone fault debugfs compile hotfix

v1.14.39 did not reach hardware. Its OpenWrt build failed in `package/kernel/mac80211` while compiling b43 `debugfs.c`. The final nested patch contained `++static int nphy_rxiq_cal_write_file(...)`; unified-diff processing consumed the first plus and emitted the second into C source, producing an invalid `+static` token. The following undeclared-FOPS and unused-helper diagnostics were cascading effects.

v1.14.40 changes no RX-IQ transaction ordering, register sequence, fault-point depth or RF policy. It removes the leaked literal plus, advances the diagnostic policy marker to v1.14.40, retains v1.14.39 as a hash-pinned predecessor/evidence fixture, and adds a regression that applies the final debugfs insertion hunk to a clean proxy source and scans the generated C for leaked diff markers.

The first hardware run remains the same five pre-tone rollback checkpoints, one at a time, only after a clean build and RAM boot. Normal `nphy_rxiq_cal: run` remains blocked.
