# RV220W v1.14.54 — combined core1 gain + IQ rollback qualification

## Qualification state entering this revision

v1.14.52 hardware-qualified point 9 (`core1-radio`) on CA channel 8. The run retained the qualified core0 gain/IQ path, core1 `RFSEQCA=0x1221`, BCM2056 core1 calibration muxes `TXMUX=RXMUX=0x0006`, clear LNAG_TUNE high nibble, architecture-resolved `-ECANCELED=-158`, cleanup mask zero, MAC suspend/resume, and exact coefficient rollback.

v1.14.53 packaged point 10 (`core1-gain`) but was intentionally not hardware-run. At user direction, v1.14.54 collapses the remaining per-core mirrored stages—point 10 gain and point 11 dedicated IQ—into one hardware transaction to reduce iteration count. A point-11 run necessarily traverses and independently gates point 10 first.

RCCAL remains separate because it is not a simple mirrored per-core stage: it introduces its own gain-control/sweep/candidate/commit semantics.

## Vendor/core-specific audit before combining the stages

The Broadcom-derived rev3+ path runs the same per-core sequence for each selected RX core: PHY setup, radio setup, gain control, dedicated tone, and RX-IQ coefficient calculation. The core1 path differs only in indexed resources. v1.14.54 explicitly gates those asymmetries:

- RX core 1 uses opposite TX core 0 on pre-rev7 N-PHY.
- Core1 PHY route remains `RFSEQCA=0x1221`.
- BCM2056r3 core1 receive calibration uses TX0 / RX1 calibration mux banks; both mux values must be `0x0006` and LNAG_TUNE bits 4..7 must be clear.
- TX core0 uses its own gain-table/RFSEQ gain slot.
- TX core0 BBMULT occupies the **high byte** of N-table15/87; the point-10 gate compares bits 15:8, not the low byte used when TX core1 is active.
- Core1 gain estimation consumes the core1 I/Q estimator fields.
- Dedicated core1 coefficient calculation uses mask `0x02` (`BIT(1)`) and records candidate A1/B1 separately from the already-qualified A0/B0 telemetry.

## Combined point-11 sequence

The public `core1-iq` fault stage performs:

1. all previously qualified points through core1 BCM2056 radio setup;
2. core1 gain search/internal corrected 160-sample tone, with independent core1 telemetry and the TX0/high-byte BBMULT gate;
3. point-10 boundary traversal without cancellation;
4. corrected dedicated core1 tone;
5. explicit 16,384-sample core1 RX-IQ coefficient calculation using mask `0x02`;
6. capture of core1 raw estimator energy, calculation status, applied mask, and candidate A1/B1;
7. injected point-11 cancellation before RCCAL;
8. exact transaction rollback and coefficient restoration before MAC resume.

A v1.14.54 PASS qualifies points 10 and 11 together. Any failed intermediate gate fails the combined run.

## Still blocked

- RCCAL sweep/commit;
- normal RX-IQ calibration;
- scan, association, AP mode, user-data TX or frame injection;
- SPROM/OTP/NOR/MTD/U-Boot or other persistent writes.

The next boundary after a successful combined run should be a separate RCCAL observation/sweep revision, not full calibration.
