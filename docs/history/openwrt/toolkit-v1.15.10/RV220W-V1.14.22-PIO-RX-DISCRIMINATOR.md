# RV220W v1.14.22 — forced-PIO receive discriminator

## Hardware evidence leading to this gate

v1.14.20 completed a CA 2.4 GHz passive scan with a successful command return, no probe/SSID request, no association and no b43 kernel error, but produced zero BSS entries.

v1.14.21 then bypassed cfg80211 scan/BSS discovery and used a fixed-channel monitor interface. All 2.4 GHz channel changes returned success but the interface RX packet counter remained zero. The first run had no antennas installed. The repeat was performed with the antennas connected and a strong dual-band access point less than two metres away; receive counters still remained zero. This makes an empty RF environment an implausible primary explanation.

The v1.14.21 analyzer also exposed two evidence-presentation bugs: a blank tcpdump stdout line was counted as one summary and `Failed frames 0/0` could be matched as a kernel error. Those are corrected in v1.14.22; neither affected the zero network-interface RX counter.

## PIO discriminator

b43 already has separate PIO and DMA transfer engines. v1.14.22 sets `pio=1` in the RAM image before the first b43 probe. No driver is unloaded or rebound. The same native physical SPROM and MTD-derived permanent MAC paths are retained.

The monitor sweep remains receive-only. For 2.4 GHz it visits 2412 through 2462 MHz (channels 1–11). For the supplementary 5 GHz test it visits 5180/5200/5220/5240 MHz (36/40/44/48, non-DFS only). After each channel-set operation the helper reads the monitor interface frequency back and requires it to equal the requested value. Each dwell lasts three seconds.

The diagnostic makes no scan request and exposes no SSID/probe, association, AP, frame injection or user-data operation.

## Interpretation

- **PIO receives frames:** the RF/N-PHY path can deliver receive data and the v1.14.21 DMA result points toward the Octeon/b43 DMA mapping, descriptor or coherency path.
- **PIO also receives zero frames:** with the attached antennas and strong nearby WAP, the transfer engine is no longer the primary discriminator. The next stage should capture/read-only compare N-PHY, radio 2056, FEM and channel-programming registers against the stock Broadcom driver before making RF changes.

No association or AP qualification follows automatically from either result.
