# RV220W v1.14.35 — stock RX-IQ dispatch correction / rev4 reconstruction checkpoint

## Hardware result carried from v1.14.34

The v1.14.34 channel-8 image cross-built and booted successfully. The active diagnostic tuned/read back 2447 MHz, ran under verified MAC suspend/resume, completed temporary-state cleanup, and rolled coefficients back safely. All three 1024-sample gain-selection IQ estimates and the final 16384-sample estimate were zero, so the active internal calibration stimulus did not reach the RX estimator.

Those results remain useful as evidence about the diagnostic implementation, but they are **not valid evidence about the stock rev4 RX-IQ algorithm** because subsequent stock-binary dispatch analysis corrected an earlier reconstruction assumption.

## Correct stock dispatch

The preserved RV220W Broadcom `wl.ko` 5.60.120.9 wrapper `wlc_phy_cal_rxiq_nphy` performs these tests at entry:

```text
phy_rev >= 7  -> helper at .text+0x11d370
phy_rev 3..6  -> helper at .text+0x11d370
phy_rev < 3   -> legacy inline body
```

For the RV220W N-PHY revision 4, the stock path therefore calls the large local helper beginning at `.text+0x11d370`. The active v1.14.28-v1.14.34 diagnostic reconstructed the legacy inline body selected only for PHY revisions below 3.

The retained dispatch disassembly is `research/stock-wl-rxiq-dispatch-v1.14.35.dis`.

## Rev4 helper boundary

The genuine local helper at `0x11d370` is materially different from the legacy body. Initial reverse engineering shows that it:

- clears PHY register 1 bit 15 and enters carrier-search hold;
- for older rev3/rev4 handling, reads/writes N-PHY table 7 around offset `0x110` and derives per-core gain state;
- saves and later restores RX-core state;
- saves/restores a much broader BCM2056 register set;
- contains 2.4 GHz-specific radio operations including `0x17e`/`0x17d`;
- calls core/radio setup helpers, RF-sequence helpers, tone/sample playback, IQ estimation/compensation and cleanup helpers that differ from the legacy inline path.

The full helper is not yet reconstructed end-to-end. Therefore v1.14.35 deliberately does **not** substitute a partially mapped rev4 routine.

## Active gate retirement

v1.14.35 blocks the old active experiment at three layers:

1. host `collect-wifi.fish` refuses `--rxiq-calibration` before SSH or RF activity;
2. target `rv220w-wifi-probe rxiq-calibration` returns a dispatch-correction evidence record before interface creation or tuning;
3. kernel `nphy_rxiq_cal` rejects `run` with `-EOPNOTSUPP` before rollback capture, MAC suspension, PHY/radio writes, tone playback or coefficient changes.

The legacy implementation remains compiled only as historical reconstruction evidence while regression tests prove it is unreachable from the rev4 diagnostic control.

## What remains qualified

The following previous results are unaffected:

- native physical-SPROM double-read and CRC-qualified calibration data;
- MTD-derived first-probe operational MAC;
- b43 STARTED / BCM4322 / N-PHY rev4 / BCM2056 rev3 receiver initialization;
- forced-PIO transport;
- normal receive-path IQ activity on both chains;
- read-only `nphy_rxdiag` and `nphy_calstate` diagnostics;
- persistent v1.7.5 Ethernet/LuCI/sysupgrade platform.

The v1.14.28-v1.14.34 **active calibration outcome** is reclassified as a legacy-branch diagnostic result and must not be used to conclude that rev4 RX-IQ calibration is ineffective or unnecessary.
