# RV220W v1.14.14 — native physical BCM4322 SPROM qualification

## Hardware result carried forward from v1.14.13

The paired 16-bit SPROM capture on the RV220W proved that Linux's ordinary single-read SSB path is not returning the data stream consumed by the stock Broadcom driver on this Octeon conventional-PCI host.

For the same 220 SPROM word addresses:

- first read stream SHA-256: `df5b03b689d59b0c7050850a2e575497caf7aedefe6ab4456d0fbd884404163f`
- first read: rev8, first word `0xffff`, Linux CRC FAIL (`0x34` vs stored `0x5a`), Broadcom residue FAIL (`0xc8`)
- second/stock-retained stream SHA-256: `461f3523e65900e1896fc6aa13e9bd551533bcfef042520e0e79acba24d34c61`
- second read: first word `0x3001`, rev8, Linux CRC PASS (`0x5a`), Broadcom full-image residue PASS (`0x9f`)
- 53 of 220 words differ between first and second streams
- the existing Linux `ssb_sprom` capture matched the first stream exactly

The valid second stream decodes to:

- SVID `0x14e4`
- PID `0x432b`
- board revision `0x1302`
- boardflags `0x00000a00`
- boardflags2 `0x00000202`
- IL0 MAC `00:90:4c:d6:00:60`
- TX/RX chain masks `3/3`
- FEM2G `0x0301`

The embedded MAC is a Broadcom-generic value. Stock RV220W userspace independently derives the operational WLAN MAC as the protected platform base MAC plus four, so calibration recovery and MAC policy remain separate.

## v1.14.14 change

The RAM-only `wifi-discovery` image retires its generic fallback-SPROM source for this qualification step:

- no `brcm,ssb-sprom` DTS platform node;
- no `broadcom-4322-sprom` package requirement;
- no generic calibration blob accepted as RF evidence.

A temporary wifi-discovery-only Linux SSB patch changes only `sprom_do_read()` so each 16-bit SPROM address is read twice and the second value is retained, matching the stock Broadcom transaction sequence. SPROM write behavior is untouched.

The patch is deliberately generic and contains no RV220W, Cisco, BCM4322, MAC, calibration, or PCI-ID constants. On hardware where first and second reads are identical it should be behaviorally neutral except for one extra read transaction per word.

## Qualification gate

Before any RF operation, a v1.14.14 RAM boot must show all of the following:

1. physical PCI identity remains `14e4:432b` at runtime;
2. no fallback-SPROM provider registers or is requested;
3. SSB registers successfully from the physical SPROM;
4. b43 identifies core rev16 / N-PHY rev4 / radio `0x2056` rev3;
5. Linux `ssb_sprom` decodes to SHA-256 `461f3523e65900e1896fc6aa13e9bd551533bcfef042520e0e79acba24d34c61` with stored/calculated CRC `0x5a`;
6. b43 capability evidence reports the recovered board flags rather than generic fallback values;
7. RF remains disabled.

Only after this gate should the board-derived WLAN MAC (`platform base + 4`) be applied and receiver-only firmware/RF qualification be considered.
