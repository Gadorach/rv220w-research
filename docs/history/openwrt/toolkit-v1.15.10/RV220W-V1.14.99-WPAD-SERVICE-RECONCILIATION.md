# RV220W v1.14.99 — live wpad service reconciliation

## Scope

v1.14.99 is a host/toolkit-only diagnostic and service-lifecycle correction. It does **not** rebuild OpenWrt, alter the persistent NOR image, modify b43, or write UCI wireless configuration.

The v1.14.97 hardware run already proved that the BCM4322 can run AP mode through b43/mac80211 on both channel 1 and channel 36 when a temporary AP interface and hostapd are launched directly. v1.14.98 then enabled the ordinary UCI AP section, but normal netifd remained `pending`/`up=false` with no AP netdev and no global hostapd process.

## Why reconcile wpad

The persistent candidate was originally built with the standalone client-only `wpa-supplicant` package. During hardware diagnosis the running overlay was changed to full `wpad`. The installed package therefore provides both `/usr/sbin/hostapd` and `/usr/sbin/wpa_supplicant`, but the running global daemon state can still reflect the process set that existed before the live package replacement.

OpenWrt's `wpad` service starts global hostapd and wpa_supplicant control daemons. Modern netifd/ucode wireless setup hands generated PHY configuration to these global services. A direct hostapd probe bypasses that service path, which explains how direct AP operation can pass while normal netifd remains pending.

## New action

```fish
./rv220w.fish persistent-wifi-stage reconcile-wpad \
    --confirm RV220W_RECONCILE_WPAD_SERVICE_V11499
```

The target action:

1. refuses to run when `uci changes wireless` is non-empty;
2. records `/etc/config/wireless` SHA-256 and current global daemon/socket state;
3. executes `wifi down`;
4. restarts `/etc/init.d/wpad`;
5. requires fresh hostapd and wpa_supplicant global processes plus their global control sockets;
6. proves `/etc/config/wireless` is unchanged;
7. executes `wifi up` using the administrator's existing UCI configuration;
8. requires `radio0.up=true`, an AP netdev, a live hostapd process, and a new b43 `Adding Interface type 3` event;
9. proves `/etc/config/wireless` remained byte-identical.

No `uci set`, `uci delete`, or `uci commit` occurs in this action.

## v1.14.98 rollback hardening

The v1.14.98 activation helper could report a byte-exact file restore while pre-existing staged UCI deltas caused the next `wifi up` to reconstruct a different effective state. v1.14.99 therefore refuses the transactional activation path when staged wireless changes exist and explicitly reverts staged wireless deltas around raw-file restoration.

## Next hardware run

No build, TFTP boot, or flash operation is required.

```fish
./rv220w.fish persistent-wifi-stage wireless-diagnose
./rv220w.fish persistent-wifi-stage reconcile-wpad \
    --confirm RV220W_RECONCILE_WPAD_SERVICE_V11499
./rv220w.fish persistent-wifi-stage installed-check
```

If reconciliation succeeds, the next production image should replace the standalone client-only supplicant package with an AP+station `wpad` variant and preserve normal administrator wireless configuration across reboot/sysupgrade.
