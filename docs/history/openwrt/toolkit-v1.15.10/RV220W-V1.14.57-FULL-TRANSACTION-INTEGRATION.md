# RV220W v1.14.57 — full rev4 RX-IQ transaction integration qualification

## Qualified predecessor

v1.14.56 hardware-qualified the final reconstructed primitive boundary on CA
channel 8.  The complete core0/core1 gain + coefficient path passed, followed
by vendor DAC-test RCCAL gain control, the 3/9.5 MHz 20-MHz RC sweep and the
mirrored non-IPA commit.  Hardware selected `best_raw=140`, candidate `12` and
live `RX_LPC/RX_HPC/TX_LPC = 140/138/138`, then reached target `-ECANCELED`
(`-158`) with cleanup mask zero and exact rollback.

The remaining question is therefore integration rather than another algorithm.

## v1.14.57 boundary

`full-transaction` uses the existing dual-acknowledgement `rxiq-fault-test`
transport but **does not inject a fault**.  The kernel runs:

```text
cal_type=2
fault=NONE
```

through the complete reconstructed rev3+/rev4 sequence:

1. transaction/global state snapshot;
2. core0 PHY + BCM2056 setup;
3. core0 gain search/internal corrected tone;
4. core0 dedicated corrected tone and 16,384-sample A0/B0 calculation;
5. core0 local setup restore;
6. core1 PHY + BCM2056 setup;
7. core1 gain search/internal corrected tone using opposite TX0 and high-byte BBMULT;
8. core1 dedicated corrected tone and 16,384-sample A1/B1 calculation;
9. vendor DAC-test RCCAL gain;
10. 3 MHz reference / 9.5 MHz target RC sweep;
11. derived mirrored non-IPA RCCAL commit;
12. explicit natural-completion marker/live-state capture;
13. the existing exact transaction rollback;
14. MAC resume.

The expected primary return is **0**, not `-ECANCELED`.

## Integration-specific rollback correction

Prior fault qualification snapshotted N-table17 according to checkpoint depth.
A natural no-fault run has no fault depth, so v1.14.57 explicitly snapshots the
same complete 320-word sample table when `cal_type=2 && fault==NONE`.  This
prevents the integration test from leaving calibration waveform data behind.

All prior rollback surfaces remain mandatory: IQEST controls, sample table,
TX-power state/tables, per-core PHY/radio state, RFSEQ gains, RX gain overrides,
RCCAL registers, BBConfig, coefficient tuple, carrier/deaf nesting and MAC
serialization.

## Natural-completion proof

After both IQ calculations and the RCCAL commit, but before cleanup, the
transaction captures the live coefficient tuple and sets `integration_complete`.
The kernel/debugfs, target helper and host analyzer require:

```text
expected_primary_rc=0
primary_rc=0
integration_complete=1
integration_live_iq_gate=1
```

and independently verify:

```text
integration_live A0/B0 == recorded core0 candidate A0/B0
integration_live A1/B1 == recorded core1 candidate A1/B1
```

The existing RCCAL analyzer simultaneously validates the six live commit
registers against the independently derived candidate.

Only after those observations does cleanup restore the original coefficient
and calibration state.  Final qualification still requires cleanup rc 0,
cleanup mask zero, exact before/after tuple, MAC suspend/resume verification,
no association/stations, no user-data TX/frame injection/AP, and no persistent
write.

## Safety boundary

Normal `--rxiq-calibration` remains blocked.  v1.14.57 is still RAM-only and
rollback-only.  Passing this stage proves that the complete reconstructed
transaction can execute naturally as one unit; it does not yet authorize
keeping the resulting calibration state after return.
