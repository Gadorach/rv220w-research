This is a packaging-only correction to the intended v1.14.37 RX-IQ outer-transaction checkpoint. The compiled C additions and fail-closed policy are unchanged.

The original v1.14.37 package passed source-token regressions but its final assembled `openwrt/wifi/998-b43-rv220w-platform-capabilities.patch` contained four stale unified-diff hunk counts. The platform installer correctly rejected the first mismatch before copying build patches or invoking OpenWrt:

- original bad nested-patch SHA-256: `5dbd3e06159b92d64fa054c773c9b1e3a7b53ca105bdd0c8a0b99d641b8f1a1e`
- first observed mismatch: declared old/new `11/70`, actual `10/69`
- three additional stale headers were found by running the installer's exact hunk-count parser over the complete patch.

Packaging revision r1 corrects all four hunk headers and adds parser-level regression coverage to both the v1.14.37 transaction test and a dedicated packaging test. No patch body/source line was added, removed, or semantically changed by this hotfix.

The recovery upgrader accepts:

1. a normal v1.14.36 toolkit;
2. the exact failed v1.14.37-r0 toolkit identified by the bad nested-patch hash above; or
3. an already installed v1.14.37-r1 toolkit, in which case it resumes platform installation/verification idempotently.

Unknown or modified v1.14.37 trees are refused.
