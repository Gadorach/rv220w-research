# RV220W v1.11.6 explicit-output ELF DTB hotfix

## Observed v1.11.5 failure

The persistent build again completed package assembly and generated a 4092.47 KiB SquashFS. The kernel pipeline copied and stripped `vmlinux.elf`, patched the command line, and invoked GNU objcopy with `.appended_dtb` section flags and content replacement.

The helper still supplied only one ELF pathname, requesting an in-place transformation. The command returned to Make without an emitted diagnostic, but the input pathname no longer existed; the immediately following copy failed with `cannot stat`.

## Corrected pipeline

`Build/rv220w-append-dtb-elf` uses separate input and output paths:

```make
$(TARGET_CROSS)objcopy ... $@ $@.rv220w-dtb
```

It then:

1. requires the explicit output to be non-empty;
2. dumps `.appended_dtb` from that output;
3. compares the dumped bytes with the generated RV220W DTB;
4. replaces `$@` only after the comparison succeeds.

A failed objcopy or comparison therefore leaves the original working ELF intact and produces a direct build error rather than a later missing-file symptom.

## Scope

This is a host/source-build correction only. It does not alter the persistent writer, flash geometry, command line, rootfs, overlay policy, boot-chain patches or router state.
