# RV220W v1.14.80 — normal managed-start PIO qualification

## Why this release exists

The v1.14.79 gated channel-8 scan actually passed at the hardware boundary. The kernel retained-state gate verified IQ/RCCAL on channel 8, b43 completed a TX status, IRQ109 advanced, and two channel-8 BSS results were returned. The analyzer's original FAIL was caused only by parsing `freq: 2447.0` as though frequencies had to be integers.

That result changes the next useful experiment. Instead of adding more lifecycle gates around mac80211, v1.14.80 asks whether the corrected RV220W hardware can run the ordinary b43/mac80211 managed-interface lifecycle.

## Runtime design

The hardware-specific corrections retained are:

- native BCM4322 SPROM consumption and stock WLAN MAC derivation;
- RV220W PCI INTA# -> Octeon PCI INT0 / CIU36 routing;
- the reconstructed BCM4322 N-PHY rev4 / BCM2056r3 RX-IQ + RCCAL transaction;
- forced PIO for this one experiment.

The reconstructed calibration is now connected to the existing `b43_nphy_cal_rx_iq()` path that `b43_phy_initn()` already calls during ordinary N-PHY initialization. Upstream rev3+ b43 currently reaches `b43_nphy_rev3_cal_rx_iq()` and gets the existing `-1` stub; v1.14.80 replaces that stub only for the exact BCM4322/N-PHY4/BCM2056r3 combination. On success the unchanged b43 caller continues into its normal `b43_nphy_save_cal()` path. Other rev3+ hardware keeps the upstream stub behavior.

For this full-send diagnostic the collector records whether that automatic calibration succeeded but does **not** stop the normal managed scan if it did not. The reconstructed transaction has its qualified rollback path, so a calibration error remains observable in dmesg/evidence while normal b43/mac80211 lifecycle is allowed to show how far it gets without another userspace stop/restore gate.

`normal-start` then creates exactly one managed interface, brings it up normally, and issues one ordinary cfg80211 scan across Canadian 2.4-GHz frequencies 2412 through 2462 MHz. It does not create a monitor vif and does not use `integration:retain`, `verify:retained`, `active-scan:arm`, channel pinning or the retired one-shot gate.

## Scope

This release is RAM-only and intentionally does not authenticate, associate, start AP mode, inject arbitrary frames, transmit user data, or write persistent/NVM/NOR state. The purpose is to qualify normal b43 PHY startup, managed-vif lifecycle and standard scan TX/RX with PIO held constant.

If this passes, native b43 DMA is the next clean single-variable experiment.
