# RV220W v1.14.85 — RAM hot-deploy and DHCP/gateway L3 qualification

v1.14.84 hardware-qualified ordinary native-DMA WPA-PSK association. The apparent frequency failure was analyzer-only: `iw link` emitted `freq: 2447.0`, while analyzer v3 accepted only integer text.

v1.14.85 changes no OpenWrt, kernel, b43, module, firmware, DT or initramfs package content. It adds a host-side `wifi-hot-deploy` action that transfers the current `rv220w-wifi-probe` over SFTP to `/tmp/rv220w-wifi-probe.hot`, marks it executable, writes a version marker, and verifies SHA-256 on the target. `collect-wifi` automatically prefers that helper when its marker matches the local toolkit. The hot helper disappears on reboot.

The new `managed-l3` test reuses the already-qualified native-DMA WPA-PSK path, then runs BusyBox `udhcpc` with a private RAM-only script. The script assigns only the leased address and prefix. It does **not** install a default route. The test sends three ICMP echoes bound to the Wi-Fi interface to the first DHCP-advertised router, then removes the supplicant config, DHCP helper/state/log, IPv4 address and test interface. No DNS, Internet reachability, UCI network update, NVM write or NOR write is performed.

If the v1.14.84 RAM image is still booted, neither OpenWrt compilation nor another TFTP boot is required: update the toolkit, run `./rv220w.fish wifi-hot-deploy`, then run the managed-L3 collector.
