# RV220W v1.14.42 — RX-IQ fault errno ABI and safe readback

## Hardware result that triggered this revision

v1.14.41 successfully built and RAM-booted. The `carrier` fault test tuned CA channel 8 to 2447 MHz and entered the kernel transaction. The post-fault state reported:

- `fault_point=1`
- `rxcore_state=0x03`
- `primary_rc=-158`
- `cleanup_rc=0`
- `cleanup_fail_mask=0x00000000`
- `mac_suspend_verified=1`
- `mac_resume_verified=1`
- `rollback_verified=1`
- before/after IQ tuple `0,0,0,0`

The kernel debugfs writer itself accepted the transaction; the target and host validators alone rejected it because they compared the numeric return code with `-125`. On Linux MIPS, `ECANCELED` is 158. Therefore the observed `-158` is the intended injected cancellation.

## v1.14.42 correction

The debugfs record now emits:

```text
expected_cancel_rc=<kernel -ECANCELED value>
```

The target helper and host analyzer compare `primary_rc` against that value. They do not contain either `-125` or `-158` as a cancellation constant, which keeps the diagnostic valid across errno ABIs.

The v1.14.41 capture also showed b43 diagnostic warnings caused by reading PHY RX-IQ registers from the debugfs **read** handler after the MAC had resumed. v1.14.42 removes that access. Exact coefficient restoration is still read-verified inside `b43_nphy_rv220w_rxiq_fault_diag()` while the MAC is suspended, and the outer debugfs writer separately verifies MAC resume. The evidence contract is therefore `before == after`, cleanup exact, and resume verified; no post-resume PHY register read is required.

## Safety boundary

The reachable fault IDs remain 1 through 5 only:

1. carrier-search hold
2. TPC disabled
3. calibration gain-table staged
4. core-0 PHY setup
5. core-0 BCM2056 radio setup

Fault point 5 remains before `rv220w_rxiq_rev4_gainctrl()` and before `b43_nphy_tx_tone()`. Normal `nphy_rxiq_cal: run` remains blocked. No scan, association, AP, user-data TX, frame injection, SPROM/NVM/NOR write, IQ calculation or RCCAL is requested by this gate.

## Qualification sequence

Rebuild and RAM-boot v1.14.42, then rerun `carrier`. It must report the architecture-resolved expected cancellation and no enabled-MAC PHY read warnings. Only after carrier passes should `tpc-off` be attempted.
