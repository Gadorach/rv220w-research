# RV220W v1.14.89 — persistent Wi-Fi client candidate

## Basis

v1.14.88 proved that ordinary OpenWrt UCI/netifd can own the BCM4322 client lifecycle on the RV220W: WPA-PSK association, DHCP, native 64-bit b43 DMA, TX/IRQ progression and exact temporary-config restoration all passed.

## Candidate profile

`./rv220w.fish build persistent-wifi` produces a separately named persistent kernel/rootfs/sysupgrade set. It reuses the established `cisco_rv220w_persistent` flash layout and production DSA topology, while adding the hardware-qualified Wi-Fi stack.

The three corrections previously staged only for the RAM WLAN build are now also staged for this candidate during its build:

- `992-ssb-pci-sprom-double-read.patch` — mirrors the vendor's paired physical-SPROM read sequence;
- `993-rv220w-octeon-pci-int0-routing.patch` — maps BCM4322 INTA# to physical Octeon PCI INT0/CIU36;
- `994-octeon-pci-irq-callback-lifetime.patch` — prevents deferred SSB probe from calling freed init text.

The globally installed b43 998/999/9998 patch stack is unchanged. Native DMA remains selected by leaving b43 `pio=0`.

## Safety boundary

The image contains no SSID/PSK and a first-boot UCI guard disables every radio and removes generated `wifi-iface` sections. The existing legacy persistent profile remains untouched. `persistent-stage` intentionally does not recognize the new `wifi-client-persistent` artifact, so this release cannot write it through the normal toolkit flash workflow.

The v1.14.89 gate is therefore: build, verify artifact integrity/sysupgrade metadata, and review logs. Persistent hardware installation is deferred to a later explicitly acknowledged release.
