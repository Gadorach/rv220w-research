# RV220W v1.14.26 — split N-PHY IQ / software calibration-state diagnostic

## Hardware result carried from v1.14.25

v1.14.25 built successfully and its Wi-Fi ELF provenance matched the current toolkit, but the target diagnostic stopped immediately after the first 2412 MHz tune at `--- nphy rxdiag sample 1 ---` with rc=255. No lines from the expanded debugfs file were returned, so the empty analyzer arrays are **not** evidence that RX-IQ coefficients or calibration chanspecs were zero.

The v1.14.25 node combined the hardware-proven v1.14.24 register/IQ reads with new live PHY-register reads and new direct calibration-cache/chanspec structure reads. Because the debugfs helper constructs its output buffer before returning data to userspace, a fault later in the callback can suppress all earlier formatted lines. The hardware capture therefore cannot identify which new read caused the abort.

## v1.14.26 architecture

`nphy_rxdiag` is restored to the hardware-proven v1.14.24 implementation. It retains the existing read-only N-PHY/BCM2056 register snapshot and 4096-sample hardware IQ estimator.

A new `nphy_calstate` node is deliberately software-only. It reads b43's already-allocated `struct b43_phy_n` state and reports cached 2.4/5 GHz RX-IQ coefficients, IQ/RSSI calibration chanspecs, chain state and calibration-policy fields. It contains no `b43_phy_read`, `b43_radio_read`, PHY/radio write, MMIO access, IQ estimator call, RX-IQ calibration call, RF override or tone/playback operation.

The target helper reads `nphy_calstate` first. If it fails, the helper stops before channel/IQ sampling. If it succeeds, the known-safe v1.14.24 `nphy_rxdiag` sweep runs normally.

## Interpretation

- `nphy_calstate_rc != 0`: the software-state debugfs path itself is implicated; do not perform active calibration.
- `nphy_calstate_rc = 0` and restored IQ sweep fails: investigate the hardware-register/IQ path independently, noting that the same path passed on v1.14.24.
- Both pass, IQ energy is present, `rx_iq_cal_rev3plus_implemented=0`, RSSI chanspec is populated, current-band IQ chanspec is zero, and cached RX-IQ coefficients are zero/default: this is strong evidence for a separately gated rev3–6 RX-IQ calibration implementation experiment.
- Both pass but IQ calibration/cache state is already populated: the missing rev3+ stub is not sufficient to explain zero decoded RX; remain read-only and compare downstream baseband state against stock `wl.ko`.

No active RX-IQ calibration is implemented or invoked by v1.14.26.
