# RV220W v1.11.5 persistent ELF DTB-injection hotfix

## Observed failure

The v1.11.4 persistent build reached `target/linux/install`, assembled all 133
root packages, generated a 4092.47 KiB SquashFS, copied and stripped
`vmlinux.elf`, and patched the kernel command line. The next step invoked the
Octeon-local helper:

```text
mips64-openwrt-linux-musl-objcopy --update-section \
  .appended_dtb=image-cn5010_cisco_rv220w.dtb \
  cisco_rv220w_persistent-kernel.bin
```

The command returned to the image recipe, but the temporary kernel no longer
existed. The following `cp` failed with `cannot stat`, aborting
`target/linux/install`.

## Cause

The Octeon target still carries the older `append-dtb-to-elf` helper, which only
runs `objcopy --update-section`. The regular non-initramfs kernel exposes the
reserved `.appended_dtb` area without file contents. Updating such a section
requires converting it to a content-bearing allocated section first.

OpenWrt v25.12.5 already provides the generic `append-dtb-elf` helper in
`include/image-commands.mk`. It applies:

```text
--set-section-flags=.appended_dtb=alloc,contents
--update-section .appended_dtb=<device DTB>
```

## Correction

Only `Device/cisco_rv220w_persistent` changes from:

```make
KERNEL := kernel-bin | strip-kernel | patch-cmdline | append-dtb-to-elf
```

to:

```make
KERNEL := kernel-bin | strip-kernel | patch-cmdline | append-dtb-elf
```

The persistent-writer profile is unchanged because its initramfs ELF already
built successfully. The flash map, command line, kernel size limit, component
writer, U-Boot policy and router state are unchanged.

## Rebuild scope

Run `platform install`, verify the source tree, and rebuild only `persistent`.
There is no need to rerun `prepare-sources` or rebuild `persistent-writer`.
