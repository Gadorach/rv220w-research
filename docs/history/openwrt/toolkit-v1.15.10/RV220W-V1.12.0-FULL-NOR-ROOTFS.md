# RV220W v1.12.0 full-NOR rootfs transition

## Why the layout changed

The rootfs-first hardware test proved that the non-initramfs kernel, SquashFS
root and JFFS2 persistence work. It also proved that OpenWrt automatically
creates `rootfs_data` inside a partition named `rootfs`. The previous layout
then exposed a second, explicit partition with the same name. The active
12 MiB overlay was the automatic child; the explicit 8.375 MiB tail was unused.

The stock 1 MiB Cisco JFFS2 area contains no OpenWrt dependency and is already
preserved in full-flash backups. v1.12.0 therefore uses every erase block between
the 6 MiB kernel partition and the final U-Boot environment as one rootfs.

## Safety boundary

The v1.12.0 updater performs no build and no router operation. The persistent
and writer images must both be rebuilt. Only the rebuilt writer understands the
25.375 MiB rootfs geometry and the new confirmation token.

The writer:

- accepts writes only to `openwrt-kernel` and `rootfs`;
- verifies exact partition sizes and 128 KiB erase geometry;
- refuses operation if an MTD filesystem is mounted;
- makes a mandatory full-region backup before every write;
- verifies the complete local image and complete NOR readback with SHA-256;
- never runs `saveenv`, changes `bootcmd`, reboots or writes the boot chain.

## Transition sequence

1. Upgrade the toolkit and install/verify platform v1.6.0.
2. Rebuild `persistent` and `persistent-writer`.
3. RAM-boot the new writer.
4. Run `persistent-stage status`; require:

```text
writable_partitions=openwrt-kernel,rootfs
rootfs_size=26607616
protected=boot-chain,uboot-env
reclaimed=stock-data,legacy-env-gap,vendor-tail
```

5. Run `persistent-stage backup` and retain its path and hashes.
6. Write the full rootfs using the exact token:

```fish
./rv220w.fish persistent-stage write-rootfs \
    --confirm RV220W_WRITE_FULL_OPENWRT_ROOTFS
```

7. TFTP-boot the rebuilt persistent ELF.
8. Confirm the expected map and one automatic overlay:

```sh
cat /proc/cmdline
cat /proc/mtd
mount
block info
df -h / /rom /overlay
```

9. Create a hostname and marker, reboot, interrupt U-Boot and repeat the TFTP
   persistent-kernel boot. Confirm both survive.
10. Stop for review before `write-kernel` or any U-Boot environment change.

## Expected data loss

The full rootfs write intentionally clears the existing test overlay and the
obsolete Cisco JFFS2 data partition. The complete original NOR dumps and the
new full-region prewrite backup provide rollback evidence.
