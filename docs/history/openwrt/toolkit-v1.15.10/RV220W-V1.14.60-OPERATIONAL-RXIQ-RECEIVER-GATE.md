# RV220W v1.14.60 — operational retained-calibration receiver gate

## Qualified predecessor

v1.14.59 hardware-qualified the complete retained-state transaction on CA channel 8. The transaction reached natural `primary_rc=0`, cleanup rc/mask `0/0x00000000`, retained IQ `(0,4,0,5)`, retained mirrored RCCAL `RX_LPC/RX_HPC/TX_LPC = 140/138/138`, `retained_state_verified=1`, and intentional `rollback_verified=0`. No association, stations, or persistent writes were observed.

## Operational boundary

v1.14.60 opens exactly one explicit `--rxiq-calibration` command on CA channel 8. This is not the retired rev<3 `nphy_rxiq_cal` implementation. The command reuses the hardware-qualified `integration:retain` transaction and then observes the calibrated receiver without transmitting user traffic.

The sequence is:

```text
qualified integration:retain calibration
        ↓
retain A0/B0/A1/B1 + six RCCAL registers
        ↓
monitor interface remains UP on 2447 MHz / channel 8
        ↓
8 seconds passive receive-only observation
        ↓
require RX packet counter increase and captured 802.11 frames
require unassociated state and zero stations
        ↓
read-only verify:retained
        ↓
MAC suspend → read IQ/RCCAL → compare → MAC resume
        ↓
PASS and monitor-interface teardown
```

## `verify:retained`

`verify:retained` performs no calibration and writes no calibration values. It is accepted only after a successful retained-state transaction. It briefly suspends the MAC, reads A0/B0/A1/B1 plus RX_LPC/RX_HPC/TX_LPC for both BCM2056 cores, compares them with that run's retained candidates/derived commit, then resumes the MAC.

The operational gate fails closed if the passive receiver sees no packets or tcpdump frames, if association/stations appear, if the retained IQ tuple drifts, if any RCCAL register drifts, or if post-RX MAC suspend/resume verification fails.

## Safety boundary

The only intended RF transmit activity remains the already-qualified internal calibration stimulus. Scan and probe requests, association, AP mode, frame injection, user-data TX, automatic startup calibration, calibration persistence, SPROM/OTP programming, NVM writes, and NOR writes remain blocked. The image and test are RAM-only.

## Hardware command

```fish
./rv220w.fish collect-wifi \
    --rxiq-calibration \
    --country CA \
    --channel 8 \
    --ack-rf \
    --ack-calibration \
    rxiq-operational-calibration-ch8-v11460
```

A PASS requires the underlying retained-state transaction to succeed naturally, passive receive activity to be observed, the interface to remain unassociated with zero stations, and `verify:retained` to confirm the live IQ/RCCAL state after receiver activity.
