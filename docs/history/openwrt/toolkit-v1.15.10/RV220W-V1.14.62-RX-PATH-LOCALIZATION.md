# RV220W v1.14.62 — operational RX-path localization

## Qualified predecessor

v1.14.61 completed retained RX-IQ/RCCAL calibration normally and ran a real eight-second background-tcpdump observation on CA channel 8. The capture runner itself passed, association/stations stayed zero, yet both the interface RX counter and tcpdump frame count stayed zero.

## Boundary

v1.14.62 does not enable any deeper WLAN operation. It repeats the same explicit RAM-only retained-calibration + passive-monitor receive experiment and instruments only the already-existing receive path.

The diagnostic records cumulative counters at:

1. generic b43 device interrupt entry;
2. DMA0 `B43_DMAIRQ_RX_DONE`;
3. dispatch to `b43_pio_rx()` (PIO is the qualified transfer mode on this target);
4. PIO `FRAMERDY` observed;
5. PIO `DATARDY` observed;
6. RX header accepted after length/FCS checks;
7. `b43_rx()` entry and b43 decode/drop outcome; and
8. delivery to mac80211.

PIO timeout, aggregate error, length-error and FCS-rejection counters are also exported. Capabilities expose current generic/DMA0 interrupt mask/reason values, MACCTL, `mac_suspended`, driver operating/interface/filter state, and PIO RX revision/base/RXCTL.

The final delivery counter is a dedicated RV220W diagnostic counter rather than b43's ordinary `dev->rx_count`, because upstream periodically resets `dev->rx_count` for its statistics report and it cannot safely serve as a cumulative observation-window counter.

During only the observation window the helper raises b43 verbose logging and captures `PIO RX timed out` / `PIO RX error:` messages as corroborating evidence, restoring the previous verbosity afterward.

## Independent retained-state verification

`verify:retained` runs after every completed receive window, including zero-RX outcomes. It remains read-only: MAC suspend, read A0/B0/A1/B1 and six RCCAL registers, compare with the retained candidates, MAC resume. A receive-path localization result is useful only after retained calibration is independently shown stable.

## Expected localization

With zero monitor frames the analyzer can distinguish:

- `rxiq-operational-rx-no-device-interrupts`;
- `rxiq-operational-rx-no-dma0-rx-done`;
- `rxiq-operational-rx-done-not-dispatched-to-pio`;
- `rxiq-operational-rx-pio-no-frame-ready`;
- `rxiq-operational-rx-pio-data-timeout`;
- `rxiq-operational-rx-pio-no-data-ready`;
- `rxiq-operational-rx-pio-length-error`;
- `rxiq-operational-rx-pio-fcs-rejected`;
- `rxiq-operational-rx-pio-header-not-accepted`;
- `rxiq-operational-rx-pio-frame-error`;
- `rxiq-operational-rx-pio-frame-not-handed-to-b43`;
- `rxiq-operational-rx-b43-frame-decode-drop`;
- `rxiq-operational-rx-b43-no-mac80211-delivery`; or
- `rxiq-operational-rx-mac80211-monitor-delivery-gap`.

A strong PASS still requires RX packet growth, captured monitor frames, zero association/stations, stable retained IQ/RCCAL, and every existing safety gate.

No scan/probe request, association, AP, user-data TX, frame injection, automatic startup calibration, or persistent/NVM/NOR write is permitted.
