# RV220W v1.8.2 B53 conduit-register diagnostics

## Evidence promoted from run 6

The v1.8.0 image creates both CPU conduits and reports the intended software affinity, but WAN traffic is asymmetric on `wan@eth1`:

- Octeon `eth1` transmits into BCM53115 CPU port 5.
- BCM53115 CPU port 5 never transmits back toward `eth1`.
- Reassigning WAN to `eth0`/CPU port 8 and reopening the port allows ARP, ordinary ICMP and 1500-byte IPv4 traffic.
- Reassigning WAN to `eth1` and reopening it restores 1000/full carrier but does not restore forwarding.

Therefore v1.8.2 is deliberately diagnostic. It does not change DTS timing, B53 forwarding code, Octeon patches or network policy.

## New tooling

`collect-conduit` retrieves a normal DSA snapshot and a selector-only B53 register snapshot under one label:

```fish
./rv220w.fish collect-conduit run7-eth1-failed --force-upload
```

The B53 report now records and evaluates:

- port 0, port 5 and port 8 control registers;
- port-based VLAN membership masks;
- PVID, GMII override and RGMII control values;
- switch mode and Broadcom-header controls;
- the live Linux WAN conduit;
- whether port 0 contains the expected CPU-port bit;
- whether the expected CPU port contains port 0.

Only pseudo-PHY selector registers `0x10` and `0x11` are written. Switch data registers are read only.

`compare-b53` compares two captured reports and decodes VLAN-mask bits as switch-port numbers:

```fish
./rv220w.fish compare-b53 FAILED_ETH1_REPORT WORKING_ETH0_REPORT     --output ~/src/rv220w-openwrt/logs/dsa/run7-b53-conduit-diff.txt
```

## Controlled capture sequence

Start in the current failed `wan@eth1` state:

```fish
./rv220w.fish collect-conduit run7-eth1-failed --force-upload
```

Then reproduce the known-working state on the router:

```sh
ifdown wan
ip link set dev wan type dsa master eth0 ||     ip link set dev wan type dsa conduit eth0
ifup wan
sleep 5
ip -d link show dev wan
```

Confirm host traffic before capturing the comparison state:

```fish
sudo ip addr replace 192.168.241.1/24 dev enp0s31f6
sudo ip neigh flush dev enp0s31f6
ping -I enp0s31f6 -c 10 192.168.241.2
ping -I enp0s31f6 -M do -s 1472 -c 10 192.168.241.2
./rv220w.fish collect-conduit run7-eth0-working --force-upload
```

Compare the two generated `rv220w-b53-*.txt` files. The next kernel revision must be based on the measured port-0/5/8 differences. Do not test `txid` or plain RGMII; carrier and bidirectional full-MTU traffic through CPU port 8 already rule out external PHY and WAN-port timing failures.

## Future rebuild behavior

The read-only B53 helper is also included in the dual-conduit root filesystem. A rebuild is not required for the immediate comparison because `collect-b53` can upload the packaged helper over UART.
