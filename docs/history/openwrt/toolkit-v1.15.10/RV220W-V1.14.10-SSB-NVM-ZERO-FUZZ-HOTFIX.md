# RV220W v1.14.10 — zero-fuzz SSB NVM diagnostic hotfix

## Hardware result that triggered this release

The v1.14.9 `wifi-discovery` build advanced beyond kernel patch preparation and reached compilation of `drivers/ssb/pci.o`. GCC then reported the new diagnostic functions as having an invalid storage class **inside `ssb_pci_block_write()`**, followed by non-constant `DEVICE_ATTR_RO` initializers and misplaced `pdev`/`err` diagnostics in the exit/init paths.

That pattern proves the patch was syntactically applied but its hunks were placed in the wrong C scopes.

## Cause

The v1.14.9 repair split the diagnostic change into narrow hunks with only one context line. GNU `patch` may apply such a hunk with fuzz. With fuzz level 1, that sole context line can be ignored, leaving the approximate source line as the effective placement hint. OpenWrt's prepared Linux 6.12.94 source had sufficient line drift for the hunk to be accepted at the wrong location.

The v1.14.9 offline regression reproduced line drift but did not pass `--fuzz=0` and verified only that expected tokens existed after patching. It therefore missed incorrect function scope.

## v1.14.10 correction

`993-ssb-pci-nvmem-diagnostics.patch` is regenerated as one multi-line semantic hunk covering the existing `ssb_sprom` sysfs tail, `ssb_pci_exit()` and `ssb_pci_init()`.

The new regression:

- invokes GNU `patch` with `--fuzz=0`;
- inserts 72 unrelated lines before the relevant Linux 6.12 source tail and requires clean relocation by context;
- requires diagnostics to appear after `DEVICE_ATTR_ADMIN_RW(ssb_sprom)` and before `ssb_pci_exit()`;
- requires `ssb_pci_block_write()` to be closed and brace-balanced before any diagnostic function;
- requires `int err` only in `ssb_pci_init()`, not `ssb_pci_exit()`;
- requires diagnostic sysfs removal only in the exit path and creation/error unwinding in the init path;
- rejects any return of the v1.14.9 one-context-line hunk form.

## Safety boundary

This hotfix changes no OTP/SPROM extraction algorithm and adds no write path. The WLAN profile remains RAM-only and RF-disabled. Platform v1.7.5, persistent images, NOR layout, DSA integration and sysupgrade remain unchanged.
