# RV220W v1.14.11 — non-binding SSB PCI OTP diagnostic module

## Why the architecture changed

v1.14.8-v1.14.10 attempted to add read-only OTP sysfs attributes directly to Linux `drivers/ssb/pci.c`. The hardware build logs showed two different integration failures: a fuzzy hunk could land in the wrong C scope, while the stricter zero-fuzz replacement correctly refused to apply against OpenWrt's prepared source. The read-only OTP operation does not require modification of the SSB core driver, so v1.14.11 removes that patch entirely.

## Module model

`ssb_nvmem_diag.ko` is an ordinary out-of-tree kernel module packaged as `kmod-ssb-nvmem-diag` only in the RAM `wifi-discovery` image. It does **not** call `pci_register_driver()` and therefore does not bind to or replace the existing SSB/b43 owner. At module load it enumerates existing PCI devices, maps BAR0 bytes `0x3000..0x3fff`, validates the SSB IDHIGH core/vendor fields as Broadcom ChipCommon, validates supported IPX OTP geometry, and adds two read-only PCI-device attributes:

- `ssb_otp_info`
- `ssb_otp_raw`

The module never changes the movable SSB BAR0 core window. Physical SPROM evidence comes from Linux's pre-existing `ssb_sprom` attribute, whose PCI implementation calls the normal physical `sprom_do_read()` path.

## Write-safety boundary

The module contains no PCI-config writes, no MMIO writes, no OTP INIT/programming sequence, no SPROM write, and no RF operation. `status_fresh=0` remains explicit because the Broadcom OTP INIT command is intentionally not issued.

## Portability

There are no RV220W, Cisco, BCM4322, PCI-ID, board-MAC, or board-calibration constants in the module. Compatibility is discovered from BAR geometry and the ChipCommon SSB identity. Unsupported layouts return no diagnostic attributes rather than being guessed.

## Remaining gate

A successful target build and RAM boot must show the module loading and expose the two OTP attributes. The collector then combines those with existing `ssb_sprom`, and the host analyzer may emit an OpenWrt fallback blob only if the geometry-defined 220-word candidate satisfies both Linux stored-CRC and Broadcom full-image residue validation. RF remains disabled.
