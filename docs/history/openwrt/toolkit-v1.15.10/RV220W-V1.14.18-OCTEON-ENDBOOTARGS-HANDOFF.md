# RV220W v1.14.18 — Octeon `endbootargs` WLAN identity handoff

## Hardware result from v1.14.17

The v1.14.17 TFTP helper correctly read the protected platform MAC from
`0xbdc6ff00`, derived the stock WLAN identity as base + 4, and emitted a
`bootoctlinux` command containing both custom arguments. The captured U-Boot
trace showed:

```text
md.b 0xbdc6ff00 6
bdc6ff00: a4 93 4c b1 42 a6
bootoctlinux 0x05500000 console=ttyS0,115200 rv220w.wlan_mac=a4:93:4c:b1:42:aa rv220w.b43_pio=0
argv[2]: console=ttyS0,115200
argv[3]: rv220w.wlan_mac=a4:93:4c:b1:42:aa
argv[4]: rv220w.b43_pio=0
```

Linux then reported a kernel command line containing neither custom token.
Consequently `/proc/cmdline`, the preinit marker and b43's module MAC remained
empty. The protected flash read and MAC derivation were therefore correct; the
failure was the Cavium boot-option/kernel-argument boundary.

## Fix

Cavium `bootoctlinux` reserves arguments before `endbootargs` for bootloader
options and treats arguments after it as Linux application/kernel arguments.
For the wifi-discovery profile v1.14.18 therefore emits:

```text
bootoctlinux 0x05500000 endbootargs console=ttyS0,115200 \
  rv220w.wlan_mac=a4:93:4c:b1:42:aa rv220w.b43_pio=0
```

The change is deliberately scoped to `--derive-stock-wlan-mac`, which is only
enabled by the RAM-only wifi/wifi-discovery wrapper. Existing persistent/NOR
boot command generation is unchanged.

The host rejects user-supplied `endbootargs` in the bootargs string so the
marker location remains controlled by the helper.

## New handoff verification

During boot capture, the helper now inspects Linux's early:

```text
Kernel command line: ...
```

and requires both:

```text
rv220w.wlan_mac=<derived base+4>
rv220w.b43_pio=0
```

If Linux reaches the command-line print without either token, `tftp-boot`
fails immediately with an Octeon handoff error instead of allowing a later
`collect-wifi --apply-stock-mac` failure to be the first indication.

## Unchanged downstream path

The OpenWrt preinit hook remains unchanged: it validates `/proc/cmdline` and
writes RAM-only `options b43 pio=0 macaddr=<base+4>` into `/etc/modules.conf`
before the normal first b43 probe. No unload/reload, SSB unbind/rebind, flash
write, SPROM write, scan, association or AP operation is introduced.

Native physical-SPROM calibration qualification from v1.14.14 also remains
unchanged.
