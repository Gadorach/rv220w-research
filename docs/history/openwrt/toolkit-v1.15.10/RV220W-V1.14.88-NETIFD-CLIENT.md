# RV220W v1.14.88 — OpenWrt UCI/netifd station integration

## Basis

v1.14.87 qualified the full direct userspace Wi-Fi client path through Internet and DNS on native b43 DMA. v1.14.88 changes the ownership model, not the radio stack: normal OpenWrt `wifi`/netifd must create and manage the station and DHCP interface from UCI.

## Test

The hot helper backs up `/etc/config/network` and `/etc/config/wireless`, verifies no MTD-backed root/rom/overlay is mounted, disables/removes any existing temporary WLAN interfaces, then creates one temporary `wifi-iface` and `network.wwan` with `proto=dhcp`, `defaultroute=0`, `peerdns=0`. Credentials arrive on SSH stdin and are never printed.

The helper calls `ubus call network reload` and `wifi up`; it does **not** directly invoke `wpa_supplicant` or `udhcpc`. Qualification requires netifd `wwan` up, WPA association, a DHCP IPv4 address, a real station entry, native DMA, b43 TX/IRQ progress and no Wi-Fi default route.

Finally it runs `wifi down`, restores both UCI files exactly, reloads netifd, leaves the radio disabled, verifies the pre/post SHA-256 values match and removes the private backups.

## Command

```fish
./rv220w.fish collect-wifi \
    --netifd-client \
    --ssid VertexHotspot \
    --country CA \
    --ack-rf \
    --ack-calibration \
    --ack-tx \
    --ack-association \
    --ack-l3 \
    --ack-netifd \
    netifd-client-dma-v11488
```

The command prompts for the WPA-PSK. No OpenWrt rebuild is required; run `wifi-hot-deploy` first.
