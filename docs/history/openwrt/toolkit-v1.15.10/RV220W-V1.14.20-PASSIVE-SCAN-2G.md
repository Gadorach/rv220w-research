# RV220W v1.14.20 — constrained 2.4 GHz passive receive gate

## Hardware prerequisites now qualified

v1.14.19 hardware proved all prerequisites for a receive-only test. b43 reads the stock identity directly from the read-only `boot-chain` MTD source and uses `a4:93:4c:b1:42:aa` from the first probe. The explicit receiver-init then loaded firmware 666.2, reached status 2/STARTED, selected 64-bit DMA, enabled QoS, retained N-PHY rev4/radio 0x2056 rev3, and showed no b43 error. The temporary interface remained unassociated and the evidence recorded zero scan, association, AP and user-TX requests.

## Scope

v1.14.20 enables exactly one additional operation:

```text
iw dev rvwscan0 scan flush freq 2412 2417 2422 2427 2432 2437 2442 2447 2452 2457 2462 passive
```

The gate is restricted to regulatory country `CA` and 2.4 GHz channels 1-11. The `passive` token causes iw to omit `NL80211_ATTR_SCAN_SSIDS`; nl80211 defines absence of that attribute as passive scanning, so no probe request is requested. `flush` removes stale BSS cache entries before the scan.

## Qualification requirements

The host analyzer requires:

- MTD source `boot-chain`, offset 458496, increment 4 and PIO 0;
- initialized permanent and scan-interface MAC equal the independently derived base+4 value;
- country CA;
- explicit passive scan mode, zero SSIDs and zero requested probe requests;
- exactly channels 1-11 requested;
- successful/non-aborted scan;
- at least one BSS received;
- every captured BSS frequency within the requested 2.4 GHz set;
- b43 status 2 and radio_on=1;
- `iw link` reports not connected after scan and station dump is empty;
- no requested association, AP or user data transmission;
- no b43 error indication.

## Still blocked

5 GHz and DFS scanning, active/wildcard probe scans, authentication, association, AP mode, hostapd/wpa_supplicant, normal data traffic and persistent WLAN configuration remain out of scope.
