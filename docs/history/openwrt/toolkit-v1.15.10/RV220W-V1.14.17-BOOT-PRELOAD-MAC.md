# RV220W v1.14.17 — boot-time stock WLAN MAC preload

## Hardware evidence leading to this change

v1.14.16 booted the already-qualified physical-SPROM/b43 path normally, but its first `apply-stock-mac` operation returned failure after beginning the live SSB rebind. A second attempt reported that no b43-bound SSB WLAN core could be found, showing that the first failure left the device unbound. Receiver-init then correctly refused to run because b43 still had no stock base+4 identity.

## Replacement architecture

Runtime identity mutation is retired. The wifi-discovery TFTP helper performs exactly one additional U-Boot memory-read command:

```
md.b 0xbdc6ff00 6
```

This reads the six protected platform-MAC bytes at NOR offset `0x6ff00`. The host validates the result as a unicast MAC, derives the stock WLAN identity as the 48-bit value plus four, and appends only RAM boot arguments:

```
rv220w.wlan_mac=<base+4> rv220w.b43_pio=0
```

No `saveenv`, flash erase/program, `mw`, `cp`, SPROM write, or RF command is used.

A wifi-discovery-only OpenWrt preinit hook runs before normal module loading. It validates the boot arguments and writes this RAM-only line to `/etc/modules.conf`:

```
options b43 pio=0 macaddr=<base+4>
```

The existing b43 `macaddr` parameter is read-only again. b43 therefore receives the stock identity during its first probe rather than through unload/reload or unbind/rebind.

## Gates

`apply-stock-mac` is retained for workflow compatibility but is verification-only. It requires agreement among the protected-flash-derived base+4 MAC, `rv220w.wlan_mac` bootarg, preinit marker, b43 module parameter and b43 first-probe log. It performs no RF action.

`reload-dma` and `reload-pio` are retired in v1.14.17. `receiver-init` remains a separate `--ack-rf` operation and passive scan remains blocked pending hardware qualification.
