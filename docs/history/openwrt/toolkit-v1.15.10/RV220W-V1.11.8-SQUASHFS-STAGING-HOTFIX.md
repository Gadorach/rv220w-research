# RV220W v1.11.8 SquashFS staging hotfix

## Observed failure

The v1.11.7 build successfully completed all OpenWrt compilation and image-generation work. It exported a 0x51b63b-byte gzip kernel, recovered the 0xc345d0-byte non-initramfs ELF for TFTP validation and created a valid approximately 4 MiB SquashFS.

The toolkit then called its fallback `mksquashfs` helper inside Bash command substitution. `mksquashfs` writes progress and its filesystem summary to stdout. Bash therefore assigned the full multi-line report plus the final output pathname to the `rootfs` variable. The subsequent `cp "$rootfs" ...` failed because that multi-line value was not a pathname.

## Correction

`find_or_make_squashfs` now checks in this order:

1. A named SquashFS image exported under `bin/targets/octeon/generic`.
2. The exact `build_dir/.../linux-octeon_generic/root.squashfs` generated by OpenWrt.
3. A guarded fallback repack from `root-octeon`.

The fallback writes stdout and stderr to `logs/rv220w-rootfs-mksquashfs.log`, mirrors that log to stderr, verifies the resulting image is nonempty and prints only its pathname to stdout. This preserves command-substitution safety.

No target source integration, kernel pipeline, package set, DTS, NOR geometry or router-side writer behavior changes in v1.11.8.
