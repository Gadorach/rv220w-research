# RV220W v1.14.64 — b43 backports-6.18.26 patch-context hotfix

## Failure being corrected

The v1.14.63 regression-suite updater completed, but the subsequent wifi-discovery build failed while OpenWrt 25.12.5 applied the RV220W b43 patch to `mac80211-regular/backports-6.18.26`.

Four receive-localization hunks were context-fragile: one interrupt telemetry insertion in `main.c`, two PIO FRAMERDY telemetry insertions in `pio.c`, and the b43 receive-entry telemetry insertion in `xmit.c`. The remaining b43 patch sections applied.

## v1.14.64 change

The source-code payload is unchanged. Regression tests require the current and exact v1.14.63 predecessor patches to contain identical added and removed code lines in identical order.

Only the four failed hunk contexts are narrowed to stable local anchors:

- `main.c`: insert immediately before the unused DMA-ring block;
- `pio.c`: insert immediately before the PIO8 FRAMERDY acknowledge write;
- `pio.c`: insert immediately before the legacy PIO FRAMERDY acknowledge write;
- `xmit.c`: insert immediately before `memset(&status, 0, sizeof(status))` in `b43_rx()`.

This keeps IRQ, DMA0 RX_DONE, PIO dispatch/FRAMERDY/DATARDY/header/error, b43 entry/drop and mac80211-delivery telemetry semantics unchanged.

## Qualification boundary

The next hardware operation remains the same passive CA/channel-8 RX-localization run after retained calibration. Scan/probe requests, association, AP operation, user-data TX, frame injection, automatic startup calibration and persistent calibration remain blocked.
