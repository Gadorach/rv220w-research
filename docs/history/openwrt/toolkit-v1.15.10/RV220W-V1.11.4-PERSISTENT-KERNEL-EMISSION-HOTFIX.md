# RV220W v1.11.4 persistent-kernel emission hotfix

## Observed failure

The v1.11.3 persistent build completed kernel compilation, package assembly and
creation of a 4.0 MiB SquashFS root filesystem. OpenWrt then finished `world`
without producing the expected per-device non-initramfs kernel in `bin/targets`.
The host staging step consequently stopped with:

```text
non-initramfs kernel artifact not found for device: cisco_rv220w_persistent
```

## Cause

The persistent device declared a `KERNEL` pipeline but also declared no regular
firmware images. OpenWrt's image framework only adds the per-device kernel copy
to the install target when `KERNEL_INSTALL` is nonempty. The initramfs writer was
unaffected because its initramfs target follows a separate path.

## Correction

The persistent profile now includes:

```make
KERNEL_INSTALL := 1
KERNEL_SIZE := 6m
```

`KERNEL_INSTALL` emits the non-initramfs ELF as
`openwrt-octeon-generic-cisco_rv220w_persistent-kernel.bin`; `KERNEL_SIZE` also
causes OpenWrt to reject a kernel that exceeds the 6 MiB NOR partition. Existing
v1.5.0 source trees are repaired semantically by `platform install`; no re-clone
or feed refresh is required.

No flash layout, DTS, rootfs contents, writer image or router state changes.
