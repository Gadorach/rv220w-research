# RV220W v1.14.73 active-scan evidence transport hotfix

## Hardware evidence driving this release

The v1.14.72 composite run requalified the known-good receive path before TX: CA channel 8 / 2447 MHz, retained calibration and post-RX verification passed, IRQ109/CIU36 remained active, and 367 receive events traversed b43 IRQ, DMA0, PIO, header decode and mac80211 with zero b43 drops or PIO/length/FCS errors.

The subsequent active-scan evidence file, however, was exactly zero bytes. Its v1 analyzer therefore reported every field missing and selected `active-scan-no-b43-tx-status`. That finding is invalid as a TX diagnosis because there was no captured target output from which to establish whether cfg80211 scanning was ever reached.

## Root cause in the evidence path

`collect-wifi.fish` redirected only SSH stdout to the active-scan artifact. Target stderr remained outside the saved evidence. `rv220w-wifi-probe active-scan-ch8` also had multiple pre-output commands under `set -e` (regulatory setup, managed-interface creation/up and other gates). A failure before the first stdout record could therefore leave a zero-byte artifact while the host still ran the active-scan analyzer.

## v1.14.73 changes

- Capture active-scan SSH stdout and stderr separately, then append target stderr plus SSH return-code/byte-count metadata to the finalized evidence file.
- Emit target `active_scan_probe_revision`, preflight, regulatory, managed-interface and scan-start markers.
- Convert `iw reg set`, managed-interface creation and interface-up into explicit return-code gates so these failures cannot disappear through implicit `set -e` termination.
- Advance the active-scan analyzer to schema v2 with separate `active-scan-evidence-empty`, `active-scan-target-preflight-failed`, `active-scan-command-failed`, genuine `active-scan-no-b43-tx-status`, and existing downstream classifications.
- Preserve the real v1.14.72 zero-byte artifact as a regression fixture; it must classify as `active-scan-evidence-empty`, never as a b43 TX failure.

## Unchanged boundaries

No kernel, b43, N-PHY/BCM2056 calibration, PCI INT0/CIU36 routing, TX command, scan frequency, association/authentication/AP policy, arbitrary injection, persistence, NVM or NOR logic changes. The active experiment remains one explicitly acknowledged cfg80211 wildcard scan on CA channel 8 after a same-boot retained-calibration/passive-RX PASS.
