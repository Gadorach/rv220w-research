# RV220W v1.14.29 — RX-IQ `phy_n.c` patch-placement hotfix

v1.14.28 did not reach compilation or hardware. The parallel build reported `package/kernel/mac80211` failure and the serial fallback proved that every preceding b43 hunk applied, but the single reconstruction hunk for `drivers/net/wireless/broadcom/b43/phy_n.c` rejected at its nominal line 5407.

The RX-IQ reconstruction itself is unchanged in v1.14.29. The 257 nonblank added implementation lines are regression-compared with the exact preserved v1.14.28 patch.

## Placement correction

v1.14.28 inserted the diagnostic immediately after `b43_nphy_rev3_cal_rx_iq()` and unnecessarily carried downstream CalRxIq text as patch context. v1.14.29 relocates the diagnostic implementation to immediately before the unique exported N-PHY operations table:

```c
const struct b43_phy_operations b43_phyops_n = {
```

All required static helpers are defined earlier in `phy_n.c`, so this location is C-equivalent for the externally declared diagnostic entry points while avoiding the brittle calibration-area text. OpenWrt's `830-b43-workaround-pcie-bcm4716.patch` modifies N-PHY MMIO accessor bodies and does not change the operations-table symbol.

The new regression extracts the actual `phy_n.c` hunk, applies it with GNU `patch` to a post-830 proxy containing `b43_wflush16()` accessor changes and deliberately incompatible rev3 calibration-area text, and requires the reconstruction to land before `b43_phyops_n`.

## Scope

No RX-IQ algorithm, runtime gate, acknowledgement, MAC-suspend, cleanup, observation, or rollback behavior changes from v1.14.28. Normal b43 rev3+ calibration remains untouched. This release only makes the already-reviewed experiment apply to the OpenWrt/backports source reliably.
