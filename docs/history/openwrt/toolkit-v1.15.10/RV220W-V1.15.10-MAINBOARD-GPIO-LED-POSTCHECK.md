# RV220W v1.15.10 mainboard GPIO LED postcheck correction

## Hardware-model correction

The RV220W front-panel POWER, DIAG, WIRELESS and DMZ indicators are mainboard LEDs driven from Octeon GPIO2, GPIO3, GPIO4 and GPIO6 respectively. They are exposed through the board DTS as `gpio-leds` class devices:

- `rv220w:green:power`
- `rv220w:red:diag`
- `rv220w:green:wlan`
- `rv220w:green:dmz`

The BCM4322/b43 device has no physical front-panel LED wired to its own LED outputs. mac80211 trigger names such as `phy0rx`, `phy0tx`, `phy0assoc` and `phy0radio` are therefore optional software event sources for a mainboard LED, not evidence that the LED mapping exists.

## Why `phy0tpt` is not a qualification gate

The V1158 hardware run proved that all four RV220W GPIO LED class entries exist while Wi-Fi is operational. The WLAN LED trigger list was:

```text
none timer heartbeat default-on [netdev] network phy0rx phy0tx phy0assoc phy0radio
```

The selected `[netdev]` state is also compatible with preserved LuCI/UCI LED configuration. Production sysupgrade intentionally preserves overlay configuration, so a post-reboot test cannot use the currently selected trigger to infer the DTS default.

Accordingly v1.15.10 makes trigger contents diagnostic-only. The read-only production postcheck requires each of the four board LED class directories plus readable/writable `brightness` and `trigger` controls. GPIO5 remains forbidden because hardware survey showed it affects the Ethernet LED/control domain.

Static built-kernel verification still requires the four exact RV220W LED labels and the `gpio-leds` marker, but no longer requires a `phy0tpt` string. Deep SquashFS verification reports whether `ledtrig-network.ko` is present but does not require it for front-panel LED qualification.

## Image lineage

This is a host/tooling policy correction only. The already-built and already-flashed V1158 production image remains current. Its package composition is retained for reproducibility and its confirmation tokens remain:

```text
RV220W_SYSUPGRADE_PRODUCTION_V1158
RV220W_V1158_SYSUPGRADE_DISPATCHED
RV220W_BOOTED_PRODUCTION_SYSUPGRADE_V1158
```

Do not rebuild or reflash merely for v1.15.10. Upgrade the toolkit and rerun `verify`, `persistent-wifi-stage ssh-check`, and the read-only V1158 `production-postcheck`.
