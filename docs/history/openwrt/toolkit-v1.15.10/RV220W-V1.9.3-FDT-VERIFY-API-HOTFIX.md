# RV220W v1.9.3 FDT verification API hotfix

## Failure

Toolkit v1.9.2 repaired the patch-999 context and the patch applied, but Linux
6.12.94 then failed while compiling `arch/mips/cavium-octeon/setup.c`:

```text
error: too few arguments to function 'early_init_dt_verify'
```

The kernel declaration is:

```c
bool early_init_dt_verify(void *dt_virt, phys_addr_t dt_phys);
```

The v1.9.2 patch supplied only `initial_boot_params`.

## Correction

Patch 999 now refreshes the post-fixup FDT CRC with both addresses:

```c
if (!early_init_dt_verify(initial_boot_params,
                          __pa(initial_boot_params)))
        panic("Corrupt Device Tree after Octeon fixups.");
```

Octeon selects appended, built-in, or firmware-provided FDTs as ordinary kernel
virtual pointers. For a firmware-provided FDT it first maps the physical pointer
with `phys_to_virt()`. `__pa(initial_boot_params)` therefore preserves the
physical address associated with the same flat tree while the helper refreshes
`initial_boot_params_pa` and the stored FDT CRC.

## Scope

No DTS, B53, DSA, VLAN, firewall, package, NOR partition, or RAM-boot policy is
changed. The explicit Octeon BootBus flash compatible and stable patch context
from v1.9.2 remain unchanged.

## Regression protection

The new test applies patch 999 to an OpenWrt-shaped Linux fixture and compiles a
minimal translation unit with the Linux 6.12 two-argument declaration. This
would fail for the exact one-argument call shipped in v1.9.2.
