# RV220W v1.14.3 b43 OpenWrt patch-order hotfix

## Failure observed

The first real `wifi-discovery` build reached `package/kernel/mac80211` preparation and rejected hunk #1 of `998-b43-rv220w-platform-capabilities.patch`. Hunks #2/#3 in `main.c` and all `debugfs` hunks applied, so this was a source-context/order failure rather than a package-selection or target-hardware failure.

OpenWrt v25.12.5 applies its b43 patch 815 before the RV220W patch. Patch 815 changes `modparam_allhwsupport` to `1`. The v1.14.2 RV220W first hunk used the pre-815 `modparam_allhwsupport` assignment as trailing context even though the insertion itself only needs the preceding `pio` module-parameter block.

## Correction

v1.14.3 retargets that hunk to the actual post-815 source state, `static int modparam_allhwsupport = 1;`. The added `b43.macaddr=` parameter is unchanged. A regression now applies the first RV220W hunk to a synthetic post-815 source fragment and verifies that it succeeds while retaining the OpenWrt value.

The platform installer also recognizes the exact SHA-256 of the v1.14.2 staged WLAN patch and replaces only that known predecessor; arbitrary differing patch files remain refused. The stale build-pass metadata string is also corrected from toolkit `1.13.3` to `1.14.3`.

## Safety and qualification boundary

Platform v1.7.5 and the hardware-qualified persistent boot/sysupgrade/DSA/NOR files remain unchanged. This hotfix only advances the RAM-only WLAN build gate. Do not flash a persistent image. After a successful compile, TFTP boot `wifi-discovery` and collect the initial read-only WLAN evidence before running any passive RF scan.
