# RV220W v1.14.83 — managed association daemon-preflight hotfix

## Hardware result motivating this revision

v1.14.82 built and RAM-booted successfully, but its first association test exited before creating a managed interface. The sole target stderr was `managed-assoc blocked: a wireless userspace daemon is already running.` Native DMA, authentication, association and RF behavior were therefore not exercised by that run.

## Cause and correction

The v1.14.82 preflight treated any `wpa_supplicant` or `hostapd` PID as a conflicting radio owner. With the OpenWrt supplicant package present, an interface-less global control daemon may legitimately be running even though all UCI radios are disabled. v1.14.83 forces `wifi down`, records daemon PIDs and the `iw dev` interface inventory, permits global-only daemons when no wireless netdev exists, and still blocks if any wireless interface remains.

The private WPA-PSK test instance remains a separate per-interface `wpa_supplicant`. Cleanup now verifies that private PID has stopped; a pre-existing global control daemon may remain alive and no longer causes a false teardown failure.

## Boundaries

No kernel patch, DMA setting, calibration implementation or credential transport changes. The test remains RAM-only, WPA-PSK association only, with no DHCP, AP mode, arbitrary injection, persistent UCI network configuration, NVM or NOR write.
