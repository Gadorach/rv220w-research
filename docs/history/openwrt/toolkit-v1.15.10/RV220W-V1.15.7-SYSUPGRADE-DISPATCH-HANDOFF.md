# RV220W v1.15.7 — production sysupgrade stage2 handoff

The v1.15.6 production sysupgrade completed successfully on hardware. Preflight passed, the target emitted the guarded dispatch marker, and OpenWrt reached:

```text
upgrade: Commencing upgrade. Closing all shell sessions.
```

while stage2 took over. During that teardown `ubus call system sysupgrade` reported `Connection failed`, and the remote command propagated status 246. v1.15.6 accepted only status 0 or 255 and therefore reported a false host-side failure even though the router subsequently booted the production image normally with working Wi-Fi and configurable front-panel LEDs.

v1.15.7 is no-build/no-flash. It adds a fail-closed dispatch classifier:

- the exact RV220W dispatch marker is mandatory;
- status 255 is accepted only if the OpenWrt stage2 `Commencing upgrade` line was observed;
- the hardware-observed status 246 is accepted only if stage2 was observed **and** the ubus `Connection failed` signature is present;
- arbitrary nonzero statuses remain failures;
- missing dispatch/stage2 evidence remains a failure.

The destructive confirmation token remains `RV220W_SYSUPGRADE_PRODUCTION_V1151` intentionally. It is the retained production-image acknowledgement token, not the toolkit revision, and changing it in a host-only hotfix would make the acknowledgement imply new image bytes that do not exist.

## Next hardware run

Do not sysupgrade again merely to test this host-side fix. Upgrade the toolkit, then run the read-only production gate against the already booted router:

```fish
cd ~/src/rv220w-research/rv220w-research/promotion-toolkit

./rv220w.fish persistent-wifi-stage ssh-check

./rv220w.fish persistent-wifi-stage production-postcheck \
    --confirm RV220W_BOOTED_PRODUCTION_SYSUPGRADE_V1151
```

If the management address is not the configured default, add `--host root@<LAN-IP>` to both commands.
