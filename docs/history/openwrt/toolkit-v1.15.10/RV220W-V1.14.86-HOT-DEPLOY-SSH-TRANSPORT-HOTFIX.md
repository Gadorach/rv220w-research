# RV220W v1.14.86 — hot-deploy SSH transport hotfix

## Failure

The first v1.14.85 hot-deploy stopped before helper installation:

```text
ash: /usr/libexec/sftp-server: not found
Connection closed
[rv220w:error] SFTP helper upload failed.
```

The target is the deliberately minimal RAM-only OpenWrt/Dropbear image and does not include OpenSSH's SFTP server. Modern OpenSSH transfer clients may use SFTP by default. The toolkit had already encountered and solved this exact compatibility issue in v1.4.1 and v1.10.2.

## Correction

`wifi-hot-deploy` no longer requires or invokes SFTP. It uses the established byte-exact path:

```text
local rv220w-wifi-probe
    -> cat
    -> ssh -T
    -> /tmp/rv220w-wifi-probe.hot.partial.<pid>
    -> target SHA-256 comparison
    -> chmod 755
    -> atomic mv to /tmp/rv220w-wifi-probe.hot
    -> version/SHA marker
    -> independent remote SHA/version readback
```

Fish `$pipestatus` is checked for both `cat` and `ssh`. A failed transfer removes the private partial. Ephemeral RAM-image host keys continue to use null known-hosts files.

## Build policy

No OpenWrt, kernel, b43, DT, initramfs package or target-helper bytes changed. This is host-only and remains **NO BUILD REQUIRED**. A still-running compatible v1.14.84/v1.14.85 RAM image can be reused immediately.

## Commands

```fish
./rv220w.fish wifi-hot-deploy

./rv220w.fish collect-wifi \
    --managed-l3 \

    --country CA \
    --ack-rf \

```

The managed-L3 scope remains unchanged: WPA-PSK association, private `udhcpc` lease, interface-bound ping to the first DHCP router, no default route, no DNS/Internet test, and no UCI/NVM/NOR write.
