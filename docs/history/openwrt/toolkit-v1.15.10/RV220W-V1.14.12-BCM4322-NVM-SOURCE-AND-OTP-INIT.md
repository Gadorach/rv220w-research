# RV220W v1.14.12 — BCM4322 NVM source selection and OTP shadow INIT

## Hardware result that motivated this release

v1.14.11 successfully built `kmod-ssb-nvmem-diag` with the real OpenWrt MIPS64 toolchain, RAM-booted, and autoloaded without displacing SSB/b43. Passive capture found a ccrev23 IPX OTP geometry of 384 words (`otpgu_base=20`, `hwbase=24`) but the 220-word hardware SROM candidate was all zero and `status_fresh=0`. The independent external `ssb_sprom` capture remained rev8 with an invalid CRC.

## Stock-source decision

Broadcom BCM4322 defines ChipCommon `chipstatus[7:6]` as the SPROM/OTP source selector: 0 = neither, 1 = external SPROM, 2 = OTP, 3 = reserved. v1.14.12 exposes `chipstatus`, `bcm4322_sprom_otp_sel` and `bcm4322_stock_source` passively. This datum is evaluated before any OTP controller command is considered.

## Explicit INIT-only follow-up

Broadcom's IPX OTP initialization sequence issues `OTPPOC_INIT` before reading OTP status/shadow. v1.14.12 exposes that operation only through a separate write-only `ssb_otp_control` attribute accepting exactly `init-shadow`. It is not used by normal collection.

The kernel refuses the command unless all of these are true:

- ChipCommon identifies BCM4322;
- `chipstatus[7:6] == 2` (OTP selected by the stock hardware strap);
- OTP already reports `READY`; the diagnostic does not manipulate PMU OTP power;
- `OTPC_PROGEN` is clear;
- `otpprog` is not busy.

The implementation contains one MMIO write: the `START_BUSY + INIT` command to `otpprog`. It does not implement BIT_PROG, SET, RESET, ROW_LOCK, OTP-control writes, SPROM writes, PCI-config writes, RF initialization or flash writes.

The target helper independently checks the same selector/source and READY state, records pre-INIT info/raw OTP, performs the exact command, then records post-INIT info/raw OTP. Host collection compares both captures and runs the existing geometry/CRC analyzer on each. A fallback blob is emitted only when the geometry-defined post-INIT candidate passes both the Linux stored-CRC convention and Broadcom full-image residue gate. CRC validity still does not imply RF qualification.

## Operator sequence

1. Build and RAM-boot `wifi-discovery`.
2. Run ordinary `collect-wifi otp-source-selector`.
3. If source is `sprom`, do not issue INIT; investigate the external-SPROM stock path.
4. If source is `otp` and READY=1, the same RAM boot may run `collect-wifi --otp-init-shadow otp-init-shadow`.
5. Review pre/post OTP evidence before any firmware/RF activation.
