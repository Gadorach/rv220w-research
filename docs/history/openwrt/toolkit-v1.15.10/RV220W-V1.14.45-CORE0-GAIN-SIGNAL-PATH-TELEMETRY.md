# RV220W v1.14.45 — core0 gain signal-path telemetry

## Hardware result that motivates this revision

v1.14.44 cross-built and RAM-booted successfully. Its point-6 `core0-gain` run reached the intended tone/gain-search scope, but returned `-EIO` before the injected cancellation. The added telemetry removed two major ambiguities:

- signed TX power index 20 was applied successfully;
- `b43_nphy_tx_tone()` returned success;
- IQEST completed (`IQEST_CMD=0`, START not stuck);
- the first gain-search iteration was row 3 with packed RX gain `0x003c`;
- every raw IQ estimator accumulator on both receive cores was exactly zero.

The previously tracked rollback surface still restored cleanly (`cleanup_rc=0`, cleanup mask zero, MAC suspend/resume verified, IQ before/after equal), but point 6 remains **not qualified** because the requested injected cancellation was never reached.

## v1.14.45 scope

v1.14.45 does not alter the rev4 gain-search algorithm and does not advance beyond point 6. It repeats the same core0 internal calibration-tone/gain-search path and still blocks the following dedicated RX-IQ coefficient-calculation tone/calc, core1 processing, RCCAL, scan, association, AP operation, frame injection, user-data TX, cache/chanspec persistence, NVM and flash writes.

The only kernel changes are read-only telemetry captured while the MAC is already suspended by the diagnostic transaction.

### Sample-playback / classifier state

The point-6 result now records classifier state before the tone, immediately after `b43_nphy_tx_tone()`, and after IQEST. It also records the sample engine command/status/depth/loop/wait registers plus RF sequence status/mode after the tone call.

The most important discriminator is `SAMP_STAT` bit 0: upstream b43's own stop-playback path treats that bit as the normal sample-playback-active indicator. A zero bit immediately after a successful tone-helper return therefore identifies a playback/control-path problem rather than an IQEST arithmetic problem.

### TX gain path

For the selected signed TX index, telemetry records the live 32-bit per-core TX gain-table word and decodes the same radio-gain, DAC-gain and bbmult fields used by the staged signed-index helper. It then reads back the live AFE override, DAC gain, RFSEQ gain and bbmult word after tone startup.

No TX gain value is changed by the telemetry.

### Loopback route

For core0 RX, the rev4/pre-rev7 path uses the opposite TX core. v1.14.45 reads back the BCM2056 `RXIQCAL_TXMUX`, `RXIQCAL_RXMUX`, and LNA-tune register selected by the already-existing radio setup, plus the relevant N-PHY RFSEQ/RFCTL/AFECTL registers. The staged radio helper still writes `0x0006` to the TX and RX calibration mux registers exactly as before.

## Analyzer findings

For a point-6 zero-power result the host analyzer can now classify:

- `core0-gain-sample-playback-not-running`
- `core0-gain-tx-gain-programming-mismatch`
- `core0-gain-loopback-route-mismatch`
- `core0-gain-estimator-zero-with-playback-active`

The existing timeout, raw-zero, rounded-zero, and general gain-control classifications remain available for older evidence and fallback cases.

## Qualification rule

Point 6 remains unqualified until the gain-search helper completes and the transaction reaches the explicit point-6 injected `-ECANCELED` return with exact rollback verification. v1.14.45 is therefore a diagnostic revision, not an expansion to `core0-IQ`.
