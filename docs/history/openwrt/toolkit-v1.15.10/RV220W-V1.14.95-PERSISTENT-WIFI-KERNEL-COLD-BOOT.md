# RV220W v1.14.95 — persistent Wi-Fi candidate kernel promotion

## Hardware basis

v1.14.94 returned `boot_check=PASS` with the candidate rootfs in NOR and candidate kernel in RAM: profile `wifi-client-persistent`, `/rom=squashfs`, `/overlay=jffs2`, `/=overlay`, b43 `pio=0`, BCM4322 IRQ109, all radios disabled, no `wifi-iface`, no wireless netdevs, interface-less global supplicant only, and LAN up.

## Write boundary

`persistent-wifi-stage write-kernel` is the only new destructive action. It first verifies the candidate manifest/rootfs/sysupgrade, proves the candidate rootfs is still present in NOR, creates a fresh backup of both persistent partitions, then writes only the 6 MiB padded candidate kernel. Exact kernel readback and unchanged candidate-rootfs readback are mandatory. Boot-chain and U-Boot env remain protected.

## Final boot gate

After the write, power-cycle normally and let the already-qualified saved `openwrt_boot` environment load/gunzip/boot the NOR kernel. Do not use TFTP for this boot. Then run:

```fish
./rv220w.fish persistent-wifi-stage cold-boot-check \
    --confirm RV220W_COLD_BOOTED_WIFI_CANDIDATE_FROM_NOR_V11495
```

The runtime validator still requires the same v1.14.94 invariants. BCM4322 on IRQ109 is independent runtime evidence that the candidate PCI-routing correction is active.
