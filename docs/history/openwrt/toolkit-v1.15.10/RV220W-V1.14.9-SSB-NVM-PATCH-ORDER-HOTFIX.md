# RV220W v1.14.9 — SSB NVM diagnostic patch-order hotfix

## Build observation

The first v1.14.8 `wifi-discovery` build reached OpenWrt target-kernel preparation, then failed before compilation while applying the temporary `993-rv220w-ssb-pci-nvmem-diagnostics.patch`.

The serial fallback showed:

```text
patching file drivers/ssb/pci.c
Hunk #1 FAILED at 1046.
Hunk #2 succeeded at 1156 (offset 72 lines).
1 out of 2 hunks FAILED
```

No diagnostic kernel code was compiled and no router operation was attempted.

## Cause

The original first hunk spanned the closing lines of `ssb_pci_ops` and the later `ssb_sprom_show()` declaration. That unnecessarily coupled a large 194-line insertion to source text on both sides of the insertion point.

OpenWrt's prepared Linux 6.12.94 source did not preserve that exact multi-line context, although the later SPROM sysfs init/exit hunk remained recognizable.

## v1.14.9 correction

The diagnostic block is inserted at the existing:

```c
static DEVICE_ATTR_ADMIN_RW(ssb_sprom);
```

sysfs boundary. This is the subsystem interface the new read-only attributes extend and is a more appropriate semantic anchor.

The functional diagnostic code is unchanged.

## Regression

`tests/test_v1149_ssb_nvm_patch_order.py` constructs a source fragment with deliberate unrelated line drift before the SPROM sysfs section, applies the shipped patch with GNU `patch`, and requires the three new read-only attributes plus init/exit cleanup to be present.

The test also verifies the hardware-qualified persistent core hashes.

## Safety

v1.14.9 remains RAM-only for WLAN. It does not enable RF, initialize/program OTP, write SPROM, inject a MAC, alter PCI configuration, or change platform v1.7.5.
