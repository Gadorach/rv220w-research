# RV220W v1.14.1 stock `wl.ko` to b43 capability crosswalk

## Scope

This stage compares the preserved RV220W Broadcom `wl.ko` with the current
Linux `b43`/SSB path and adds only capabilities that are both platform-relevant
and implementable without copying proprietary algorithms.

The source module was preserved separately and is not redistributed by this
toolkit. Its audited identity is:

```text
size:     5222416 bytes
sha256:   59097fc90ef2af55ce22000c7cd4ee0567bebae8ea6243963539008c6307ad0d
version:  Broadcom 5.60.120.9
vermagic: 2.6.21.7-Cavium-Octeon mod_unload OCTEON 64BIT
```

The machine-readable inventory and generated report are under
`docs/analysis/`. Regenerate them with:

```sh
./tools/wifi/audit_stock_wl.py /path/to/wl.ko \
  --json /tmp/rv220w-wl.json \
  --markdown /tmp/rv220w-wl.md
```

## Stock-driver evidence

The proprietary module exports a broad, unstripped feature surface. Symbol
families include N-PHY/HT-PHY initialization, AMPDU, MIMO/spatial-stream and
antenna selection, PHY/radio calibration, TSSI and transmit-power control,
noise/interference handling, radar/DFS, MBSS/BSSCFG, WDS, WME/QoS and
TKIP/AES/WPA code.

Its module parameters are:

```text
name:string
nompc:int
macaddr:charp
instance_base:int
piomode:int
oneonly:int
```

The stock `/etc/userInit` path derives the wireless MAC from the platform base
MAC and loads `wl.ko` with an explicit `macaddr=` value. This is the one clear
RV220W platform contract that current b43 does not expose directly. The stock
`piomode` control already has a b43 equivalent named `pio`; the remaining stock
parameters are vendor instance/interface/power-policy controls rather than
missing BCM4322 hardware algorithms.

## Responsibility crosswalk

| Stock capability evidence | Modern owner | v1.14.1 disposition |
|---|---|---|
| explicit `macaddr=` module parameter | b43 platform attachment | **Added** as a read-only-at-runtime b43 module parameter; invalid or non-unicast addresses fail probe. |
| `piomode=` | b43 DMA/PIO selection | Already represented by b43 `pio`; discovery profile still defaults to DMA and retains PIO fallback. |
| PCI/SSB/SPROM identity and board flags | SSB + b43 | **Exposed** through a new read-only b43 `capabilities` debugfs file and captured by the RV220W collector. |
| PHY/radio revision, 2/5 GHz support, radio and power-control state | b43 | **Exposed** read-only for first-hardware qualification. |
| AP/STA/IBSS/mesh interface behavior | mac80211/cfg80211 + hostapd/wpa_supplicant | Not a b43 patch. The first image intentionally excludes AP/supplicant packages and disables the radio. |
| multiple SSIDs, VLAN binding, WPA/802.1X policy | hostapd/netifd/userspace | Deferred until basic radio operation is proven. |
| WDS management | mac80211/hostapd/userspace plus peer compatibility | Deferred; no vendor ioctl compatibility layer is added. |
| WME/QoS and hardware crypto | mac80211 + b43 | Existing b43 state is reported; no vendor control ABI is copied. |
| N-PHY calibration, TSSI and antenna algorithms | b43 N-PHY implementation + SPROM data | Existing open implementation is used. First gate is exact SPROM/PHY evidence, not vendor code transplantation. |
| radar/DFS | cfg80211 regulatory + driver radar support | No parity claim. The first profile must not transmit; 5 GHz/DFS remains a later, separately gated stage. |
| AMPDU, HT rates and 40 MHz operation | b43/mac80211 | **Not implemented.** Upstream b43 documents no support for 802.11n HT, aggregation or 40 MHz width. Stock symbol presence is insufficient to reconstruct this safely. |

## Kernel patch

`openwrt/wifi/998-b43-rv220w-platform-capabilities.patch` is installed into the
OpenWrt mac80211 `patches/brcm` stack. It adds:

1. `b43.macaddr=xx:xx:xx:xx:xx:xx`, preserving the existing SPROM
   `et1mac`/`il0mac` fallback when unset;
2. `/sys/kernel/debug/b43/<phy>/capabilities`, mode `0400`, containing board,
   chip, core, SPROM, transfer-engine, QoS, crypto, radio and PHY state;
3. no transmit operation, ioctl compatibility layer or SPROM write path.

The override is deliberately **not enabled automatically** in v1.14.1. The
first snapshot must compare the b43 SPROM permanent address with the stock
platform-derived address before selecting a permanent policy.

## Validation boundary

Completed here:

- proprietary module metadata and symbol-family inventory;
- source-level responsibility crosswalk;
- nested-patch structural validation;
- installer placement and exact-byte verification;
- collector integration and static regressions.

Still required on the user's OpenWrt build tree and router:

```fish
./rv220w.fish platform install
./rv220w.fish platform verify
./rv220w.fish build wifi-discovery
```

- OpenWrt mac80211 package compile against the pinned v25.12.5 tree;
- TFTP/initramfs boot;
- PCI, SSB, SPROM and `capabilities` capture;
- comparison of SPROM MAC versus stock base-MAC-plus-four behavior;
- only then, a separately authorized radio-enable and association test.

No v1.14.1 result should be described as HT/802.11n parity with the stock
driver.
