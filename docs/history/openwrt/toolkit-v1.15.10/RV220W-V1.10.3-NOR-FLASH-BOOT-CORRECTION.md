# RV220W v1.10.3 NOR flash boot correction

## Hardware result

The v1.10.2 host transport successfully wrote the complete 22 MiB
`openwrt-slot` and the target-side full read-back matched SHA-256:

```text
51340539fff729869bab36181662e36648768663c9774e5f98646d4283bc86a5
```

The subsequent command:

```text
bootoct 0xbdc80000 forceboot
```

did not boot Linux. U-Boot identified it as an Octeon Executive application and
failed while creating a read-only TLB mapping:

```text
ERROR CREATING TLB MAPPING (read only)
ERROR: Unable to properly load application
```

This does not indicate a failed NOR write. `bootoct` is the wrong loader for the
staged Linux ELF.

## Correct launch model

The proven TFTP path first places the ELF in ordinary RAM at `0x05500000` and
then invokes `bootoctlinux`. NOR boot must reproduce that model:

1. Read the exact ELF byte count from memory-mapped NOR at `0xbdc80000`.
2. Copy those bytes to RAM at `0x05500000`.
3. Invoke `bootoctlinux` on the RAM copy.

For the validated LuCI image:

```text
source_size decimal: 18179536
source_size hex:     0x11565d0
NOR source:          0xbdc80000
RAM destination:     0x05500000
RAM end:             0x066565cf
```

Commands:

```text
cp.b 0xbdc80000 0x05500000 0x11565d0
bootoctlinux 0x05500000 console=ttyS0,115200
```

Enter the commands separately during the first test. Do not use `saveenv`.

## Toolkit changes

`build_rv220w_nor_slot.py` now records:

- the RAM staging address;
- exact decimal and hexadecimal ELF copy length;
- the two-command U-Boot sequence;
- `direct_flash_bootoct_supported=false`.

`./rv220w.fish nor-stage boot-plan` derives the commands from the existing
manifest. Old v1.10.0 manifests remain usable because they already contain
`source_size` and the correct NOR source address.

After a successful write, the host and target writer now state that direct
`bootoct` is invalid and print or reference the NOR-to-RAM sequence.

## Scope

This correction changes no kernel, DTS, OpenWrt target, partition map, writer
binary, written slot image, or protected NOR region. The already programmed
payload remains valid and does not need to be rewritten.
