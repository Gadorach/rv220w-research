# RV220W v1.13.7 configuration-preservation marker

## Hardware observation

Both command-line and LuCI upgrades accepted the standard image, saved the
configuration archive, erased and verified rootfs, wrote and verified the kernel
last, and rebooted normally. The saved hostname and explicit UCI marker were not
restored. The stage2 log did not contain the `mtd` JFFS2 append message.

## Cause

The RV220W runtime intentionally trims the tar `root` member to SquashFS
`bytes_used`. That exact file has no JFFS2 end marker. `mtd -j` only inserts its
archive when the write stream reaches `de ad c0 de` at the beginning of an erase
block, so supplying `-j` alone was insufficient.

## Platform v1.7.5 behavior

When `UPGRADE_BACKUP` is nonempty, stage2 performs all of these checks before
erasing NOR:

- exact RV220W board, archive and MTD-layout validation;
- nonempty backup file, successful `gzip -t`, successful nonempty `tar tzf`;
- conservative space check for the backup and JFFS2 overhead;
- temporary root image equal to the exact SquashFS, zero padded to the next
  128 KiB erase boundary, followed by `de ad c0 de`;
- marker offset, alignment, output size and marker-byte validation.

It then erases the complete rootfs region and writes the temporary image using
`mtd -j`. The exact raw SquashFS is used for prefix verification. Stage2 dumps
four bytes at the insertion offset and requires JFFS2 magic before proceeding to
the kernel. A missing, corrupt, empty or oversized backup aborts before erase; a
marker that was not replaced aborts before the kernel write.

The no-backup path continues to write the exact raw SquashFS. Neither path can
write `boot-chain` or `uboot-env`.

## Hardware test gate

Use a distinctive hostname and UCI token, then run normal `sysupgrade -v` or
LuCI with **Keep settings** selected. The UART log must include:

```text
RV220W configuration backup validated; JFFS2 insertion marker is at rootfs offset ...
Integrating the preserved configuration into the new JFFS2 rootfs_data area...
Appending jffs2 data from ...
RV220W preserved configuration was embedded in rootfs_data.
```

After reboot, verify the hostname, UCI token, JFFS2 overlay, platform v1.7.5
hash and fixed MTD map. Package binaries installed only into the old overlay are
not expected to survive unless included in the rebuilt image or reinstalled;
this qualification concerns standard OpenWrt configuration backup restoration.
