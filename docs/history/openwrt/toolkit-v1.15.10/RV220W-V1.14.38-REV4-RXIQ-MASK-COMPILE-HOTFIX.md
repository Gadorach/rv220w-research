# RV220W v1.14.38 rev4 RX-IQ mask compile hotfix

v1.14.37-r1 successfully passed package/platform installation and reached the
actual OpenWrt/backports b43 compilation step. The serial fallback identified a
single compiler failure in `rv220w_rxiq_rev4_run_transaction()`:

```
b43_phy_mask(dev, B43_NPHY_BBCFG, ~B43_NPHY_BBCFG_RSTRX);
```

`b43_phy_mask()` accepts a 16-bit mask. In the expression above the bitwise
complement is integer-promoted, producing signed `int` value `-32769` for the
`0x8000` RSTRX bit. The OpenWrt/backports build uses warnings-as-errors and
therefore rejects the implicit conversion to `u16` with `-Werror=overflow`.

v1.14.38 changes only this source expression in the rev4 outer transaction:

```
b43_phy_mask(dev, B43_NPHY_BBCFG,
             (u16)~B43_NPHY_BBCFG_RSTRX);
```

This preserves the intended low-16-bit mask (`0x7fff`) while making the
narrowing explicit. The exact v1.14.37-r1 b43 patch is retained as a protected
fixture and its SHA-256 is allowlisted as the only new WLAN predecessor for
platform replacement.

The full stock-order rev4 outer transaction, rollback/fault-injection scaffold,
v1.14.36 helper family, and hash-pinned rev<3/rev2-family reference are otherwise
unchanged. Active RX-IQ calibration remains blocked at host, target, and kernel
gates. v1.14.38 remains a compile/boot qualification checkpoint; there is no
active RF calibration command for this release.
