# RV220W v1.14.67 — Octeon diagnostic package Makefile tab hotfix

## Failure

The v1.14.66 parallel build isolated the failure to `package/kernel/octeon-pci-irq-diag`. The serial fallback reached the package after successfully compiling mac80211 and stopped immediately with:

```text
Makefile:36: *** missing separator.  Stop.
```

The package recipe lines generated for `Build/Prepare` and `Build/Compile` contained the literal two-byte sequence `\\t` rather than an ASCII tab (`0x09`). GNU make therefore did not recognize them as recipe lines. No `octeon_pci_irq_diag.c` compilation occurred.

Broken package Makefile SHA-256:

```text
9f1d720cc187a8fddba14edacd5f8390d593ab46ae13d90deaf39bea4b2fca42
```

Corrected package Makefile SHA-256:

```text
469ce01b24bdba0f5df1d5288ced92d8b11c937ac39d99bc84c1222d521cf614
```

## Change

Only recipe indentation in `openwrt/wifi/octeon-pci-irq-diag/Makefile` changes. The v1.14.66 CIU diagnostic C source, probe/analyzer policy, b43 patch, RF/calibration logic, safety gates, and IRQ-routing behavior are unchanged.

`tests/test_v11467_octeon_package_makefile_tabs.py` inspects raw Makefile bytes and requires real recipe tabs while rejecting the exact literal `\\t` prefixes that caused the v1.14.66 failure.

## Hardware boundary

This remains the v1.14.66 read-only CIU discriminator. After a successful build, run the same RAM-only CA/channel-8 retained-calibration observation. Do not manually change PCI/CIU/SSB routing.
