# RV220W v1.14.79 — channel-8 pre-TX retained-state gate

## Hardware result that motivates this revision

v1.14.78 proved that userspace cannot establish a durable managed channel-8 context before interface activation. `iw dev rvwact0 set freq 2447` returned success while the managed vif was DOWN and the held monitor/b43 remained on channel 8, but `ip link set rvwact0 up` still moved the shared b43 PHY to channel 1. No scan or probe transmission was reached.

The passive prerequisite remained qualified, and the active-side `integration:retain` transaction plus its first `verify:retained` completed successfully before managed-vif activation. Therefore the unresolved boundary is not calibration itself; it is proving that those retained coefficients are still present after mac80211 performs the scan's own channel-1 -> channel-8 switch.

## v1.14.79 design

v1.14.79 moves the final proof to the b43 channel configuration path instead of trying another userspace ordering workaround.

After a fresh retained calibration and generation-backed verification, the target helper creates and starts the single managed station vif. It then explicitly writes `active-scan:arm` to the existing RV220W RX-IQ debugfs control. Arming is accepted only when the BCM4322 is STARTED, N-PHY rev4/BCM2056r3 is active, PIO is selected, a real station vif is operating, the full retained transaction reached fault point 15, retained/integration state is valid, and a non-zero prior retained-verification generation exists.

The arm is one-shot. The first subsequent b43 configuration of channel 8 consumes it. `b43_op_config()` has already suspended the MAC and called `b43_switch_channel()` at that point. Before returning success to mac80211, the gate reads the live A0/B0/A1/B1 IQ compensation and all six RCCAL registers through the already-qualified read-only retained verifier and compares them with the retained candidates. A mismatch or failed prerequisite returns an error from `b43_op_config()`; userspace therefore treats the scan as blocked and no channel-8 probe request is qualified to proceed.

On success, the gate records its attempt generation, channel, IQ tuple, RCCAL readback and rc, then allows the normal cfg80211 wildcard scan to continue. The host analyzer requires a fresh one-shot attempt, successful verification on channel 8, matching IQ tuple, normal scan completion, advancing b43 TX status, channel-8 BSS results, host IRQ activity, and an unassociated zero-station post-state.

## Safety boundary

This revision does not add arbitrary frame injection, association, authentication, AP mode, user-data transmission, persistent calibration, NVM writes or NOR writes. The only TX-bearing request remains the explicitly acknowledged one-channel cfg80211 wildcard active scan on CA channel 8.

The hardware-qualified 993 and 998 patches and the compiled 999 verification-generation patch remain unchanged. v1.14.79 adds a separate post-999 patch containing only the one-shot scan gate and its telemetry.
