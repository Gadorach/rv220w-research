# RV220W v1.15.0 guided U-Boot GPIO survey

The stock RV220W U-Boot contains a recovered `gpio` command with syntax:

```text
gpio r gpio_number
gpio w gpio_number value
```

The reconstruction also exposes the Octeon GPIO per-pin `BIT_CFGX` CSR at physical I/O base `0x1070000000800 + 8*gpio`, and U-Boot provides `read64`/`write64`. The toolkit therefore uses both surfaces so it can restore pin direction/mux configuration rather than merely restoring the observed level.

Run with the router already stopped at the stock `rv200w#` prompt:

```fish
./rv220w.fish uboot-gpio-survey --port /dev/ttyUSB0
```

Default range is GPIO0 through GPIO10. Inputs are skipped by default, because front-panel LEDs should already be output lines and arbitrary input GPIOs may be buttons or strap signals. GPIO1 is known reset/recovery and is skipped explicitly. The known GPIO4 WLAN LED is annotated as active-low.

For each output pin the tool:

1. snapshots `BIT_CFGX` and `gpio r` level;
2. prints the starting level/direction;
3. drives HIGH and asks for an observation;
4. drives LOW and asks for an observation;
5. restores the original latch level and exact `BIT_CFGX` value;
6. verifies the configuration register restored exactly;
7. records the observations to JSON.

Ctrl+C during a pin restores the current pin before exiting and writes partial results.

`--include-inputs` exists for deliberate investigation but is not recommended. `--include-sensitive` is additionally required to touch known-sensitive GPIO1.
