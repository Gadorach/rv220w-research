# RV220W v1.3.2 repaired-baseline changes

## Purpose

Version 1.3.2 is deliberately narrow. It combines two independently proven behaviors:

- v1.3.1 UART: explicit `clock-frequency = <400000000>` on `uart0`.
- v1.3.0 MTD: BootBus enabled with the inherited `nor@0,0` child enabled.

The v1.3.1 assumption that the BootBus parent alone would trigger Octeon legacy flash registration was disproven on hardware: `/proc/mtd` was empty. The v1.3.2 profile therefore accepts the redundant failed generic physmap probe because the same enabled child also triggers the correct `phys_mapped_flash` registration from U-Boot's live CS0 register.

## Supplied candidate

A DTB-repacked RAM-boot candidate is included. It retains all v1.3.1 kernel/initramfs sections and changes only the appended DTB. Before merging, the tool asserts that the actual v1.3.0 and v1.3.1 DTBs differ only in the NOR child and UART clock. The resulting DTB is semantically equal to v1.3.0 plus the 400 MHz UART setting.

Structural validation confirms:

- `.appended_dtb`: 3,688 to 3,804 bytes;
- `PT_LOAD.p_filesz`: extended by exactly 116 bytes;
- every other file-backed ELF section: byte-identical to v1.3.1;
- candidate TFTP source-buffer end: `0x063fb2a8`, below `0x07f00000`;
- input baseline hashes remained unchanged.

## Unchanged safety boundaries

- RAM-only initramfs profile; `IMAGES :=` remains empty.
- Seven NOR partitions remain command-line `ro` partitions.
- No `saveenv`, MTD write, erase, sysupgrade, reset-button activation, GPIO LED mapping, USB, or B53/DSA binding.
- Existing legacy Octeon Ethernet fallback remains unchanged.

## Validation state

Static checks, patch-structure checks, reference-DTB parsing, installer guards, synthetic platform upgrades, and candidate ELF structural checks are complete. A real OpenWrt build and RV220W RAM boot must still confirm UART, MTD, and Ethernet together. Until then, v1.3.1 remains the last hardware-proven ELF.
