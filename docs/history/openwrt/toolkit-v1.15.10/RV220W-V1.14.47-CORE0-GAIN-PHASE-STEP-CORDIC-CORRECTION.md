# RV220W v1.14.47 — core0 gain phase-step / CORDIC correction

## Why this revision exists

v1.14.46 proved that the target-scoped low-10-bit I/Q packer writes the N-PHY sample table, but it did not generate the intended rotating calibration tone. Hardware telemetry showed 160 non-zero words, all 160 with a non-zero I component, zero Q components, identical sample data (`sample0=OR=0x0002d400`, XOR zero), and an all-zero IQ estimator. Playback, TX gain and the BCM2056 loopback muxes still read back correctly.

The local v1.14.46 helper copied two assumptions from the generic b43 N-PHY sample generator that are unsuitable here. With `freq=2000` kHz and `bw=20` MHz, `(((freq * 36) / bw) << 16) / 100` equals `36 << 16`, which truncates to zero when stored in `u16 rot`. In addition, the Linux `cordic_calc_iq()` API accepts degrees and performs `CORDIC_FIXED()` internally; pre-applying `CORDIC_FIXED(angle)` double-scales the angle.

The Broadcom-derived brcmsmac tone generator uses the integer-degree relation `((f_kHz * 36) / phy_bw) / 100` and passes the angle directly to `cordic_calc_iq()`.

## v1.14.47 change

Only the RV220W rev4 point-6 diagnostic helper changes:

```c
s32 rot, angle = 0;
rot = ((freq * 36) / bw) / 100;
...
iq = cordic_calc_iq(angle);
angle += rot;
```

For the point-6 20 MHz / 2 kHz stimulus, the expected step is 36 degrees per sample. The 40 MHz / 4 kHz case has the same step. The v1.14.46 low-10-bit I/Q packing remains:

```c
pi = (u16)iq.i & 0x03ff;
pq = (u16)iq.q & 0x03ff;
data[i] = ((u32)pi << 10) | pq;
```

The generic b43 sample generator/loader remains untouched.

## Rollback and active boundary

The v1.14.46 320-word N-table17 snapshot/restore/verify is retained, as are exact IQEST CMD/SAMCNT/WT rollback, TX-power state rollback, RF/PHY loopback rollback, MAC suspend/resume verification and IQ before/after verification.

`core0-gain` / fault point 6 remains the deepest public boundary. The dedicated RX-IQ coefficient-calculation tone, `b43_nphy_calc_rx_iq_comp()`, core1, RCCAL, scan/association/AP/frame injection/user-data TX and persistent writes remain unreachable.

## Qualification interpretation

A useful v1.14.47 capture should first show a genuinely rotating waveform: 160 samples on 20 MHz, non-zero I and Q counts, and non-zero packed data. Point 6 is qualified only if gain control completes and the requested architecture-resolved cancellation is reached (`-158` on the MIPS target), followed by cleanup rc 0, cleanup mask 0, verified MAC suspend/resume and exact rollback.

If the waveform rotates correctly but IQEST remains all-zero, the remaining fault is downstream of sample generation and point 6 remains unqualified.
