# RV220W v1.14.2 BCM4322/b43 staged bring-up

## Merge basis

v1.14.2 starts from the hardware-qualified v1.13.7 core. The platform v1.7.5
sysupgrade implementation, persistent image configuration, DSA patches and
full-NOR image builder are deliberately unchanged. The v1.14.1 WLAN-only
branch deltas are layered on top.

The WLAN target is a Broadcom BCM4322 Mini PCI function (`14e4:432b`) using
Linux b43 over SSB and OpenWrt's stable b43 firmware selection. The preserved
stock `wl.ko` is reference evidence only; it is not included in this toolkit.

## Gate 0: build-time compatibility

`platform install` places the b43 patch under the OpenWrt mac80211 `patches/brcm`
stack. `build wifi-discovery` is the first real compatibility test against the
pinned OpenWrt tree. The output is RAM-only.

## Gate 1: zero-RF baseline

Boot the `wifi-discovery` image by TFTP and run:

```fish
./rv220w.fish collect-wifi initial-b43-probe
```

The target collector does not scan, associate or start an AP. It records:

- PCI `14e4:432b` identity and driver binding;
- SSB cores;
- readable `ssb_sprom` bytes and SHA-256;
- b43 module parameters and firmware inventory;
- b43 `capabilities` debugfs report;
- the six-byte platform base MAC at protected NOR offset `0x6ff00`;
- the stock expected WLAN MAC (`platform base + 4`);
- wiphy/interface state and relevant kernel messages.

The host collector automatically runs `scripts/analyze-wifi-snapshot.py` and
writes `.analysis.txt` and `.analysis.json` beside the evidence report.

Do not set `b43.macaddr` automatically. Compare the SPROM and b43 permanent
address with the stock expected address first.

## Gate 2: transfer-engine/MAC reload

These commands operate only in the RAM image, keep every UCI radio disabled,
and reload b43 without changing SSB, SPROM or NOR:

```fish
./rv220w.fish wifi-probe status
./rv220w.fish wifi-probe reload-dma
./rv220w.fish wifi-probe reload-pio
```

If the evidence proves the stock WLAN address should be used but SPROM does not
supply it, test it only in RAM first:

```fish
./rv220w.fish wifi-probe reload-dma --mac 00:11:22:33:44:55
```

An invalid, multicast, all-zero or all-FF address is refused.

## Gate 3: passive 2.4 GHz receive test

Only after Gate 1/2 show a healthy wiphy and firmware state:

```fish
./rv220w.fish wifi-probe passive-scan --country CA --ack-rf
```

Replace `CA` with the correct ISO alpha-2 country for the test location. The
helper creates a temporary station interface and asks `iw` for a **passive**
scan on 2412/2437/2462 MHz (channels 1/6/11), then removes the interface. No
probe SSID is supplied, and 5 GHz/DFS is not tested at this stage.

## Stop conditions

Stop before RF testing if any of these are absent or fail:

- PCI `14e4:432b`;
- SSB enumeration;
- b43 firmware load;
- b43 capability report;
- a wiphy/phy;
- credible SPROM/board identity.

If DMA attach shows transfer errors, capture the baseline before trying
`reload-pio`. If PIO materially changes the result, preserve both snapshots.

## Deferred until first hardware evidence

- AP mode and station association;
- WPA/WPA2/crypto testing;
- 5 GHz and DFS;
- permanent automatic MAC override;
- WLAN LED GPIO 4 ownership;
- persistent inclusion of wireless packages.

The stock driver symbol inventory is useful for responsibility mapping but is
not evidence that b43 has HT/AMPDU/40 MHz support.
