# RV220W v1.14.37 — rev4 RX-IQ outer transaction compile staging

## Release intent

v1.14.37 is the next guarded integration checkpoint after the successful v1.14.36 cross-build and RAM-boot smoke test. It does **not** enable active RX-IQ calibration. The host collector, target helper and kernel debugfs `run` gate all remain fail-closed before the new transaction can execute.

The objective of this revision is to compile the complete N-PHY rev4 / BCM2056 rev3 outer orchestration around the v1.14.36 helper family and to make every temporary state mutation converge on one rollback/verification path.

## Qualified predecessor

v1.14.36 established that the staged rev4 PHY/radio loopback helpers, signed TX-power-index handling, gain search and RCCAL sweep compile against the real OpenWrt/backports tree and do not regress boot/probe on the RV220W. v1.14.37 accepts the exact v1.14.36 WLAN patch hash as a known predecessor and does not alter the protected Ethernet, persistent-image or sysupgrade baseline.

## Target scope

The staged runner refuses anything outside the first known hardware case:

- N-PHY revision 4.
- BCM2056 radio revision 3.
- 2.4 GHz channels 1 through 11.
- Both RX cores already enabled (`RFSEQ RXEN == 0x3`).
- `nphy->phyrxchain == 0x3`.
- Non-IPA / external-PA path.

The requirement for both RX cores is intentional. The stock routine can temporarily expand a one-core state to two cores for RCCAL, but b43's existing RX-core setter performs its own MAC suspend/resume. The future diagnostic transaction will already execute under an outer MAC serialization boundary, so v1.14.37 refuses that case rather than nesting MAC state transitions.

## Stock-order transaction

The compile-staged runner now performs the source-mapped rev3+ sequence in the expected order:

1. Sample the live TX gains before disabling TPC.
2. Snapshot original RX-IQ coefficients, BBConfig, `deaf_count`, `hang_avoid`, the complete v1.14.36 TPC rollback state, and the final RCCAL commit registers.
3. Clear `BBConfig.RSTRX`, enter carrier search and disable `hang_avoid` for the transaction.
4. Disable TPC and install per-core RX-IQ calibration RFSEQ gains derived from the captured TX gains.
5. For RX core 0 and RX core 1, perform rev4 PHY setup and BCM2056r3 radio loopback setup.
6. For calibration type 0 or 2, run gain control, transmit the stock RX-cal tone, calculate per-core RX-IQ compensation, stop playback, and retain the observed coefficient tuple for diagnostics.
7. For calibration type 1 or 2, run the RCCAL gain-control/sweep stage on RX core 1 and return the measured candidate without letting the sweep implicitly persist it.
8. Reconstruct the stock non-IPA RCCAL commit formula for both cores.
9. Enter the single cleanup path and restore all transaction state, including the just-computed IQ tuple and RCCAL commit. v1.14.37 is therefore rollback-only even on successful completion.

## RCCAL commit model

For each core, the staged non-IPA commit computes:

- `RX_LPC = candidate | 0x80`
- `RX_HPC = clamp((((candidate - 12) >> 1) + 10), 0, 31) | 0x80`
- `TX_LPC = clamp(((candidate - 12) + 10), 0, 31) | 0x80`

The transaction snapshots both cores' RX LPC/HPC and TX LPC registers before calibration. The commit is applied only to prove the complete stock-order path can compile; cleanup then restores and verifies the original values.

## Fault-path staging

The runner contains explicit injected-failure points after carrier-search entry, TPC disable, RFSEQ calibration-gain installation, each core's PHY/radio/gain/IQ stages, RCCAL measurement, and final RCCAL commit. These are not externally selectable in v1.14.37. They exist so a later guarded test revision can execute each failure case without adding a second cleanup implementation.

The final verifier covers:

- Per-core radio setup restoration.
- Per-core PHY setup restoration.
- RCCAL commit registers.
- TPC software state, TPC PHY state, RFSEQ gains, bbmult, DAC state, and both 84-entry adjusted-power table images.
- RX-gain override release.
- Exact BBConfig restoration.
- Original RX-IQ coefficient tuple.
- Original `hang_avoid` value.
- Exact carrier-search/deaf nesting count.

Any rollback mismatch converts an otherwise successful transaction into `-EUCLEAN`.

## v1.14.37 qualification procedure

The useful qualification is a normal `wifi-discovery` cross-build followed by the same optional RAM-boot smoke test used for v1.14.36. There is **no active RX-IQ RF test in v1.14.37**. Do not invoke `collect-wifi --rxiq-calibration`; the host gate intentionally rejects it before connecting to the target.

If the build succeeds, the important evidence is that the full outer transaction compiles against the actual backports tree. If the optional TFTP boot also succeeds, confirm the normal BCM4322 N-PHY4 / BCM2056r3 probe and wired DSA path remain unchanged.

## Preserved legacy reference

The v1.14.28–v1.14.34 reconstructed active body remains hash-pinned under `research/legacy-revlt3-rxiq/`. Stock dispatch analysis identifies that body as the rev<3/rev2-family algorithm; it remains useful reference material for other hardware and is not deleted or rewritten by this revision.
