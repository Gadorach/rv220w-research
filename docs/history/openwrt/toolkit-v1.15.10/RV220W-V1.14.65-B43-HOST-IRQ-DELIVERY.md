# RV220W v1.14.65 — b43 host IRQ delivery localization

## Hardware evidence entering this release

The v1.14.64 build passed the real OpenWrt/mac80211 build and booted the BCM4322 with b43/backports-6.18.26. The retained RX-IQ/RCCAL transaction completed successfully and remained intact after the eight-second passive monitor observation. No packets reached the netdev or tcpdump.

The decisive observation is above PIO: both before and after the receive window, b43 debugfs reported `GEN_IRQ_REASON=0x00008100` with `GEN_IRQ_MASK=0x38058a64`, and `DMA0_REASON=0x00010000` with `DMA0_IRQ_MASK=0x00013c00`. Thus the generic DMA bit (`0x00008000`) and DMA0 RX_DONE (`0x00010000`) are simultaneously pending and enabled. Nevertheless the b43 claimed-IRQ counter and every downstream RX counter remain zero.

## v1.14.65 scope

This release deliberately leaves `998-b43-rv220w-platform-capabilities.patch` byte-identical to v1.14.64. The only new target-side observations are:

- the BCM4322 PCI BDF and assigned Linux IRQ;
- the corresponding `/proc/interrupts` line and summed CPU count before/after the capture;
- a read-only 12-byte sysfs PCI config-space read at `0x90–0x9b`, covering SSB PCI `IRQS`, `IRQMASK`, and `BACKPLANE_IRQS`;
- explicit pre/post copies of the existing b43 generic and DMA0 interrupt reason/mask registers.

No PCI config write, SSB register write, IRQ remap, route override, scan, association, AP, user-data TX, frame injection, automatic calibration, persistence, NVM write, or NOR write is introduced.

## Decision tree

1. If RX_DONE remains pending, the assigned host IRQ count does not increase, and b43 claims no IRQ, the fault is localized to device/SSB/PCI-to-host IRQ delivery rather than PIO. Do not alter PIO or calibration.
2. If the host IRQ count increases but b43 still claims zero interrupts, investigate Linux handler registration/claim behavior before touching hardware routing.
3. If b43 starts claiming interrupts, continue using the already-existing DMA0 -> PIO dispatch -> FRAMERDY -> DATARDY -> header -> `b43_rx()` -> mac80211 counters.

A routing mutation is intentionally deferred until this read-only provenance is captured.
