# RV220W v1.14.28 — opt-in rev4/BCM2056 RX-IQ calibration experiment

## Evidence threshold

v1.14.26 hardware evidence, corrected by the v1.14.27 parser, established the precondition for this experiment:

- N-PHY rev4 / BCM2056 radio rev3;
- b43 STARTED and forced PIO;
- both RX cores enabled and CCK+OFDM classifiers enabled;
- substantial IQ-estimator energy on both receive chains;
- RSSI calibration saved at 2412 MHz;
- rev3+ RX-IQ implementation flag zero;
- 2.4 GHz RX-IQ calibration center frequency zero;
- cached 2.4 GHz RX-IQ coefficients `(0,0,0,0)`;
- decoded monitor RX still zero.

This is the pre-declared `rx-iq-calibration-unsaved-rssi-calibrated` signature.

## Reconstruction basis

The preserved Cisco/Broadcom `wl.ko` 5.60.120.9 routine `wlc_phy_cal_rxiq_nphy` was disassembled and cross-walked against Linux b43. The RV220W rev4 path follows the older inline rev3–6 sequence and is structurally close to b43's existing rev2 RX-IQ routine rather than the later rev7+ wrapper.

The diagnostic reconstruction preserves the stock operations needed for the RV220W path:

- carrier-search hold;
- RFSEQ gain-table save/replacement/restore;
- per-core AFE/RF-control save and restoration;
- stock 2.4 GHz RF-control values;
- legacy spare-register coupling used by the shipping routine;
- four-pass `{LNA, HPF1, HPF2}` gain search;
- internal 4 kHz calibration tone with stock local amplitude `0x00b5`;
- 1024-sample IQ estimates for gain selection;
- existing b43 coefficient calculation;
- playback stop, RX reset and complete temporary-state rollback.

The normal b43 `b43_nphy_rev3_cal_rx_iq()` stub is intentionally not replaced.

### Stock helper/control-flow mapping

The rev3–6 stock path has been mapped far enough to avoid substituting unrelated rev7+ behavior:

- stock local `.text+0xf0b50` matches the gain-parameter derivation role of `b43_nphy_iq_cal_gain_params()`;
- `.text+0xf5560` matches the RF-control override operation used for field `0x400`;
- `.text+0x10d758` matches sample playback/run after the first gain pass;
- `.text+0xfa7e8` is the RX-IQ compensation calculation path and calls the stock RX-IQ coefficient/estimator helpers;
- `.text+0x11d370` belongs to the rev7+ branch and is intentionally out of scope for this rev4 device.

The stock routine initializes a first-pass flag, uses `wlc_phy_tx_tone_nphy()` while that flag is set, clears it after the pass, and uses the local sample-playback helper on later passes. The diagnostic mirrors that exact first-tone/subsequent-playback split. Stock `wlc_phy_nbits()` was also verified as bit-width of the absolute value, which supports `fls()` rather than a population count for the fourth-pass HPF adjustment.

Pre-rev7 radio addressing was checked against the stock binary as well: the stock read helper applies the legacy read bank while the write helper uses the raw caller register, matching b43's asymmetric access model. The raw `0xD6`/`0xE2` spare-register cleanup therefore follows the shipping driver's own convention.

## Two corrected b43 rev2 transcription defects

The current b43 rev2 routine is not called directly because comparison with the stock/Broadcom algorithm found two material differences:

1. Measured IQ power is indexed by gain-search pass. Current b43 writes `power[i]`, where `i` is the RX core. The reconstructed diagnostic writes `power[pass]`.
2. Fourth-pass HPF adjustment uses the bit width / magnitude scale of the selected power value. Current b43 uses `hweight32()`, a population count. The reconstructed diagnostic uses `fls()`.

The HPF calculation is performed in signed arithmetic before clamping to `[0,10]` to prevent unsigned wrap.

## Deliberate scope

The active gate accepts only:

- N-PHY revision 4;
- radio `0x2056`, revision 3;
- 2.4 GHz channel 1 / 2412 MHz;
- forced PIO;
- CA regulatory domain;
- explicit `--ack-rf` **and** `--ack-calibration`.

It uses local stock `rxcalparams=0x010100B5`. It does not initialize or mutate `nphy->rxcalparams` globally.

It does **not** save the resulting coefficients into the b43 calibration cache or IQ-cal chanspec. The new coefficients exist only in the live four RX-IQ compensation registers during a five-second receive observation.

## Runtime MAC serialization

The debugfs wrapper already serializes callbacks with `wl->mutex`, but that alone does not suspend an operating MAC. v1.14.28 therefore wraps every RF/PHY mutation window in b43's own nesting-aware MAC suspend/enable mechanism.

For both `run` and `restore`, the gate requires a verified `mac_suspended` transition from 0 to 1, confirms `B43_MACCTL_ENABLED` is clear and `B43_IRQ_MAC_SUSPENDED` is asserted, performs the RF/PHY operation, then resumes and verifies the nesting count returns to 0 and MAC enable is restored. The analyzer requires all four markers:

- `run_mac_suspend_verified=1`;
- `run_mac_resume_verified=1`;
- `restore_mac_suspend_verified=1`;
- `restore_mac_resume_verified=1`.

If any transition is not positively verified, the experiment is invalid regardless of coefficient or receive results. The five-second receive observation occurs only after the calibration mutation window has resumed the MAC.

## Sample-playback state restoration

The b43 sample-playback path saves BBMULT before a tone/run sequence. `b43_nphy_stop_playback()` restores that saved BBMULT and clears the saved-state marker. The reconstructed calibration calls `stop_playback()` around every gain pass and again during cleanup, so sample-playback amplitude state is restored through the existing b43 mechanism rather than by a new board-specific register write.

## Rollback model

Before calibration, all four live RX-IQ coefficients are saved **before the MAC is suspended or any RF/PHY state is mutated**. The calibration routine then suspends/verifies the MAC, saves and restores its temporary RFSEQ table entries, legacy radio spare registers, per-core RF-control/AFE/RFSEQ state and carrier-search nesting state, and resumes/verifies the MAC before observation. Cleanup is read-verified; RF-sequence timeout or MAC suspend/resume verification failure makes the experiment invalid.

After the receive observation, the helper unconditionally writes `restore` to the debugfs gate. Restore has its own verified MAC suspend/resume window, and the helper verifies all four live coefficients equal their saved values before the interface is removed. The EXIT/HUP/INT/TERM trap attempts restoration on interrupted runs. A write return code alone is not considered restoration success.

No SPROM, MTD, NOR, U-Boot environment or persistent WLAN configuration is modified.

## Expected interpretation

- **Decoded frames appear while reconstructed coefficients are active:** the missing rev3–6 RX-IQ calibration path becomes the leading causal blocker. The experiment still rolls the coefficients back.
- **Coefficients change but frame RX remains zero:** RX-IQ calibration is incomplete as an explanation; continue post-ADC/baseband comparison while leaving normal calibration disabled.
- **Coefficients do not change:** revisit stimulus/gain reconstruction before making causal claims.
- **Cleanup or final restore cannot be positively verified:** reboot the RAM image, do not rerun the calibration gate, and treat the capture as a safety failure.

Normal scan, association, AP operation and persistent WLAN remain unqualified.
