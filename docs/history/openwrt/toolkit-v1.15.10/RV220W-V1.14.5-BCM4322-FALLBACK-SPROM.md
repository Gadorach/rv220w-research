# RV220W v1.14.5 BCM4322 fallback-SPROM gate

## Hardware evidence

v1.14.4 proves the temporary Octeon IRQ-lifetime fix: PCI `14e4:432b` receives IRQ 110 and SSB identifies chip `0x4322`, revision `0x01`, package `0x09`. Registration then stops at `unable to fill SPROM for [0:3]` / fallback error `-22`. No kernel panic occurs.

## Interpretation

OpenWrt v25.12.5 compiles its generic SSB fallback-SPROM provider into SSB. That provider matches conventional PCI by bus and slot. Error `-EINVAL` means no registered provider matched `[0:3]`. OpenWrt also carries a dedicated `broadcom-4322-sprom` package installing `brcm/bcm4322-sprom.bin`.

## v1.14.5 discovery-only change

`wifi-discovery` uses a dedicated DTS template that adds:

```dts
bcm4322-sprom {
    compatible = "brcm,ssb-sprom";
    pci-bus = <0>;
    pci-dev = <3>;
    brcm,sprom = "brcm/bcm4322-sprom.bin";
};
```

The production DTS is unchanged. The RAM profile additionally selects `CONFIG_PACKAGE_broadcom-4322-sprom=y`.

No board-specific `brcm,sprom-fixups` are claimed. No nvmem MAC provider is attached yet because the hardware-qualified base MAC lives at NOR offset `0x6ff00` behind the legacy Octeon MTD path, not a DT-partition/nvmem provider. The OpenWrt fallback driver therefore supplies a temporary random MAC. The evidence collector still independently derives the stock-expected WLAN MAC as platform base + 4.

## RF boundary

The generic blob is an enumeration aid, not qualified RV220W RF calibration. `/etc/rv220w-wifi-sprom-policy` therefore sets `rf_qualified=0`, and `rv220w-wifi-probe passive-scan` refuses to run. Association/AP operation remains out of scope.

## Next evidence gate

A successful v1.14.5 boot should show an `ssb-sprom` provider registered for `[0:3]`, populated SSB devices, b43 core/PHY capability output, firmware selection, and a wiphy. If a raw `ssb_sprom` sysfs file appears, collect it. The following phase is to recover/compare board-specific calibration data from stock firmware or another trustworthy source and then apply the known stock MAC policy.
