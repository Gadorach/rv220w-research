# RV220W v1.15.8 — mac80211 WLAN LED trigger repair

## Hardware result that triggered this revision

The v1.15.6 production sysupgrade itself booted normally from NOR. Preserved Wi-Fi returned and the surveyed POWER, DIAG, WLAN and DMZ GPIO LEDs were present/configurable. The first v1.15.7 read-only production postcheck failed only at:

```
ERROR: WLAN LED does not expose phy0tpt trigger
```

That is narrower than a WLAN or GPIO mapping failure. The GPIO4 active-low WLAN LED exists; automatic mac80211 activity triggering is absent.

## Dependency repair

The production profile already contains b43/mac80211 and the DTS requests:

```
linux,default-trigger = "phy0tpt";
```

A DTS default-trigger string does not itself create a trigger provider. OpenWrt's mac80211 build enables `MAC80211_LEDS` only when the kernel LED-trigger core is enabled. v1.15.8 therefore selects:

```
CONFIG_PACKAGE_kmod-ledtrig-network=y
```

The network trigger module is not used as the RV220W WLAN LED policy. It is selected as a normal OpenWrt package that pulls in the LED-trigger core; mac80211 can then register `phy0tpt`, and the existing DTS can bind GPIO4 to it.

The deep persistent rootfs verifier also requires `ledtrig-network.ko`. This intentionally makes the pre-v1.15.8 production rootfs stale and unusable for v1.15.8 production preflight until rebuilt.

## Safety boundaries unchanged

- BCM4322 b43/SSB firmware and driver qualification are unchanged.
- Native DMA and PCI INT0/IRQ109 routing are unchanged.
- POWER=GPIO2, DIAG=GPIO3, WLAN=GPIO4 and DMZ=GPIO6 remain active-low.
- GPIO5 remains excluded because the U-Boot survey affected all Ethernet LED groups.
- Configuration-preserving sysupgrade, recovery backups and boot-chain/U-Boot-env protections are unchanged.
- The v1.15.7 stage2 disconnect classifier remains fail-closed.

## Qualification sequence

After upgrading the toolkit:

```
./rv220w.fish platform install
./rv220w.fish platform verify
./rv220w.fish build persistent-wifi
./rv220w.fish verify
```

The old artifact set should fail deep rootfs verification before the rebuild because `ledtrig-network.ko` is intentionally missing.

Then:

```
./rv220w.fish persistent-wifi-stage ssh-check
./rv220w.fish persistent-wifi-stage sysupgrade-preflight
./rv220w.fish persistent-wifi-stage sysupgrade-install \
    --confirm RV220W_SYSUPGRADE_PRODUCTION_V1158
```

After a normal NOR boot:

```
./rv220w.fish persistent-wifi-stage ssh-check
./rv220w.fish persistent-wifi-stage production-postcheck \
    --confirm RV220W_BOOTED_PRODUCTION_SYSUPGRADE_V1158
```

The postcheck requires `phy0tpt` to be exposed and selected as `[phy0tpt]` by the boot-time DTS default. On failure it now reports the entire WLAN trigger list and `/sys/class/leds` entries before stopping.
