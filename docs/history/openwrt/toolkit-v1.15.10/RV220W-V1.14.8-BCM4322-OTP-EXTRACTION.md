# RV220W v1.14.8 — portable SSB PCI SPROM/OTP extraction

## Purpose

v1.14.8 moves the WLAN work from generic fallback-SPROM discovery to recovery of the board data the stock Broadcom driver actually consumed. The stage remains RAM-only and radio-disabled.

The preserved Broadcom 5.60.120.9 `wl.ko` contains an OTP hardware-region SROM fallback path. See [`analysis/RV220W-STOCK-WL-OTP-PATH.md`](analysis/RV220W-STOCK-WL-OTP-PATH.md).

## Kernel diagnostic

`openwrt/wifi/993-ssb-pci-nvmem-diagnostics.patch` is staged only while building `wifi-discovery` and removed by the build cleanup trap. It augments the already-bound Linux SSB PCI driver with three read-only PCI sysfs attributes:

- `ssb_sprom_physical` — direct physical SPROM shadow using the existing SSB read primitive, separated from platform fallback data;
- `ssb_otp_info` — validated ChipCommon/IPX-OTP geometry and status metadata;
- `ssb_otp_raw` — numeric 16-bit `sromotp[]` words across the detected OTP geometry.

It does not contain an RV220W or BCM4322 device ID. It validates the fixed 16 KiB BAR0 layout and Broadcom ChipCommon core before treating BAR0+12 KiB as ChipCommon.

The first revision is intentionally read-only even relative to Broadcom's normal OTP read sequence: it does not issue the OTP `INIT` command, therefore `status_fresh=0` is reported explicitly.

## Target capture

The image installs `/usr/sbin/ssb-nvmem-capture`. `rv220w-wifi-snapshot` invokes it automatically and records paths for:

```text
*.otp-info.txt
*.otp-raw.hex
*.sprom-physical.sysfs.hex
```

No target-side conversion or fallback installation occurs.

## Host reconstruction

`analyze-ssb-nvmem.py`:

- parses the IPX geometry;
- takes the primary 220-word SROM candidate only from the geometry-defined hardware-region start;
- serializes numeric words low-byte/high-byte for Broadcom/Linux CRC validation;
- checks the stored CRC and the Broadcom full-image `0x9f` residue;
- writes a canonical 440-byte candidate for offline analysis;
- emits OpenWrt fallback firmware only if the primary geometry candidate passes both integrity checks;
- serializes that fallback as big-endian bytes per numeric word, matching OpenWrt `brcm,ssb-sprom` firmware loading;
- never inserts the RV220W MAC or other board values;
- never treats an arbitrary scan hit as an automatic candidate.

## Safety boundary

Even a CRC-valid OTP SROM is **not automatically RF-qualified**. Before firmware initialization or passive receive testing, compare the recovered board flags, PA/power tables, TSSI, antenna/chain, FEM and regulatory fields against the RV220W hardware and stock behavior. The existing stock MAC policy (`platform base + 4`) remains a separate identity decision.

Do not run `reload-dma`, `reload-pio`, `passive-scan`, association or AP operation during this gate.

## Test sequence

```fish
cd ~/src/rv220w-research/rv220w-research/promotion-toolkit
./rv220w.fish platform verify
./rv220w.fish build wifi-discovery
./rv220w.fish verify

./rv220w.fish tftp-boot \
  --profile wifi-discovery \
  --interface enp0s31f6 \
  --configure-interface

./rv220w.fish collect-wifi otp-srom-capture
```

Expected new evidence includes `ssb_otp_info`, a raw OTP-word capture, the geometry-defined SROM integrity report and—only if integrity checks pass—an offline `*.openwrt-fallback.bin` artifact. The emitted blob is evidence for the next integration stage; it is not installed or transmitted automatically.
