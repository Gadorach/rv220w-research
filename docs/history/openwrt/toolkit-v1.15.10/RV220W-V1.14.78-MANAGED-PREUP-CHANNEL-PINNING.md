# RV220W v1.14.78 — managed-vif pre-UP channel pinning

## Evidence from v1.14.77

The passive prerequisite remained qualified. The active helper established and verified a fresh retained calibration on `rvwactmon0` at 2447 MHz. After `rvwact0` was brought UP, b43 reported channel 1 even though status=2, N-PHY rev4, BCM2056r3, PIO, fault point 15, retained-state=1 and integration-complete=1 remained valid. Retuning `rvwactmon0` to 2447 MHz after that transition failed with nl80211 `-EBUSY`. The scan was therefore not started.

## v1.14.78 experiment

The managed interface is created but kept DOWN. While the calibration monitor still owns the verified channel-8 context, the helper requests `iw dev rvwact0 set freq 2447`. It then records managed/monitor/b43 channel state. Only if that pinning succeeds is `rvwact0` brought UP. The helper immediately verifies that the held monitor remains at 2447 MHz and b43 remains on channel 8, then checks the complete retained-verifier guard set and requests a fresh generation-advancing verification.

Only after all of those checks pass can the existing single wildcard cfg80211 active scan execute. Authentication, association, AP operation, arbitrary frame injection, user-data transmission, persistence, NVM writes and NOR writes remain blocked.

## Expected classifications

- `active-scan-managed-preup-channel-pinning-failed`: the managed vif cannot be pinned to the channel-8 context while DOWN.
- `active-scan-managed-up-channel-preservation-failed`: pre-UP pinning succeeded but the UP transition still moved the shared PHY away from channel 8.
- `active-scan-managed-verify-not-fresh`: channel state is correct but the kernel verifier still rejects the fresh request.
- `active-scan-no-b43-tx-status`: the scan was actually started/completed but no new b43 TX status was observed.
- `b43-channel8-active-scan-tx-rx-qualified`: TX status, channel-8 BSS RX, host IRQ activity, and post-scan unassociated state all pass.
