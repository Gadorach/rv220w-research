# RV220W v1.14.81 — normal managed-start native DMA

v1.14.80 hardware-qualified the ordinary b43/mac80211 managed lifecycle with
forced PIO: interface add/up succeeded, a normal CA 2.4-GHz cfg80211 scan
returned rc=0, b43 TX status advanced 0→11, IRQ109 advanced by 36, and two
2447-MHz `VertexHotspot` BSS entries were received while unassociated.

The v1.14.80 analyzer's only FAIL gate was automatic RX-IQ/RCCAL telemetry
0/0/0. The patched RX-IQ function logs before calling the reconstruction, and
no such log appears in the raw/serial evidence, so that startup did not reach
the rev3+ RX-IQ dispatcher; it is not evidence that the reconstructed routine
ran and failed. Normal operation nevertheless qualified strongly.

v1.14.81 is therefore a single-variable transport experiment:

- keep 993 RV220W PCI INT0/CIU36 routing byte-identical;
- keep hardware-qualified 998 b43 platform/RX-IQ reconstruction byte-identical;
- keep 999 retained-verification diagnostic ABI patch byte-identical;
- keep 9998 normal RX-IQ dispatcher repair byte-identical;
- remove only `pio=1` from the wifi-discovery b43 module options;
- retain MTD-derived MAC parameters unchanged;
- run the same normal managed interface and ordinary CA channels 1–11 scan;
- require b43 `active_transfer=dma` for DMA qualification.

Automatic RX-IQ/RCCAL invocation remains telemetry rather than a pre-scan gate.
No monitor interface, debugfs retained transaction, channel pinning, one-shot
gate, association, authentication, AP mode, arbitrary injection, NVM write,
NOR write, or persistent firmware change is part of this test.

If b43 falls back to PIO, fails interface startup, or reaches DMA but cannot
scan/TX/RX, the artifact preserves that as the DMA result without changing the
calibration lifecycle at the same time.
