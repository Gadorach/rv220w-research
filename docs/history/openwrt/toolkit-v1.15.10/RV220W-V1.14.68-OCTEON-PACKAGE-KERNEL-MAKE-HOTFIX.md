# RV220W v1.14.68 Octeon package kernel-make continuation hotfix

## Trigger

The first v1.14.67 build proved the real-tab correction worked: OpenWrt parsed `package/kernel/octeon-pci-irq-diag/Makefile` and entered `Build/Compile`. The serial fallback then emitted a kernel make command ending in a literal `\\` argument and failed with:

```text
make[4]: *** No rule to make target '\'.  Stop.
```

The C source still had not compiled.

## Correction

The package no longer relies on make/shell line continuation for the external-module invocation. It now uses exactly one recipe line:

```make
	+$(KERNEL_MAKE) $(PKG_JOBS) M="$(PKG_BUILD_DIR)" modules
```

This avoids both generator escaping and nested GNU-make/shell continuation ambiguity.

## Boundary

No diagnostic C source, b43/backports code, CIU register policy, PCI configuration, calibration logic, RF behavior, or persistent platform behavior changes in this release. The module remains read-only and the next hardware run remains the CA/channel-8 retained-calibration CIU INTx discriminator.
