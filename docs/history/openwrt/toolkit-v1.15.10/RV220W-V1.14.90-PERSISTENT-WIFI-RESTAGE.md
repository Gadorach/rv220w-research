# RV220W v1.14.90 — persistent-Wi-Fi artifact restage hotfix

## Build result

The v1.14.89 `persistent-wifi` OpenWrt build completed normally through final
checksum generation. The kernel/rootfs compile is therefore not repeated in
this release.

## v1.14.89 staging defect

`build_rv220w_persistent_images.py` used a global legacy prefix for its padded
partition images. The new candidate correctly staged its source files as
`rv220w-openwrt-rv220w-wifi-client-persistent-kernel.elf.gz` and
`...-rootfs.squashfs`, and its sysupgrade tar/report had the new namespace, but
the padded 6 MiB/25.375 MiB component wrappers were emitted under legacy
`rv220w-rj45-luci-persistent` names.

This is a host artifact-labeling bug, not a kernel/rootfs build failure.

## v1.14.90 correction

The component builder now accepts `--prefix`; the persistent-Wi-Fi build branch
passes the candidate prefix explicitly. `./rv220w.fish restage persistent-wifi`
regenerates only the padded component wrappers and manifest from the already
compiled v1.14.89 kernel/rootfs, verifies the existing sysupgrade identity,
deep-inspects the SquashFS, and quarantines legacy-named component files only
when they are byte-identical to the correctly restaged candidate.

`./rv220w.fish verify` now treats candidate source artifacts as proof that a
complete candidate artifact set must exist and fails with an explicit restage
instruction if not. It also checks the manifest `artifact_prefix` and SquashFS
contents.

The legacy `persistent-stage` command is additionally locked to the exact
legacy component/manifest basenames and manifest image identities. It cannot be
redirected to `wifi-client-persistent` artifacts with command-line path flags.

## Scope

No OpenWrt image bytes, kernel patch, DTS, package selection, radio policy, or
runtime Wi-Fi logic changes in v1.14.90. Do not rebuild unless the v1.14.89
source kernel/rootfs/sysupgrade artifacts are missing. Do not write NOR.
