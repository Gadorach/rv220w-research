# RV220W v1.14.84 managed-association supplicant launch hotfix

The v1.14.83 hardware run proved that the daemon preflight fix worked: no wireless netdev existed before the test, the managed b43 interface reached STARTED state on native DMA, IRQ109 advanced by 72 and 74 DMA RX frames were delivered without drops. Association itself never began because the OpenWrt `wpa_supplicant` build in the RAM image does not implement the `-f` logfile option. The helper invoked `wpa_supplicant -B ... -f /tmp/...`, the binary printed usage and exited, while the shell return code was misleadingly recorded as a successful start.

v1.14.84 changes only process launching. It removes `-B` and unsupported `-f`, starts foreground `wpa_supplicant` under ash backgrounding, redirects stdout/stderr to the private mode-600 `/tmp` log, records the launcher PID, and requires `kill -0` to prove that process is still alive two seconds later. Cleanup kills the PID-file process when available and otherwise falls back to the shell launcher PID. Credential handling, native DMA, kernel patches, CA regulatory scope, no-DHCP boundary, and RAM-only teardown are unchanged.
