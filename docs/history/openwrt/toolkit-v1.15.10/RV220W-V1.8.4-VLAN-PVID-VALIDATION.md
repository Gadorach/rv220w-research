# RV220W v1.8.4 VLAN/PVID validation

## Purpose

The dual-conduit image has no active OpenWrt firewall policy. Failed WAN tests stop at ARP: switch port 0 receives host traffic, but Octeon `eth1` receives no Ethernet frames. Run7 also proved that port-based VLAN membership is already symmetrical for the failed path (`port0=0x0021`, `port5=0x0021`).

Run8 ruled out the port-0 EAP BASIC/SIMPLIFIED mode as the direct cause. The remaining simple discrepancy is 802.1Q classification state:

- external WAN port 0 default VID: 0;
- CPU port 5 default VID: 1;
- proven CPU port 8 default VID: 0.

v1.8.4 reads the actual VLAN-table entries for VID 0 and VID 1, then permits reversible RAM-only tests which alter only those two VLAN entries and the port-0/5 default VLAN tags.

## Safety boundaries

The `b53-vlan` helper:

- requires the live topology to report `wan@eth1` before any write;
- requires an internal `RAM_ONLY_CONFIRM` token supplied by the host wrapper;
- writes only default VLAN-tag registers for ports 0 and 5, plus generic B53 VLAN-table entries 0 and 1;
- saves original port-0, port-5, port-8, VLAN-0 and VLAN-1 values under `/tmp` before its first write;
- verifies state through immediate readback;
- restores the pseudo-PHY selector registers on exit;
- does not change PVLAN masks, EAP state, PHY state, RGMII timing, DSA affinity, bridge membership, firewall configuration, MIB controls or flash.

A reboot discards all live switch changes. `restore` is still required before ending the controlled sequence so the captured final state is explicit.

## Commands

The running v1.8.0 image lacks this helper, so use `--force-upload`.

### 1. Read the untouched failed state

```fish
./rv220w.fish b53-vlan show --force-upload
./rv220w.fish collect-conduit run9-eth1-vlan-original --force-upload
```

Record these fields:

```text
before_pvid0_vid
before_pvid5_vid
before_pvid8_vid
before_vlan0_members
before_vlan0_untag
before_vlan1_members
before_vlan1_untag
```

### 2. Test only the suspected stale CPU-port PVID

```fish
./rv220w.fish b53-vlan set-p5-pvid0 --force-upload
sudo ip neigh flush dev enp0s31f6
ping -I enp0s31f6 -c 10 192.168.241.2
ping -I enp0s31f6 -M do -s 1472 -c 10 192.168.241.2
./rv220w.fish collect-conduit run9-eth1-p5-pvid0 --force-upload
```

This changes only port 5's VID field from 1 to 0. No VLAN-table entry is changed.

### 3. If step 2 fails, establish an explicit VLAN-0 WAN domain

```fish
./rv220w.fish b53-vlan set-domain-vlan0 --force-upload
sudo ip neigh flush dev enp0s31f6
ping -I enp0s31f6 -c 10 192.168.241.2
ping -I enp0s31f6 -M do -s 1472 -c 10 192.168.241.2
./rv220w.fish collect-conduit run9-eth1-domain-vlan0 --force-upload
```

The helper preserves unrelated VLAN-0 members, adds ports 0 and 5, makes port 0 untagged, keeps CPU port 5 tagged, and sets both default VIDs to 0.

### 4. Restore before the VLAN-1 experiment

```fish
./rv220w.fish b53-vlan restore --force-upload
./rv220w.fish b53-vlan show --force-upload
```

### 5. Reproduce the vendor-style VLAN-1 WAN domain

```fish
./rv220w.fish b53-vlan set-domain-vlan1 --force-upload
sudo ip neigh flush dev enp0s31f6
ping -I enp0s31f6 -c 10 192.168.241.2
ping -I enp0s31f6 -M do -s 1472 -c 10 192.168.241.2
./rv220w.fish collect-conduit run9-eth1-domain-vlan1 --force-upload
```

The helper preserves unrelated VLAN-1 members, adds ports 0 and 5, makes port 0 untagged, keeps CPU port 5 tagged, and sets both default VIDs to 1.

### 6. Final restore

```fish
./rv220w.fish b53-vlan restore --force-upload
./rv220w.fish b53-vlan show --force-upload
./rv220w.fish collect-conduit run9-eth1-restored --force-upload
```

## Interpretation

| Result | Meaning |
|---|---|
| Step 2 works | Port 5 retained a stale PVID; permanent fix is CPU-port default-VLAN initialization |
| Step 2 fails, step 3 works | VLAN 0 table omitted or tagged port 5 incorrectly |
| Only step 5 works | RV220W requires the vendor-style VID 1 CPU/WAN domain |
| All fail | Ordinary 802.1Q/PVID state is ruled out; investigate CPU-port-5 IMP ingress classification or Octeon receive handling |

The test is about Ethernet delivery to `eth1`, not WAN firewall policy. ARP must succeed before ICMP filtering can matter.


## Hardware result

Run9 completed the full sequence and proved ordinary VLAN classification was
causal:

| State | Port 0 PVID | Port 5 PVID | VID 0 members | VID 1 members | Result |
|---|---:|---:|---|---|---|
| Original | 0 | 1 | `{0,1,2,3,4,8}` | `{}` | failed |
| Port-5 PVID only | 0 | 0 | `{0,1,2,3,4,8}` | `{}` | failed |
| Explicit VID 0 | 0 | 0 | `{0,1,2,3,4,5,8}` | `{}` | passed |
| Explicit VID 1 | 1 | 1 | `{0,1,2,3,4,8}` | `{0,5}` | passed |
| Restored | 0 | 1 | `{0,1,2,3,4,8}` | `{}` | failed again |

Both working domains passed ordinary ICMP and a 1472-byte payload. The absolute
VID was not important; matching PVID classification and actual CPU-port
membership were. Port 5's PVID alone was insufficient because port 5 remained
outside the selected VLAN-table entry.

The production correction is kernel patch
`998-b53-enable-dt-cpu-ports.patch`. It adds firmware-described DSA CPU ports to
B53's enabled-port mask before generic default-PVID/VLAN setup. This lets the
existing driver initialize secondary CPU conduits without hard-coding an
RV220W WAN VID. See `RV220W-RUN9-VLAN-PVID-PROOF.md`.
