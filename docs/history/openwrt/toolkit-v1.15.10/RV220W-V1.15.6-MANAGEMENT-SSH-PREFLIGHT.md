# RV220W v1.15.6 — installed-router SSH target / sysupgrade preflight

v1.15.5 global verification passed the production artifact set. The first production `sysupgrade-preflight` then failed before any target backup or write because the toolkit attempted SSH at `192.168.240.2`, inherited from the TFTP direct-link variable, and the workstation had no reachable SSH path to that address.

This is not a firmware/image failure. v1.15.6 is no-build/no-flash and separates installed-router management from TFTP addressing.

## Management target

The toolkit now defines:

```fish
set -gx RV220W_PERSISTENT_SSH_HOST root@192.168.240.2
```

in `config/toolkit.env.fish.example`. A user may override it in `config/toolkit.env.fish`, or per command:

```fish
./rv220w.fish persistent-wifi-stage ssh-check --host root@<current-LAN-IP>
```

`RV220W_TFTP_DEVICE_IP` remains dedicated to TFTP/direct-link workflows.

## Identity/reachability gate

`ssh-check` is read-only. It requires the remote system to identify as Cisco RV220W / `cisco,rv220w` and reports the configured LAN address. Production sysupgrade preflight runs this gate before creating a recovery directory or streaming an MTD partition.

If SSH is unreachable, the action fails before target backup/write activity and advises either an explicit `--host` or a direct-link route to `192.168.240.0/24`.

## Next hardware run

First establish a management path. For the original direct-link LAN arrangement, connect the workstation to an RV220W LAN port and ensure the workstation has an address/route on `192.168.240.0/24`. Then:

```fish
./rv220w.fish persistent-wifi-stage ssh-check
./rv220w.fish persistent-wifi-stage sysupgrade-preflight
```

If the router's current LAN management address differs, use `--host root@<LAN-IP>` on both commands or set `RV220W_PERSISTENT_SSH_HOST` persistently.
