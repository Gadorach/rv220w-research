# RV220W v1.15.9 — v1.14.91 synthetic-rootfs regression hotfix

The v1.15.8 updater correctly advanced the production rootfs verifier to require `ledtrig-network.ko`, but the historical `test_v11491_unprivileged_persistent_wifi_verify.py` fixture still enumerated the pre-v1.15.8 synthetic rootfs contents. The updater therefore stopped with `missing required rootfs entry: ledtrig-network.ko` before reaching the v1.15.8 build instructions.

v1.15.9 changes no OpenWrt source, configuration, kernel, rootfs, sysupgrade payload, b43 patch, DTS, NOR layout, or V1158 image token. It updates only the synthetic fixture so it continues testing the original v1.14.91 invariant—`unsquashfs -lc` plus narrowly scoped `-cat`, with no extraction—against the current production-rootfs content policy. A dedicated v1.15.9 regression runs the historical fixture end-to-end.

The v1.15.8 image requirement remains unchanged: if the LED-trigger-enabled persistent-WiFi image has not yet been built, build it once after installing v1.15.9, then use the existing `RV220W_SYSUPGRADE_PRODUCTION_V1158` / `RV220W_BOOTED_PRODUCTION_SYSUPGRADE_V1158` qualification path.

Two additional pre-existing standalone historical tests were also made series-agnostic: v1.14.32 no longer rejects toolkit versions after the 1.14 series, and v1.14.63 no longer hashes an intentionally evolving host artifact-builder script. Their historical patch/platform invariants remain intact.
