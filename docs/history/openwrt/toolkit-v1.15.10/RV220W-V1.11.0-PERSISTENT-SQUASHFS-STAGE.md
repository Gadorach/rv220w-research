# RV220W v1.11.0 persistent SquashFS stage

## Scope

v1.11.0 adds the first non-initramfs, persistent OpenWrt promotion path. It is
not yet a hardware-validated release and does not yet enable normal `sysupgrade`.
The purpose of this stage is to prove:

1. a non-initramfs MIPS64 ELF can boot through vendor `bootoctlinux`;
2. the kernel mounts the 16 MiB NOR `rootfs` partition as SquashFS;
3. OpenWrt initializes and mounts the reclaimed 8.375 MiB `rootfs_data` as
   JFFS2 overlay;
4. settings and installed packages survive reboot.

## New build profiles

```fish
./rv220w.fish build persistent
./rv220w.fish build persistent-writer
```

`persistent` produces:

```text
rv220w-openwrt-rv220w-rj45-luci-persistent-kernel.elf
rv220w-openwrt-rv220w-rj45-luci-persistent-rootfs.squashfs
rv220w-openwrt-rv220w-rj45-luci-persistent-kernel.part.bin
rv220w-openwrt-rv220w-rj45-luci-persistent-rootfs.part.bin
rv220w-openwrt-rv220w-rj45-luci-persistent-images.json
```

The `.part.bin` files are exact partition sizes and are padded with `0xff`.
The manifest records source sizes and hashes, partition hashes, flash offsets,
the erased-overlay hash and the fixed-size gzip U-Boot copy/decompression plan.

`persistent-writer` produces a RAM-only maintenance image. Only these MTD
partitions are writable in that profile:

```text
openwrt-kernel
rootfs
rootfs_data
```

`boot-chain`, `stock-data` and `uboot-env` remain read-only.

## Important transition property

The currently flashed LuCI payload is a single initramfs ELF extending from the
kernel partition into the old rootfs region. Writing the new `rootfs` component
therefore invalidates that existing NOR initramfs payload. This is expected.

Do not begin the write unless all of these are ready:

- TFTP RAM boot remains proven;
- the new persistent writer is already running in RAM;
- the legacy 22 MiB slot backup is retained;
- the new writer has completed a component backup;
- physical recovery-button download mode remains available;
- the combined boot-chain patches remain installed.

## First hardware sequence

Build both profiles:

```fish
./rv220w.fish platform install
./rv220w.fish build persistent
./rv220w.fish build persistent-writer
./rv220w.fish verify
```

RAM-boot the new writer:

```fish
./rv220w.fish tftp-boot \
    --profile persistent-writer \
    --interface enp0s31f6 \
    --configure-interface
```

Set a temporary root password from UART, then inspect and back up:

```fish
./rv220w.fish persistent-stage status
./rv220w.fish persistent-stage backup
```

Write only the SquashFS component:

```fish
./rv220w.fish persistent-stage write-rootfs \
    --confirm RV220W_WRITE_PERSISTENT_ROOTFS
```

Erase the new overlay partition:

```fish
./rv220w.fish persistent-stage erase-overlay \
    --confirm RV220W_ERASE_PERSISTENT_OVERLAY
```

Reboot to U-Boot and TFTP-boot the non-initramfs kernel:

```fish
./rv220w.fish tftp-boot \
    --profile persistent \
    --interface enp0s31f6 \
    --configure-interface
```

Do not write the kernel partition until that TFTP kernel mounts the NOR rootfs
and overlay correctly.

## Runtime validation

Collect:

```sh
cat /proc/cmdline
cat /proc/mtd
mount
cat /proc/mounts
block info
ubus call system board
logread | grep -Ei 'squashfs|jffs2|overlay|mount_root|rootfs_data'
df -h / /rom /overlay
```

Expected structure:

```text
/rom      read-only SquashFS from rootfs
/overlay  writable JFFS2 from rootfs_data
/         overlayfs
```

Persistence test:

```sh
uci set system.@system[0].hostname='rv220w-persistent-test'
uci commit system
printf 'persistent-test\n' >/etc/rv220w-persistence-marker
apk add <small-test-package>
sync
reboot
```

After reboot, verify the hostname, marker and package remain.

## Final kernel installation

After the TFTP persistent-kernel test passes, RAM-boot the persistent writer
again and write the kernel:

```fish
./rv220w.fish persistent-stage write-kernel \
    --confirm RV220W_WRITE_PERSISTENT_KERNEL
```

Generate the exact U-Boot plan:

```fish
./rv220w.fish persistent-stage boot-plan
```

Use the manifest-generated fixed 6 MiB copy, `gunzip` destination, and `bootoctlinux` address. First validate the padded gzip path in RAM; do not reuse the old initramfs command.

## Recovery

The writer can restore any component backup:

```fish
./rv220w.fish persistent-stage restore \
    --partition rootfs \
    --image /path/to/rootfs.bin \
    --confirm RV220W_RESTORE_PERSISTENT_PARTITION
```

To restore the old monolithic initramfs slot, RAM-boot the legacy `nor-writer`
and use `nor-stage restore` with the saved 22 MiB backup.

## Next gate

Only after this stage passes should the platform add target-specific
`platform_check_image`, `platform_do_upgrade`, configuration retention and a
component-based sysupgrade archive.
