# RV220W v1.14.93 — first persistent-WiFi rootfs/TFTP-kernel boot gate

## Qualified prerequisite

v1.14.92 `verify` reaches zero failures for the previously compiled `rv220w-wifi-client-persistent` candidate. Its rootfs is deeply inspected, its component manifest and sysupgrade metadata are valid, and the v1.14.89 namespace collision is quarantined. No OpenWrt rebuild is needed for v1.14.93.

## Why rootfs first

The first hardware promotion deliberately writes only the 25.375 MiB `rootfs` partition. The 6 MiB kernel partition remains on the previously installed firmware. The new non-initramfs candidate kernel is instead TFTP-loaded into RAM. This proves the persistent candidate rootfs, automatic JFFS2 overlay and candidate kernel together before committing the candidate kernel to NOR.

The write resets the current rootfs/JFFS2 contents to the candidate's clean first-boot state. v1.14.93 therefore creates fresh complete backups of both writable persistent partitions before writing. Those backups are the rollback source; this first qualification does not merge the previous overlay into the candidate.

## Writer sequence

RAM-boot the existing `persistent-writer` image, keep UART and TFTP recovery available, and set a temporary root password if required. Then run:

```fish
./rv220w.fish persistent-wifi-stage status
./rv220w.fish persistent-wifi-stage write-rootfs \
    --confirm RV220W_WRITE_WIFI_CANDIDATE_ROOTFS_V11493
```

The host revalidates the candidate manifest/rootfs/sysupgrade, requires the dedicated writer profile, creates complete backups of `openwrt-kernel` and `rootfs`, streams only the candidate rootfs wrapper, and requires complete NOR read-back SHA equality. The remote writer still protects `boot-chain` and `uboot-env`. No candidate kernel-write action exists.

Do not power-cycle into the unqualified mixed NOR state intentionally. Return to U-Boot and TFTP-load the candidate kernel.

## First candidate boot

```fish
./rv220w.fish tftp-boot \
    --profile persistent-wifi \
    --interface enp0s31f6 \
    --configure-interface
```

The host checks the raw ELF against the candidate manifest's decompressed-kernel SHA and size before TFTP. The kernel remains in RAM and mounts the newly written NOR rootfs.

After OpenWrt reaches SSH:

```fish
./rv220w.fish persistent-wifi-stage boot-check
```

The check is read-only and requires:

- build profile `wifi-client-persistent`, `writes=none`;
- exact physical boot-chain/kernel/rootfs/U-Boot-env geometry and one derived `rootfs_data`;
- `/rom` SquashFS, `/overlay` JFFS2, `/` overlay;
- NOR SquashFS prefix exactly matching the qualified candidate source SHA;
- b43 + ssb loaded, b43 `pio=0`, BCM4322 probe and MTD-derived MAC markers;
- BCM4322 PCI IRQ 109;
- at least one `wifi-device`, every radio `disabled=1`, zero `wifi-iface`;
- no running wpa_supplicant or hostapd.

## Stop conditions

Do not write the candidate kernel if any backup, local artifact check, transfer SHA, NOR readback, TFTP kernel identity, SquashFS/JFFS2 mount, rootfs prefix, PCI IRQ, b43 identity or default-radio guard check fails. Keep the RAM writer/TFTP recovery path available.

If the candidate rootfs must be rolled back, RAM-boot `persistent-writer` again and use the existing `persistent-stage restore --partition rootfs --image <backup>/rootfs.bin --confirm RV220W_RESTORE_PERSISTENT_PARTITION`.
