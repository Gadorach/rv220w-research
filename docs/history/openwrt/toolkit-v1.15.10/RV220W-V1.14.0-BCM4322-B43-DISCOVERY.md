# RV220W v1.14.0 BCM4322/b43 discovery profile

## Purpose

This stage adds the first RAM-only wireless image while preserving the fully
hardware-qualified five-RJ45 and LuCI baseline.  The removable Broadcom
BCM4322 (`14e4:432b`) is probed through Linux SSB and `b43` using the stable
5.100.138 firmware selected by OpenWrt.

## Safety policy

- TFTP/initramfs only; reboot returns to the installed persistent image.
- No flash-writing helper is added or invoked.
- All generated `wifi-device` sections are forced to `disabled=1`.
- No `wpad`, hostapd or wpa_supplicant package is included.
- The automatic collector never scans, associates or starts an AP.
- SPROM access is read-only and a binary copy is written only to `/tmp`.

## Build and boot

```fish
./rv220w.fish platform verify
./rv220w.fish build wifi-discovery
./rv220w.fish verify

./rv220w.fish tftp-boot \
    --profile wifi-discovery \
    --interface enp0s31f6 \
    --configure-interface
```

Expected artifact:

```text
~/src/rv220w-openwrt/artifacts/rv220w-openwrt-rv220w-wifi-discovery-initramfs.elf
```

## First evidence capture

Do not run `wifi up` or `iw ... scan` before the baseline is collected.

```fish
./rv220w.fish collect-wifi initial-b43-probe
```

The collector stores the text report under `logs/wifi/` and separately copies
and hashes a readable `ssb_sprom` sysfs image when available.

## Gate interpretation

1. `14e4:432b` absent from PCI sysfs: investigate Mini PCI power/reset or host
   enumeration before touching b43.
2. PCI present but no SSB devices: investigate SSB attach/endian/PCI bridge
   behavior.
3. SSB present but firmware load fails: inspect the requested b43 filename and
   included `/lib/firmware/b43` inventory.
4. Firmware loads but no `phy`: inspect PHY/radio revision, SPROM and DMA errors;
   retry with the compiled PIO fallback only after the baseline report.
5. `phy0` appears: preserve and decode SPROM before any scan or RF test.
